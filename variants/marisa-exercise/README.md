## 原作速率与流畅度修正

`menu.cs` 设置普通目标帧率 60，`yu_base.cs` 在 Update 驱动动作计数。左右体操在计数超过 8、17、26、35、44、53、62 后换姿态，超过 70 复位：按默认 60 帧推算循环为 71/60 秒。上下体操超过 156 后复位，对应 157/60 秒。这是从代码推算的正常帧率节奏，未声称实机逐帧录制；原作低帧率／慢动作模式另有影响。

保留左右 15°／30°目标，在中间角度使用连续三次插值，避免每个关键姿态都减速到零；只有左右极限自然换向。上下插值抵达原作阶段，回落前提前平滑过渡。左右动画现在保持伸高循环，普通伸缩由另一套体操控制。

预览按完整真实时间差推进，不再把每帧耗时截短到 0.05 秒。缓存轨道、每骨骼组合一次矩阵，替代逐顶点反复解算父级。优化与原算法的几何及法线误差低于 0.00000001。当前机器的性能与计时测量见 `pose-performance.json`、`browser-performance.json`；不是所有设备的帧率保证。

GIF 使用 20 毫秒帧间隔（50 帧/秒），周期因 GIF 时间粒度近似为 1.18／2.62 秒；为匹配动画导出的百分之一秒精度，交互与模型周期统一为 1.18／2.62 秒，与代码推算相差不到 0.004 秒。

Blockbench 对照在导出的关键帧时刻采样，四套动画各 41 个姿态；其编辑器插值器会将距离关键帧不足 1/1200 秒的时刻吸附到该帧，连续预览仍使用真实时间线性求值。
