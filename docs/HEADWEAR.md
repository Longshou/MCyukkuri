# 头饰第二生命与制裁（世界观包 6、包 7 的“无头饰误认”）

依据：komicolle「饅饅來大講堂」No.11518829（头饰随身体成长并能自我修复；饅会用舔把碎掉的头饰聚在一起保存等待修补；失去头饰会被社会性抹杀，本人也承受极大压力；不能慢慢来的会被“制裁”，能否慢慢来取决于有无头饰、是否完整）、回帖“头饰以自我感觉为养分成长”，No.11518847（没有头饰就认不出是同类）。裁决见 C7、C11。**用户修正（2026-10-18 晚）优先**：认不认得出由智力决定，不看徽章（原 Q3“金章观察者例外”已删除）；失饰者被认不出它的油库里鄙视、厌恶，这是根因；制裁是欺负，不是杀；亲属不豁免。具体数值都是项目设计。

代码：`headwear/Headwear.java`（状态、成长、损坏、修复、碎片收集目标）、`headwear/Recognition.java`（唯一的识别判定）、`headwear/Contempt.java`（对失饰者的鄙视、回避与“怪物”恐惧）、`headwear/Sanction.java`（制裁＝欺负的执行目标与族规接口）、`item/AccessoryShardItem.java`、`client/HatDamageMask.java`、`client/HatDamageFaces.java`。状态只存在主人身上，物品和帽船只带主人令牌，所以损坏与尺寸在被摘走、被偷、当船时都保持不变。

## 状态

| 状态 | 含义 | 对 `unease` 的持续压力（每分钟） |
| --- | --- | --- |
| `worn` | 戴着；损坏 0 完好、1 轻损（毛边缺口）、2 撕裂（缺一大块） | 0／0.5／1（`accessory_torn`） |
| `off` | 头饰离开头顶；实际托管与被摘走、被偷另行区分 | 3（`no_accessory`，有效托管为 0） |
| `shattered` | 碎了，碎片散落还没收齐 | 4（`accessory_shattered`） |
| `reassembling` | 碎片已收齐，放在头上慢慢长合（仍不算完整，同族仍认不出） | 1.5（`accessory_mending`） |
| `lost` | 烧掉、碎片被毁或三天没找到任何碎片 | 5（`accessory_gone`） |

压力由 `MindLife.sample` 读取 `Headwear.uneasePerMinute()`；碎裂瞬间另加 12（烧毁 20），并沿用 `lost_accessory` 事件（+15、台词“帽子不见了”）。

### 暂放、帽船托管与真正失去

主动放帽接生、放船和落水时用自己的帽子自救，都登记同一主人、同一头饰令牌和实体帽子的托管关系。托管期间不触发失帽事件、无帽持续不安或无帽垂头待机。帽船卸载只表示当前位置未知，不算丢失；旧档若保存了对应帽船 ID，在加载到实物前保留待核实托管。没有帽船记录的旧失帽不会被推断为托管。

主人没有乘坐时，玩家可站在干岸上空手蹲下右击帽船。只有全部乘员都有安全落点、没有进行中的登船预约时才回收：乘员先安全上岸，粮食在岸边落下，玩家获得一顶带原主人与令牌的帽子。主人加载时立即承受失帽反应；未加载时保存通知，等主人加载再处理。归还同一顶帽子恢复佩戴和既有归还反应。

已加载、没有乘员的漂浮帽子距主人超过 96 格并连续维持 1200 tick，也会结束托管并触发失帽。失去状态不会被旧帽船 ID 或附近扫描自动撤销；真正重新上到那顶帽船或取回原帽才恢复。区块未加载会中止漂远计时。帽船累计承受 6 点火焰伤害，或翻覆进水 600 tick 后实际下沉、整个船体顶部在水下连续 200 tick，分别按烧毁、沉没处理【项目设计】：原令牌失效，剩余库存散落，帽主收到一次真正失帽通知。主人未加载时保存通知，加载后结算；及时扶正会停止进水并恢复浮力；普通翻覆瞬间和卸载不触发此规则。

## 损坏、修复、碎裂

- 来源（`Headwear.struck`，在 `YukkuriEntity.hurt` 中调用）：打到头顶 70%、捕食种咬 45%、其他 ≥3 的打击 15% 损坏 1 级（≥5 为 2 级）；火每次 35% 损坏 1 级，烧到第 3 级直接烧没（无碎片）；爆炸 2–3 级；落石压 2 级；制裁时被咬每口 1/3。
- 自我修复：戴着时按心情累积，安心（`unease<35`）每 tick +2，不安 +1，甜化或非油症时停止。轻损 6000、撕裂 12000（安心约 2.5 分钟／5 分钟一级）。橙汁不能修头饰（C4）。
- 碎裂：超过撕裂即碎成 2–3 块 `accessory_shard`，带主人与碎片令牌，地上可存在 3 天。主人会走过去舔起来（`shard_seek`／`shard_lick`）；玩家也可以捡走，对主人右键交还（凑齐时增加对玩家的信任）。碎片被火、岩浆等毁掉，或三天没有进展，头饰就算永久失去。
- 拼回：碎片凑齐后放在头上，以“拼回”外观显示，安心时每 tick +2、其余（非油症除外）+1，到 12000 长合，恢复为撕裂级头饰，再按上面的修复速度变好，并触发 `returned_accessory`（-20 不安）。

## 随身体成长

`Headwear.fit` 记录头饰自身的大小。戴着且主人不甜化时，头饰会长到和身体一致（安心时约 50 秒从 0.6 长回 1.0）；摘下、当船、甜化或非油症时不长。所以被摘走很久后还回来的头饰、长期不安的个体，头上的饰物看起来偏小（最小 0.6 倍，以饰物底部为中心缩放）。头饰不会大于身体。

## 识别：头饰、智力与水生例外（`headwear/Recognition`）

所有“认不认得出”都走 `Recognition.recognizes(observer, target)`：目标戴着头饰，或坐在自己仍能保护乘员的帽船里，就认得出；目标在已加载、主人和令牌均吻合的自有实体帽子 8 格内，也算有头饰，包括陆地接生帽。未知位置的托管只影响主人自己的失帽反应，不给远处观察者提供识别依据。其余无饰目标可由水生观察者认出，其他观察者要求**智力** ≥190。`YukkuriLife.canRecognize`、`Headwear.isUnrecognizedHatless/fairGame/remainsRecognized`、聚落冷落、族规目击、亲子喂食、求偶、问候、舔舔疗伤、护卫、同类相食的判定都调用它。**亲属不豁免**：认不出就当陌生的失饰者对待，不喂、不护、同样鄙视。回窝同睡、惊吓传播、河岸相遇里的“亲属”同样要先认得出；同类相食只看 `fairGame` 且不吃“怪物”（重伤失饰者），不再排除亲属与同群。

智力 ＝ 认知能力（`cognition/Cognition`：先天＋习得）＋ 2 × 训练知力（`pet.Ability.WITS`，0–100，徽章考试的“知力”；野生为 0）。阈值与权重是项目设计，分布沿用现有生成规则：

| 群体 | 现有分布 | 能认出失饰者的比例（抽样估算） |
| --- | --- | --- |
| 野生（自然生成；聚落生成的成员 2026-10-18 起同样抽取） | 先天 50–200 均匀，知力 0 | 先天 ≥190：11/151 ≈ 7%（少见的高知力野生油） |
| 野生所生幼体 | 父母先天均值 ±20 | 两只普通野生所生约 2%；聪明父母的孩子多数能（可遗传） |
| 妖梦（先天 ×0.6，30–120） | 知力 0 | 单靠先天不可能，要训练知力 |
| 店内初始铜章 | 先天 100，知力 30–40 | 0%（100 + 2×35 = 170） |
| 店内初始银章／金章 | 先天 100，知力 60–70／83–93 | 100% |
| 店育幼体（馅统 55–85，四科约 32–64） | 先天父母均值 ±20 | 发银章者约 94%；发铜章者约 60%（多是知力已近银章线、只差规矩或学力的） |
| 玩家训练的宠物 | 先天随来源 | 知力课把知力练到 45 左右（先天 100 时）就能认出 |

所以“通常银章、金章能认出，普通野生认不出，少数高知力野生也能”，但徽章本身不参与判定：过期、作废或摘章都不影响，知力高的铜章或无章个体一样能认出。

状态键 `cognition.intellect`（读）、`cognition.sees_hatless`（读，是否能认出失饰者）、`cognition.innate`（读写，测试门）。

## 失饰的社会后果：鄙视是根因（`headwear/Contempt`）

- 每只油库里约每 3 秒看一眼 6 格内、有视线的失饰个体；认不出就**鄙视**：对它的好感 −3（只靠鄙视最多降到 −40）、生气脸并说 `hatless_scorn`（“连饰物都没有、没法慢慢来的家伙，去那边吧！”），能走动时走开回避；被鄙视者不安 +0.5、含泪，三次里约一次说 `settlement_hurt`（只说台词，不再叠加该事件自带的 +8）。同一观察者对同一目标的被动观察与社交问候共用冷却：普通鄙视 400–599 tick，怪物反应 600–799 tick；冷却只保留当前遭遇，不写存档。
- 凶悍成体（攻击性 ≥55，或自私 ≥65 且自制 <65）在好感 ≤−15 时、或每次 1/4 机会，改为发起**制裁**（理由 `hatless`，见下）。好感持续下降也会让普通的欺负回合（`GroupInteractionGoal`，好感 ≤−20）找上它。
- 问候走到跟前才发现没有头饰，同样按鄙视处理（`YukkuriSocial`）。
- **怪物（当前实现，待按新裁定修改）**：失饰活体只要濒死、存在任一深伤、霉斑中期以上或生命 ≤35%，就会在认不出它的个体眼里成为怪物：观察者不安 +6、惊恐脸并说 `hatless_monster`（“是怪物哦哦哦！”）；凶悍成体围上来驱赶（制裁理由 `monster`，最多 3 只），其余的逃开（`frightenFrom`）。被当怪物者不安 +2、哭。这里**不吃**它。

2026-10-20 反馈：怪物应对应失饰且伤口多、外观残破，当前条件尚未满足；普通失饰的嫌弃与怪物恐惧要分开。低智力亲油未嫌弃失饰子油也已复测失败，不能因存在通用识别／鄙视接口就算完成。两项分别归[待办](TODO.md)陆 20、11。

- 亲友只保护认得出的受害者（`GroupInteractionGoal.witnessedAttack`）；认得出它的高智力个体不鄙视、不参与制裁，仍会护它。
- 聚落内：原有的冷落 → 驱逐／嗯嗯奴隶链不变（`SettlementSociety`，仍要求观察者认不出它）。
- 判定接口：`Recognition.unrecognizedHatless(observer, target)`（＝`Headwear.isUnrecognizedHatless`）；`Recognition.fairGame`（＝`Headwear.fairGame`：同上且目标是自由个体、不是捕食种，宠物和有主个体不被欺负、驱赶或捕食，C11）；`Recognition.grotesque(target)`、`Recognition.seenAsMonster(observer, target)`；`Recognition.remainsRecognized(observer, remains)`。

## 制裁＝欺负，不是杀（`headwear/Sanction`）

- 理由：`hatless`（鄙视引发）、`monster`（怪物驱赶）、`non_yukkuri`（同聚落或无聚落的非油症狂乱个体，执行者自己每 10–15 秒扫描一次，1/3）、族规判定（偷公粮、杀同族、同类相食、违抗、被逐者回来、失饰入侵者，经 `settlement/Sanction.punish` 转交）。
- 执行者：自由成体、生命 ≥60%、非捕食种／家油、凶悍。`hatless`／`monster` 只由**认不出它的**个体执行（认不出的亲属一样参与），认得出它的不参与；族规案件只由同一聚落的正式成员执行，认得它的近亲（父母、子女、伴侣）不参与。每案最多 3 只。
- 过程：走到 3 格内宣告（生气，`hatless_scorn`／`hatless_monster`／`settlement_drive`；目标哭，不安 +4），接触后每 30 tick 一次欺负动作，最多 5 次：有吃的或宝物先**抢**（嘴里的食物被抢去吃，吃不下就打掉；否则抢一件宝物），否则在血量允许时**咬**（1.5 尝试伤害、小撕裂伤），之后**推**（击退）。实际扣血和伤口都走普通受击事务；受害者没有实际损失时不记为成功。多人共用同一案的一次咬伤记录，不会每人再补一口，也不产生吞咽收益。第 5 次**赶走**（`settlement_drive`，目标惊逃，不安 +3）。
- 不以致死为目标：咬后仍须高于 50% 血量才允许咬。目标生命已 ≤50%、虚弱、濒死或中枢受损时立即停止，不再持续追推；目标若因原有伤势死亡，仍记录为欺凌期间死亡。
- 一案结束后，同一目标 6000 tick（5 分钟）内不再因 `hatless`／`monster`／`non_yukkuri` 被制裁；族规判定不受此限。目标逃出 24 格、执行者受伤 <30% 或惊慌、或 2400 tick 后放弃。
- 族规接口：`Sanction.request(target, reason, accuser)`；`Sanction.judged(target)` 读当前案件。宠物、有主、家油和捕食种不会被制裁。配置 `life.sanction`（默认开）。

## 美术

制作源 `art/props/hat-damage/recipe.json`，导出 `scripts/export_hat_damage.py` → `yukkuri_presentation/hat_damage.json`、`yukkuri_props/accessory_shard.json`、`textures/props/accessory_shard.png`、`models/item/accessory_shard.json`；预览 `art/props/hat-damage/preview.py`（输出 `.local/previews/hat-damage/`）。

损坏保留完整头饰轮廓：前/后/上/下四个方向的盒面切成正方形像素格，只去掉少量格子；左右侧面的薄面完整保留，因此没有三角形锯齿或细长毛刺。轻损 5 处、撕裂 8 处，位置不对称、大小混合；帽顶只留 1–2 格（轻损）/ 2–3 格（撕裂）的小缺口。每个方孔内衬从局部布料颜色计算：绿色用浅绿、红色用亮红、黑色用浅灰紫、淡粉用暗粉，孔边缘用同色系深色。白边、蕾丝、扇贝边与金月仍然保留；拼回不挖洞，只沿两道窄缝加深。

碎片三块完全同款：共用一个破布模型，按 `SourceModel` 的主色族着色（`recipe.json` 的 `shard.tints`），不再按 `Piece` 做不同外观；不同头饰颜色不同，视觉上不通用。物品归属、堆叠与收集逻辑仍按现有 `AccessoryShardItem`/`Headwear`，本次未改逻辑。被摘下的饰物物品按 `HatDamage` 显示同样的方形损坏。帽船船体仍显示完好（未改水生代码）。
