# 玩法日志

状态：**已接入待试玩**。开发约束见 [AGENTS.md 的日志留痕](../AGENTS.md#日志留痕)；运行包、日志位置与按时间查找方法见[开发指南](DEVELOPMENT.md)。日志用于还原实际发生的事件，不代替用户在试玩场的确认。

## 后续功能的规则

- 新增或修改玩法时，一并留下关键事件：明确的玩家操作，行为链开始、重要阶段、完成和中断，实际伤病、亲缘、归属及物资变化。发生过的尝试被拒绝，要记录已有判定中的原因或阻塞条件。
- 在拥有业务状态的组件里记录结果。不要为日志再调用治疗、寻路、扣料、抽签或其他会推进玩法的函数；概率记录复用本次结果。开始接近、开始吃饭、实际吞咽必须区分，不能把开始写成完成。
- 重要事件默认 `INFO`，服务端记录一次。客户端渲染和同步不重复记同一事件。已有 `[headwear]`、`[mind]` 等日志继续保留，不再平行重复。
- 新日志用 `status/GameplayLog`：`event(entity, category, message, values...)` 自动附品种／实体类型、`#id`、UUID、游戏 tick、维度和位置。跨重载追同一实体用 UUID；实体数字 ID 只在本次运行内有效。关联目标、brood、票据、聚落或物资要在正文保留标识。
- 没有存活实体的交易用 `world(ServerLevel, ...)`，正文必须给出事务／地块标识。拒绝和等待用 `limited` / `worldLimited`，key 由稳定的事件与原因组成，不能把当前时间、坐标小数或剩余冷却塞进 key。
- 通常同实体、同原因 200 tick 至多一条；明确玩家操作的连点用 20 tick，追击／俯冲切换用 100 tick，部分无草场重试用 1200 tick。按模拟 tick 计时，20 TPS 下分别约为 10 秒、1 秒、5 秒、60 秒。下一次同 key 输出带 `suppressed=N`，表示中间省略的调用次数；没有下一次调用就不额外补一条。
- 限频缓存只在运行期存在，不写 NBT。统一入口每实体／世界最多 64 个 key，弱引用所属实体／世界；达到容量会清空该桶，因此不会保证大量不同 key 并发时仍严格保持原间隔。
- 文本只留排查所需字段。记录实际数量、生命小数、前后状态；不输出完整 NBT、背包或寻路节点。新增系统要同步本页覆盖范围和有意省略项。

## 橙汁与疤痕排查

在试玩场陆 49，先清空本场地，再按原场景操作。以正在运行包的 commit、CI run 和测试时间定位日志，不用当前源码 HEAD 代替。搜索同一实体的 `[body]`：

1. 受伤后应看到 `wound placed/deepened ... on ...`，生命损失保留小数；封顶或无新增变化会写 `wound unchanged`。
2. 橙汁成功应看到 `orange juice cleared N wound(s)`、治疗后生命 `X/Y` 和治疗前生命，随后玩家操作日志给出实际物品数量前后值。没有适用伤病或正在惊慌／水中／着火／濒死等会记录 `treatment refused`，不会消费一剂。
3. 自然愈合或舔舐闭合最后一级时，`scar formed/not formed` 给出伤型、峰值、概率和本次抽签；疤痕已满则写容量原因。橙汁直接清除活动伤口不经过成疤抽签。
4. 面粉糊应看到 `flour paste cleared N scar(s)`，包括旧伤口列表中的疤痕计数；活动伤口和生命读数不因面粉糊变化。

其他链路在原有场景复测即可：护子看捕食目标 UUID 是否转到亲油，妖梦战斗看双方每次真实受击与停止条件；接生／喂食看 brood、新生儿、取粮→交餐→吞咽；水生救援看阶段、滑落原因和登船。没有对应日志时，结合现场阶段读数与 `/yukkuri status` 判断是否尚未进入该边界，不能仅凭“没有成功日志”断定没有执行。

家庭链还记录实际求偶权限判定、接触开始、停止原因和受孕结果；喂食意愿补充本次抽签值，已选中饥饿子油但未找到粮源时限频记录双方营养。亲油死亡时记录携带照护粮是否成功生成掉落物。失散寻亲在实际 Goal 首 tick 记录目标／最后已知位置；普通跟随、守家、等待孩子的频繁停止不记 INFO。

茎生结束后的空茎实物交接用 `[family] shed stem queued/delivered` 串起母体、brood 与掉落物 UUID。`queued` 只表示已登记；`delivered existing=true` 表示找到了此前已经生成的同一物体，不重复声称新生成。身份冲突和生成被拒绝按 brood 与原因 1200 tick 限频，区块未加载或幼体尚未落定不逐次记录。

低频生命周期可在原有试玩入口核对：`factory_wear` 的 `[factory] parent cycle recorded`、`parent retired` 和 `replacement pair assigned` 对照真实组号、服役次数及用途；`agitation_relief` 对照躁动阶段和剩余期，读档初始阶段不当作新发生事件。宠物请求看请求图标／状态与 `[request]` 的类别、主人、过期时主人是否在附近；`satisfied` 表示请求条件满足（食物请求也可能由附近食盆有粮满足），不替代 `[meal]` 的真实吞咽。娱乐设施日志的 `completed` 与现场是否走完整条设施路线对应，纯动作播放不计作设施使用。

迁徙拒绝、饥饿时住所／觅食阻塞和路线重启按实体与稳定原因 1200 tick 至多一条；营养跨档按目标档 200 tick 限频。它们复用现有判定和数值，不额外扫描粮源、选择照护者、寻路或抽签。路线日志只表示已选中可执行路线，实际运行 Goal 仍以现场读数为准。

## 有意省略与按需细查

- 岸边出航的条件拒绝及实际放帽失败默认 INFO，同实体同原因 200 tick 限频；岸上阶段切换按目标阶段 100 tick 限频。无可达岸候选只更新 `water.launch` 中最近判定，不逐次 INFO；`launchCheck`、`checkTick` 是最近一次实际判定，可能因其他 Goal 接管而变旧，不是读数时重新跑业务。真正的拾取、采集和船建立逐次记录。首次观察到已坐船的存档只写乘员观察变化，不声称刚执行了登船动作。

- 不记录每 tick 的移动、朝向、物理接触采样、动画帧、表情、台词和音效；空闲游荡、普通娱乐的连续姿态也不记录。明确玩家发起的相关动作仍在交互入口留结果。
- 不默认记录每次普通问候、自由唱歌／玩耍、宝物凝视、相扑推挤、幼体练习和每次温度采样；保留产生资源、关系、技能或阶段结果的关键边界。野外事件的正式预留和阶段记录不代替内部每个动作。
- 日常亲昵／唱歌／运动与玩具使用只记录活动汇总，按主体与活动种类 1200 tick 限频，不记录每个音符、动作或玩具触碰。呕吐记录实际能量变化与毒素快照，200 tick 限频；不额外抽取发病概率。玩家教学的自动重复拒绝、审判接触变化和没收重复拒绝按稳定原因 200 tick 限频。
- 只有真正创建帽船的两个入口记录碰撞类别；候选水面扫描仍用原有检查而不输出。入口按 Minecraft 1.21.1 `CollisionGetter.noCollision` 的方块→实体→世界边界顺序取得一次结果，保持原碰撞上下文与短路行为，不在失败后重新探测世界。
- 宠物请求沿用原有每只每天至多 6 次、每主人附近每天至多 12 次的业务额度，日志不增加请求；遛弯逐步计程不输出。设施起止、缩壳与躁动阶段按实体及稳定类别 1200 tick 限频，接触中断 200 tick 限频；工厂亲代替补、服役计数与退役只在真正写入变更后记录，日常损耗采样省略。
- 本页覆盖的是表中明确列出的已实现边界，不表示所有系统的内部拒绝分支都已穷尽。剩余细节继续按待办与现场读数补，尤其是更早的 Goal 仲裁、船上照护内部阶段、普通社交的细分拒绝；不为“全量”而默认打开高频 trace。
- 不记录每一滴漏馅、每一步代谢、能量／卫生自然衰减、每次咀嚼或舔舐的微量回血。保留伤病变化、弱势阈值、真正吞咽、治疗与结束时的数值。
- 不把所有候选扫描、无目标扫描、探路节点、分片搜索 `DEFERRED`、逐格挖掘和每棵采草写入 INFO。已经开始的任务在交接、失败、结束、实际交付处留痕；诊断细节不足时补对应读数，不另做一条业务路径。
- 同一自动失败／等待反复出现时限频；成功交易和真正物资结算通常逐次记录。大规模实体和密集战斗仍会产生相应数量的事件，未设置会丢掉真实交易的全局条数上限。
- 水生几何细节继续由原有 `AquaDiag` 开关控制（`/yukkuri aqdiag on`，关闭用 `off`），状态变化细查继续用 `/yukkuri status trace true`（关闭用 `false`）；均不默认开启。它们的细密日志可能较快增大文件。
- `HatBoarding`、`CradlePickup`、`FirstVoyage` 和落水的离散阶段默认 INFO，按实体与阶段 200 tick 限频；同阶段反复停止也限频，动态坐标不作限频键。逐步路径、接触几何、划桨、甲板行走和水流采样仍需 `AquaDiag`，不逐 tick 输出。求偶接触和权限判定 200 tick 限频，照护无粮与失散寻亲开始 1200 tick 限频；读档不重放阶段事件。
- 船内库存日志在实际物资转移处记录，每次弃粮／散落汇总数量，不逐个物品刷屏；空仓扫描、满仓候选判断、救援召回每次发声尝试不输出。挪粮起止／拒绝、警报阶段及救援目标切换按主体与稳定类别 200 tick 限频；库存 `load` 和警报 `load` 不补写旧事务。
- 部分离体茎／巢的纯账本取消没有可用实体上下文时，保留原接口；其取消范围以调用者已有记录及世界账本读数辅助判断，不为日志扫描世界寻找实体。无存活实体但已有 `ServerLevel` 的出生／收容等事务使用世界日志。
- 本次不回填所有旧日志的 UUID，也不默认开启完整实体保存视图。存档诊断仍由现有 `debug.entitySaveViews` 配置管理。

## 试玩场读数按钮移除后的排查

观察台不再放场景读数、主角状态和按钮自检按钮。业务日志仍按上表默认记录；用户只需提供场景和大概时间。`mcylab:read/` 诊断函数及报告通道保留，只有手工调用才生成对应快照和报告日志，不新增自动轮询。移除按钮不会补写此前未查询的状态；缺少瞬时证据时结合现有日志与按需查询判断。
