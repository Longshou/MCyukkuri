# 商店、工厂与人类 NPC

人类世界包括三种独立工厂、街边建筑和人类 NPC（爱派居民、鬼威惨、店员）。宠物店的考试、养成、商品目录、报价和徽章规则见[宠物店](PET_SHOP.md)。代码位于 `human/`、`shop/`；建筑、设备与服装是项目原创转译，作品出处和取舍见[Wiki](../wiki/shops-factory-npcs.md)。

目标规则：人类对象的默认亲近度偏低，油库里不会轻易主动问候；被问候时应回礼。交互中的非语言功能使用 Minecraft 原生交互，只有语言功能进界面。工厂设计重点是加工现场的油库里遭遇演出，机械产出为配套。

## 生成与体验

宠物店含展舱、后场、繁育室和考场，由店主、考官、饲养员及居民运作。劳力工场以真实劳作将甘蔗制纸；馒头工厂处理遗体、蒸制和育成；活体袋装厂清洁、封装和育成，成品仍是原个体。鬼威惨是工厂工头或独立 NPC，只伤害未受保护的野生油库里，不主动攻击玩家；附近爱派可阻止行为。居民可带宠物散步、喂食野生个体和捐赠油粮；商店库存与交互按[宠物店规则](PET_SHOP.md#6-商店)维护。

结构用 jigsaw 与 random spread 在平原、向日葵平原、草甸和热带草原的新区块生成；先检查五点地基，再整平放置。商店与工厂有独立区块间隔，既有区块和被清空的模板不会自动补建。游荡人类只在白天明亮地表生成，附近达到人数上限后停止；结构岗位不受游荡开关影响。

## 店铺登记与饲主归属

`Custody` 统一查询与转换归属。实体 `NeoForgeData.HumanCommerce` 保存 `Owner`、用途 `Use` 和可选 `OwnerKind`；未知用途不改写。离线、跨维度或未加载不表示死亡。只有 NPC 的真实死亡路径会在主世界 `mcyukkuri_custody` 留下死亡记录；普通移除、卸载和玩家死亡不会触发死主清理。未加载的名下个体在以后加载时应用已确认死亡记录：宠物转野生，商店与工厂个体解除归属后可被捕获。

确认主人死亡后，清除全维度已加载的名下个体及中央捕获快照的归属、用途和临时标记，保留血缘、伤病、技能、徽章和历史，不作弃养记录或徽章作废。升级前已死亡且缺少身份或死亡台账的旧 UUID 保持 `UNKNOWN`。运输篮、活体包装和冰柜持有令牌，权威捕获快照位于 `YukkuriWorldData.Captives`；释放失败不会消耗令牌或装备，死主清理可重复执行且不重复返还装备。

店主 UUID 是店铺身份。`ShopRegistry` 保存岗位位置与维度，`ShopStock` 按店主记录货架和每日交易。上架来自模板、岗位命令或玩家卖回；购买保留同一实体的 UUID、家庭、性格、身体和徽章。

居民可在白天、非雨天于住处附近带自己的宠物散步；宠物有紧急需求或落后时散步暂停。居民在宠物附近时不累计冷落。建筑放置和命令共用 `HumanScenes`，并按岗位绑定人员和模板个体。

## 交易、照顾与工厂

店主、考官和饲养员分别负责交易、考试、相亲和运送；其他居民与工厂职员使用 `HumanMenu`。玩家可捐赠普通油粮，店主和饲养员每日补充照顾口粮。居民只在野生个体营养较低时喂食，并对同一目标共用冷却。服务器验证距离、视线、日间、付款、背包容量和现场实体／运输令牌，不能以客户端报价代替。

工厂只接收玩家主手中真实且归玩家所有的运输篮。劳力厂消耗甘蔗和劳力营养制纸；馒头线消耗小麦与遗体食用余额；袋装线消耗纸，产物仍是同一活体。输入数量、原料、成品和中断均按真实库存结算。

`factoryShopShipping` 开启时，工厂每两游戏日可向 256 格内店铺出货至多两只符合独立生活条件的育成栏个体；2400 tick 后可办理到货，仍受空栏和运输条件限制。到货保留徽章数据；有效无章徽章的工厂货才在无章报价上再乘 0.8。`commodityHarshness=0` 同时关闭商品化背景与滞销回收，`staleRationDays` 仅为旧配置兼容项。

自然地形陡坡、建筑重叠、多人交易与长期经济平衡尚未得到游戏验证，相关缺口见[待办](TODO.md)。工厂当前使用单体周转托盘，遭遇演出仍待完成；轮换工位、分选、整茎采收、批次育成和多体袋装未接入。人类关系、被问候回礼、原生交互承载非语言功能及工厂遭遇表现的当前接入边界见[待办](TODO.md)。村边偷粮应优先低伤驱离或请求玩家处理，不破坏房屋。NPC 床上睡眠未接入；居民或鬼威惨身份不自动意味着这些关系行为。最高级考试的生存风险未采用。
