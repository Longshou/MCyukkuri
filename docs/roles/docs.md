# 文档、Wiki 与机械活

适用于文档、Wiki、台词与其他机械活。通用规则见 [AGENTS.md](../../AGENTS.md)。

## 各类文档的写法

- 只写当前：不写排查过程、修复流水、逐轮读数、阶段总结、交接记录、裁决页或计划页；被替代或下线的内容在同一提交删除，不留“旧版”说明。纯内部整理不另写记录。
- 唯一归属：玩法规则在[功能说明](../FEATURES.md)所属小节，进度与问题在[待办](../TODO.md)，理念在 AGENTS.md，做法在角色文件或专题 README；其他地方只链接。来源不明的原创规则注明“项目设计”。
- 功能说明：只写玩家可见规则与关键数值、用户决定和 Wiki 出处，不写实现细节和未实现要求。未实现的要求只在待办，不能写成已实现。
- 待办：维护规则见 [lead.md](lead.md#待办维护)。
- AGENTS.md 只写通用知识、指导思想与设计理念，不写例子和具体做法；角色文件写具体做法；两者都不写原话、日期、出处和背景。
- 制作说明保留产物、接口、使用方法和可追溯来源，不写当轮日期、授权对话、执行代理或工具访问过程；来源的实际采用范围与未核验边界必须保留，不能把既有摘录改写成已核验原文。
- 生成清单只改生成源并重建输出，不手改生成页。场景、按钮、初态和读数只在 `scripts/museum_*.py` 等源码维护，日志文案和字段以代码为准。
- 提交前逐段检查文档差异：是否放在唯一位置、有无重复或过程性内容、是否保留未解决问题与验收边界。

## Wiki

- 以《饅饅來大講堂》（L36）与 [yukkuri.fandom.com](https://yukkuri.fandom.com/) 为主干组织，写成辅助开发的条目式介绍，不写过程性叙述，正文不带抓取、核读、缓存等时间戳（来源的发表信息与抓取记录放来源表或 manifest）。
- Wiki 只随来源证据或采用内容变化更新。
- 来源之间的冲突属正常，全部记录在[设定差异](../../wiki/hakkei-reference/lore/conflicts.md)：游戏已采用的设定以游戏实现为准并注明，不再问用户；其余需用户裁决的冲突登记到[待办](../TODO.md#待用户裁决)“待用户裁决”，由用户决定。

## 台词

- 台词源在 `art/dialogue/`，生成的语言文件与对白资源只经项目脚本重建，不手改生成输出；改完跑台词导出与语料校验。
- 配音与台词最后统一补，用户明确要求前不单独开工。
