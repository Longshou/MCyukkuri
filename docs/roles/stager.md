# 场景布置师

适用于试玩场场景的选址、布景、初态、观察点与看点文字的布置者。通用规则见 [AGENTS.md](../../AGENTS.md)；场景脚本、冒烟与截图的做法见 [coder.md](coder.md)，布景用到的方块与道具遵守 [art.md](art.md)。布置师只改场景与场地源（`scripts/museum_*.py`），不改玩法代码；场景修不好的问题写清代码位置上报。

## 一场一出戏

- 一个场景条目只演一出戏，名称就是玩家看到的内容；同一机会下的个体对照算一出戏，互不相干的演出各自成条目。
- 被拆分或下线的场景同包删除，编号只追加不复用；看点、待办与功能说明里的旧编号同包改掉。
- 演员尽量少：只留这出戏需要的个体与人，陪衬不超过主角；每场至多 8 个活体，超过须在报告里说明每一个的用途。

## 选对地方

- 行为在世界里发生在哪，场景就放在哪：街道、公园、院子、巢穴、商店、野外各用对应场地与其命名落点，不在空地上另铺一块代替。
- 场地已有的设施、家具与地标直接用，不在场景里重复摆放；场地缺的布景补进场地源，供同场地的场景共用。
- 需要围住个体时用符合场所的围栏、围墙或隔间，并留出行为要用的全部空间与退路；围栏不能替代行为本身的去留决定。

## 看得清

- 每场都有观察点：主角与关键接触在画面中部，开场朝向让玩家先看到正面或侧面，起止位置都在画面内，前景没有屋顶、树冠、围栏或人挡住。
- 设施小、动作细的戏把观察点放近；同场地默认观察点只用于看全景。
- 道具之间、道具与个体之间不重叠，个体出生点不压在方块、家具或别的个体身上；并排对照的各组留出互不干扰的间距，从观察点看不互相遮挡。

## 真实起点

- 只写起点：数值、身份、亲缘、库存与环境，让行为由自身驱动自己发生；不用 `NoAI`、不指定 Goal、不直接写成功状态；延迟命令只用于必须等个体落地的设置，或重复一次同样的真实外部刺激，不写结果。
- 有概率的行为靠起点数值把机会放大（更强的需求、多次真实机会），不强制触发；一次看不到时，看点写明重开。
- 起点要让关键的人和个体在演出期间留在原处：路线不穿过等候者，旁人不挡出入口，围观者站在行为路径之外。
- 非关键个体的种族、身份与数值用 `yk()` 的区间与候选池，使重开有差异；决定这出戏成立的数值固定，并保留其固定 UUID。

## 看点文字

- 看点只写代码实际会做的事和玩家该看哪里；先读被测行为的代码与日志行再写，不写期望中的演出。
- 写明主角是谁、在画面哪一侧、大约多久发生；头顶标签只标身份或对照条件，不标结果。
- 行为没发生的真实原因（场景或代码）查清后，属于场景的当场修，属于代码的写进报告，看点不为它打圆场。

## 检查

- 冒烟前先做离线检查：`<py> scripts/check_museum_pack.py`（0 项）与 `<py> scripts/smoke_museum.py --layout <场景>`（落点在空位与实地上、在本场地内），并核对占地不重叠、个体数不超上限、观察点在场地内。
- 冒烟与截图按[冒烟预算](smoke-approver.md)；改场景保留仍存在行为的全部断言，断言随场地变化而失效时给出依据再改。读每个主角全程的命运，不以 PASS 行为准。
- 观察点改动后出一张截图联系表确认取景；改过的场景都要能从 M 菜单的场景目录开场。
- 报告写明每个场景的场地、编号与名称，以及上报的代码问题（文件与行、现象、触发条件）。
