# 轻量季节日历

状态：3.1 代码已接入，尚待游戏确认。此单元只含持久日历、体感季节偏移与观察页，不包含秋季储粮、冬季分粮、春季共享或迁徙。

## 实际阅读的依据与适配边界

- [E07《ゆっくり解体新書》原文](https://w.atwiki.jp/yukkuri_gyakutai/pages/3102.html)：页首作者明确称其为个人设定，数值随意、不要求别人采纳。5.3 的四季段提供春季出窝、夏季活动与风雨、秋季准备及冬季留窝的生活情境；5.4 描写储食窝居及不同越冬机制。本实现遵循开发计划 A3，只采用环境冷暖与实际暖巢方向，不把不同冬眠解释并在一起，不移植统一越冬成功率、月龄或季节强制成熟。
- [N02《ゆっくりの一年春編》原文](https://w.atwiki.jp/yukkuri_gyakutai/pages/2736.html)：实际阅读春段 77–113 与 149–163。春天雪融、个体出窝时，有的家庭尚余食物，有的已经耗尽，有的仍可外出觅食；后段的繁殖选择与冬季余粮、住居准备相关。这里只采用季节影响生活条件、同一季节中个体情况不同，不把春季自动繁殖、固定成长时限或文中角色相信的材料用途作为通则。
- 已查看 `wiki/art-references/images/M14/001-05a0e489.jpg`：寒夜巷中幼体蜷缩、饥寒的画面，支持保暖需求，不给出全种族统一温度或死亡期限。
- 已查看 `wiki/art-references/images/M03/001-5cd90af4.png`：雪地中仍有家庭外出活动。只取“冬天并非一律无法外出”；该篇后续拾取物涉及有毒物，不能称作安全食物。
- 本单元全部季长、温差、遮阴公式和日历推进规则均是 MC 原创适配，不是原作统一法则，也不是现实摄氏度。不改变饥饿与正常睡眠结算，不增加免食冬眠、季节催熟、抗水等于抗寒或强制冬日禁足。

## 唯一服务端日历

`season/SeasonData` 仅存于主世界 `SavedData` 的 `mcyukkuri_seasons` 文件。所有维度通过主世界取得同一实例；实体数量、区块加载数和客户端帧率不影响季节推进。`SeasonCalendar` 只监听一次服务器 `ServerTickEvent.Post`，读取主世界 `dayTime` 与 `doDaylightCycle`。观察页、温度采样和跨维度读取均不推进日历。

默认每季 7 个游戏日，按春、夏、秋、冬循环。一个游戏日为 24,000 个日历刻；不记录现实年号，避免无限累加。存档保存版本、初始化标志、上次主世界时间、每季天数和周期内进度，包含未满一天的余数。

| 情境 | 明确行为 |
|---|---|
| 新装入旧世界或新建世界 | 第一次服务器采样从春季第 1 日零进度开始；已有世界年龄不追补 |
| 正常正向 `dayTime`、睡觉跳夜、正向 `/time add` 或 `/time set` | 计入两次采样间的正向增量，可跨多季 |
| 同一时刻多次采样、只读取季节 | 不重复计数 |
| 负向改时间 | 日历不倒退，只把当前时间设为新基线；之后正向增量正常计入 |
| `doDaylightCycle = false` | 暂停日历；期间命令改变时间也只重置基线，不积压待补时间；恢复后只计算新增量 |
| 保存重载 | 保留基线、季节和余数；相同时间不重复计数，新推进时间不丢失；不读取现实离线时长 |
| 修改 `seasons.daysPerSeason` | 下一服务器采样先保留当前季节和季内比例，再计该次新时间；整数向下取整误差小于 1 个日历刻，暂停时也可调整比例 |
| 负时间与极大正跳 | 时间戳按有符号 `long` 比较；正跳用周期模差求精确余数，避免直接相减溢出。`Long.MAX_VALUE` 跳到负数按倒退重置，不当成正跳 |
| 版本不支持、缺字段或无效 NBT 范围 | 按未初始化日历处理，下次从春季起，不推算历史 |

同一服务器刻内多条时间命令最终以采样时的净时间差为准，昼夜开关也取该次采样的最终状态，不追踪每条命令之间未被采样的中间状态。日历改变只改变季节读数和下一次体感采样，不向任何实体补发饥饿、冻伤、成长、睡眠或繁殖结算。各项身体状态仍按已有已加载服务器刻推进。

## 配置与真实体感

服务器配置组 `seasons`：

| 参数 | 默认 | 范围 |
|---|---:|---:|
| `daysPerSeason` | 7 | 1–365 游戏日 |
| `springTemperature` | 0 | -2 至 +2 |
| `summerTemperature` | +0.45 | -2 至 +2 |
| `autumnTemperature` | -0.25 | -2 至 +2 |
| `winterTemperature` | -0.8 | -2 至 +2 |

参数由配置规格约束，日历入口还把长度夹到 1–365；读取温差时再约束范围，非有限数按 0 处理。NBT 长度不合法则保守重新初始化，不按坏值推导除法。长度切换比例运算的最大乘积小于 `8×10^13`，周期小于 3,504 万刻，均不会溢出 `long`。

只有有天光且没有固定昼夜时间的维度应用季节温差。下界、末地与其他无天光或固定时间维度仍可看同一个世界日历，但温差为零，不硬套普通四季。此模块不改变群系注册、天气类型、降雪、作物或植被颜色。

`TemperatureLife` 先读取当前位置群系温度，加当前季节偏移，再沿用昼夜与遮蔽。夜晚的露天 -0.35、真实遮蔽 -0.15 保持不变。原有基础温度至少 0.8 的白天日晒仍加 0.35；遮阴从加过季节偏移的环境温度中削去高于 0.8 的部分，最多削去 `0.65 + max(0, 季节偏移)`。因此夏季真实树荫也能削去额外热量；削热本身不能把温和环境降至 0.8 以下，寒冷的季节环境本身仍可低于此值。基础温度低于 0.8 的原有白天逻辑保持不变。

之后依次保留原有冷地露天降水、体表湿度、实际干燥完好铺垫窝和无遮挡真实热源。热源不因季节穿墙，记住住所不等于身处暖巢，裸树荫没有铺层保温。既有避险、喝水、饥饿、生育、操作等优先级和完整睡眠规则不变。

默认数值核算（干燥、无热源，表内小数为理想群系值；实际 MC 群系为浮点数）：

| 环境 | 春 | 夏 | 秋 | 冬 |
|---|---:|---:|---:|---:|
| 平原 0.8，白天日晒 | 1.15 | 1.60 | 0.90 | 0.35 |
| 平原 0.8，白天真实阴影 | 0.80 | 0.80 | 0.55 | 0.00 |
| 沙漠 2.0，白天真实阴影 | 1.35 | 1.35 | 1.10 | 0.80 |
| 平原 0.8，夜晚露天 | 0.45 | 0.90 | 0.20 | -0.35 |
| 平原 0.8，夜晚有屋顶、足够干铺层的自用窝 | 0.65 | 1.10 | 0.40 | 0.85 |

默认炎热阈值为 1.5，夏季平原日晒会推动现有避暑和口干机制，真实阴影可供休息。冬季平原日晒仍可能舒适，夜晚则需实际暖窝或可达热源；树荫不能冒充暖窝。初始春季温差为 0，原温度公式逐点保持，包括基础温度低于 0.8、夜晚、降雨与无天光分支。阈值、个体成长阶段和湿度仍会改变结果，不保证所有冬日或所有住所都安全。

## 观察与远端夹具

普通打开观察笔记时首页显示季节、季内第几日、当前每季天数、本维度温差及日历暂停状态；观察实体时也有独立季节页。中英日各新增 8 个键；保留此前独立状态页、2.1 空茎物品名和原有观察内容。

独立远端套件入口为 `./gradlew runP0GameTest -Pp0Suite=seasons`，仅供远端运行：

- `persistenceAndTimeCommands`：旧世界首次启用、多次采样、回拨、跳夜等价增量、暂停中命令改时及恢复、NBT 保存重载与余数、改季长保持比例、配置极值、损坏 NBT；用 `BigInteger` 独立算式对照跨完整有符号长整数范围的大正跳。
- `sharedClockAndRealRefuges`：真实注册的服务器事件在无油库里时推进；多维度共用同一数据与只读页面；无天光/固定时间排除；真实平原、实体屋顶、可达避暑点、有住户及实际铺层的纸箱暖窝、冬日/冬夜差别、破屋顶失去保温；日历跳转不补发生理；冻结昼夜时实际改 `dayTime` 后恢复不追补。结束与失败均恢复时间、配置、天气、日历、方块及强制区块状态。

本机已通过 8 个涉及 Java 文件的 tree-sitter 语法解析、三语 JSON 无重复键/各 8 新键/5 个页参数/原键值完整保留检查，以及差异空白检查。非编译数学核算覆盖 32,192 组春季公式逐点一致性、30,216 组带极值时间戳的周期余数对照和季长变化比例边界；不会把这些检查称为 Java 类型或游戏行为验证。临时报告与哈希清单仅放在忽略的 `.local/seasons/`，不提交。

本机不编译、不运行 Gradle、游戏或界面自动化。日历时间处理、保存重载、多维度共享及真实遮蔽／暖窝采样已在服务端受控场景核对；真实睡觉跳夜、时间命令操作、停服重启、多人及自定义维度兼容、自然避暑导航、季节变化后的完整睡眠和三语页排版仍待游戏确认。
