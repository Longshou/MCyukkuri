## 1　目标与非目标

### 1.1 体验目标

| # | 玩家应当感受到 | 设计含义 |
|---|---|---|
| X1 | **油库里是笨拙、柔软、能力有限的小生物** | 跳不高、搬不动、会打滑都是真实的。能力随体型、体力、伤病变化，同一只个体在任何场景里表现一致 |
| X2 | **看得懂它想干什么** | 动作有预备（看向目标、蓄力、压扁），失败有可见的反应（够不着、滑下来、哭）。玩家能从动作读出意图 |
| X3 | **失败是故事，不是卡死** | 手段用尽才失败；失败留下现场并产生后果（摔伤、落水、放弃、求助）。不出现原地抽搐、来回切换、永远等待 |
| X4 | **仪式感** | 分娩、接生、初航这类重要时刻有专门的编排和演出，但演出里的每个身体动作仍是同一套能力 |
| X5 | **世界是连续的** | 帽船是会漂、会晃、会翻的小陆地；在不在帽里、在不在窝里，只看身体实际在哪 |

### 1.2 工程目标

- **一个能力只实现一次**：新场景靠组合已有能力搭建，不再写衔接代码。
- **问题能定位到层**：每次失败都能从日志读出是哪个意图、哪个手段、哪个动作、差了多少。
- **调参不用等 CI**：能力系数与欲望权重放在数据包里，`/reload` 即时生效。
- **净代码量下降**：水生旧实现（约 1.8 万行）整体删除，重建的 `aquatic/` 控制在 6000 行以内；出生链（`family/` 分娩部分）至少缩小 30%；`motor/` 与 `intent/` 合计在 WP3b 合入时不超过 4500 行、WP6 后不超过 6000 行（水中动作按 4.2 归底座，计入此处）（代码保持仓库的紧凑写法，不写长篇 javadoc）。每个工作包的提交说明写明净行数。

### 1.3 非目标

- 不重写原版实体物理、碰撞和寻路：骑乘、`move` 碰撞、`PathFinder` 全部沿用。
- 不做通用自动规划器（GOAP 式搜索）。手段是人写的有序表，可调、可读。
- 不推翻 52 个现有 Goal 的仲裁。只有迁移到新框架的领域，才在领域内部改为欲望竞争。
- 不在本轮补配音、台词、表情缺口（按 AGENTS 约定最后统一补）。

## 2　诊断：为什么上一轮“统一”没生效

10-26 已经做过一轮“唯一入口”重构，涉及 `CrewTransfer`、`HatDeck`、`HullHelm`、`HullFactory`、`WaterIncidents`、`HatCustody`。10-27 试玩仍多处阻塞。下表证据审计于 6d33c130。

| 病根 | 证据 | 后果 |
|---|---|---|
| **同一事实存多份** | “在船上”同时由原版骑乘、`HatDeck`（102 个席位、6 种租约）、`CrewState`、`HatStations` 表达，靠对账同步；“孩子在帽里”由搬运者、孩子、租约三方各判 | E11“放下又放回”：托举途中孩子仍是帽的乘客（`CrewTransfer:1476`），滑脱后曲线倒放回座（`:1601-1610`） |
| **能力做成了事务** | `CrewTransfer` 1710 行，六个阶段加租约；HOP 按步行限速沿曲线走（`YukkuriLocomotion:66`） | 1.44 格的跳用了 25 tick；出发席位被别处删除，报 `no_departure_seat` |
| **同一动作多套实现** | 跳和弧线至少 8 套、转身 4 套；新生儿一次飞行混用两种重力；帽檐几何有带倾斜、不带倾斜两套 | 反复 `rim_out_of_reach` |
| **失败没有结构** | 几何拒绝被改记为暂时失败，而暂时失败不计次（`CrewTransfers:94-97`）；分娩链至少 7 套预算；状态切换没有滞回 | 救援 `attempts=0`；RECOVER⇄ASHORE 每秒互切 |
| **一个身体多个写者** | 被动时钟写租约和舵（舵调用 127 处，分布在 14 个文件） | `seat_claim_lost`、`boarding_done` 刷屏 |
| **底座认识 DLC** | 底座约 500 处引用水生概念；`LiveDelivery` 有 11 处 `boatHome()!=null` 分支 | 修陆地牵动水生，修水生又牵动陆地 |

结论分四点：
1. 封装的单位应是**动作**（可行性、进度、保证成立的后置条件），而不是事务（票据加租约加阶段）。
2. 每个事实只存一份；失败用有限词表，一个意图只用一个预算。
3. 独有演出放进**编排**，不放进动作。
4. **冻结的旧实现不迁移**。WP1–WP2 合入后 `src/main` 净增约 4450 行：新底座与旧实现并存，旧水生的每一步都还要保持可编译、可运行，并有约 35 个底座文件带水生分支（`ShoreWork`、`boatHome()`、`HatBoatEntity.protects` 等）。旧水生在试玩中主链全部阻塞，逐步迁移的成本高于整体下线后重建。

## 3　设计宪法

| # | 原则 | 评审时怎么判断 |
|---|---|---|
| P1 | 能力决定动作 | 高度、距离、速度、时长只来自能力表或物理 |
| P2 | 一个动作只写一次 | 同类动作没有第二份实现 |
| P3 | 行为只说目标 | 行为代码里没有坐标插值、冲量、曲线 |
| P4 | 限制必须附带手段 | 每个新拒绝原因，都至少有一个方法能缩小它 |
| P5 | 世界连续 | 不使用座位表、冲突矩阵；空间与拥挤由几何现场判定 |
| P6 | 物理是唯一真相 | 动作的每个结束路径都按实际位置落定，绝不倒放、回座、瞬移或回滚 |
| P7 | 帽船是可站立宿主 | 乘员用原版骑乘随船，帽内局部位置自由 |
| P8 | 真实失败有后果 | 手段用尽才失败，失败交给后果规则 |
| P9 | 底座不认识 DLC | 底座包不 import `subspecies.*` |
| P10 | 先验动作，再验行为 | 动作有单元测试或展台，行为问题先定位到动作 |
| P11 | 真实驱动，调欲望不写死（用户裁决） | 不同个体、不同行为之间的先后由欲望竞争产生 |
| P12 | 一个身体一个驱动者 | 同一时刻只有一个动作在改它；被动时钟只读 |
| P13 | 演出可以独有，动作不能独有 | 编排决定何时、什么顺序、谁、播什么；不决定身体怎么动、算不算成功 |

## 4　架构选型

### 4.1 选择与理由

| 层 | 选用 | 为什么不用别的 |
|---|---|---|
| 选择做什么 | **领域内效用打分（Utility），带滞回与承诺** | 行为树把顺序写死，违背 P11。效用打分天然支持“调欲望得演出”，`[intent]` 日志打出前三名得分就能解释选择 |
| 怎么达成 | **意图加有序手段表（HTN-lite）** | GOAP 式通用搜索难调试、开销不可控，代理也难正确实现。手段表人写、可调、每一步都有日志 |
| 身体执行 | **动作层（Action）加单一驱动者（BodyDriver）** | 把唯一会动身体的代码集中起来。动作有可行性、进度、后置条件，失败带差额 |
| 仪式演出 | **编排（Choreography）**，相当于脚本序列与 Smart Object | 分娩这类由设定事实决定顺序的仪式，用编排表达；编排只调用意图和动作，不直接动身体 |
| 物理与依附 | **原版物理与骑乘** | 原版自带碰撞、同步、插值、随载体存档和区块处理；自写平台携带等于重写实体物理 |

### 4.2 分层

```
L3 行为   Drive（选意图）→ Intent（要什么结果）→ Method（有序手段）       Choreography（仪式编排）
              │ 只经 BodyDriver 请求动作
L2 动作   Walk Face Hop Launch Gesture Hold Await Grab Carry Release PlaceProp TakeProp
          Swim Climb Push Right Paddle（水中动作，底座提供，水生只修正系数）
              │ 只读 L1；只经 Motor／Attach 改身体
L1 身体   BodyAbility · Attach · SurfaceHost · ContactGeometry · Container/Occupancy · Custody
L0 引擎   原版 move／碰撞／重力、骑乘、YukkuriGroundNavigation
横切      Presentation（读动作姿态、依附、编排节拍、情绪）· Trace（[intent][method][action][body][choreo]）
```

- **依赖方向**：只能向下依赖。
- **DLC 边界**：DLC 只通过底座的接口接入，即 `AbilityModifier`、`SurfaceHost` 实现、领域 Goal、后果规则和片段注册。水生 DLC 的代码只放 `aquatic/`；`subspecies/` 只留不足形态、灵胖、螺壳等通用亚种。
- **放下的帽子属于底座**：接生帽（帽子翻过来当容器）是陆地出生链的一部分，由底座的 `headwear/PlacedHatEntity` 承担，实现 `SurfaceHost`。水生 DLC 让同一顶放下的帽子漂浮、可划、可翻（第 8 节），不另造第二种帽实体。
- **验收标准**：关掉 DLC 注册后，底座与陆地玩法照常运行。物种事实（水生只与水生配对、水伤数值）是物种数据，留在底座，不随 DLC 下线。

## 5　身体与动作（玩家看到的“手感”）

### 5.1 能力

| 能力 | 成体基准 | 说明 |
|---|---|---|
| 跳高 / 跳远 | 0.8 格 / 1.0 格（用户裁决 Q1） | 子油、赤油按体型缩小；体力低、受伤、负重时下降 |
| 台阶 | 不跳直接走上去的高度 | 超过就要跳，跳不上就绕路或求助 |
| 转身速度 | 有限 | 不再瞬间转向，转身本身可见 |
| 游 | 很弱的挣扎前进（Q2） | 漂浮不等于会游；水生种只在系数上更强 |
| 攀爬与抓握 | 扒住边沿能爬上的高差；在斜面上站得稳 | 打滑是真实的 |
| 够得着 | 嘴、辫梢的可达距离 | 魔理沙的辫子额外加成 |
| 搬运 | 不设重量（Q1） | 被搬者体型小于搬运者即可搬；越大越慢、越容易滑落 |

### 5.2 动作手感约定

- **预备—执行—收尾**：
  - 跳：先压扁蓄力，起跳冲量落在片段的起跳标记上，空中由物理决定，落地时压扁回弹。
  - 抛（新生儿被推出、翻船甩出）：没有预备，直接交给物理。
- **动画是运动的结果**：空中姿态读真实速度，落地片段由真实接触触发，所以动画永远和动作一致。
- **最低弧线**：能跳上去就用最低的弧线跳，不夸张；跳不上就不跳，换手段。
- **失败可见**：够不着时伸长、退回；打滑时滑下；放下时孩子落在真实位置。失败都有短反应，不会静默重试。

## 6　行为、欲望与编排

### 6.1 意图与手段

- **意图**：意图是“要什么结果”，成功条件只看物理事实，例如“孩子在帽腔里且站稳”“帽子戴在头上”。
- **手段表**：每个意图有一张有序手段表。以“上船”为例：
  1. 能跳到就跳；
  2. 走近一点再跳；
  3. 船在靠近就等；
  4. 请亲油叼过去；
  5. 下水游过去再扒上来。
- **换手段**：手段失败时带回“差多少”，优先换能缩小这个差额的手段。环境没变化之前，不会原样再试同一个手段。
- **手段用尽**：交给后果规则，例如哭、呼救、放弃，或者落水后溺亡。

### 6.2 欲望

- **欲望强度**：每只个体同时有饥饿、困倦、寒冷、护幼、亲近、好奇、恐惧、想回水上、帽子不在身边等欲望。强度来自现有需求、性格和环境。
- **选择**：在领域内选“强度 × 权重”最高的意图。切换要超过当前意图一定幅度并持续一段时间，避免来回切。
- **承诺**：正在进行的上船、靠岸、接生等动作带承诺，只有危险能打断。
- **演出靠调参得到**（P11）：例如“亲油先送孩子上船”来自“孩子不在身边”时护幼欲望很高；“下雨不出航”来自寒冷与躲雨压过水上生活的欲望。
- **只有设定事实是硬规则**：生殖只在岸上、水生只与水生配对、水伤数值、产程顺序。

### 6.3 编排（独有演出的唯一归宿）

| 编排可以决定 | 编排不能做 |
|---|---|
| 何时开始、节拍顺序（限设定事实，如产程） | 直接改位置、速度、朝向、骑乘 |
| 谁担任什么角色、站在哪（作为目标） | 自己判断“在不在、到没到、成没成” |
| 播什么片段、表情、声音、粒子 | 自设重试和等待预算 |
| 失败时走哪条剧情分支（摔伤、落水、无接生者） | 排定不同个体之间“谁先谁后” |

## 7　出生链设计

**一个编排，三种接收者**。接收者可以是放下的接生帽、自己的帽船或窝；三者都没有时落在地面。陆地分娩、帽船分娩和茎生只是接收者和发射源不同。

| 节拍 | 玩家看到 | 由谁完成 |
|---|---|---|
| 产地 | 临产母油回窝、上自己的帽船，或在岸边、稳固地面停下 | 母油的“到达”意图 |
| 会合 | 父亲（魔理沙）走到接生站位，两只互相看见 | 共享的会合方法，只有一个期限；超时就进入“无接生者”分支 |
| 放帽 | 父亲用辫子摘帽、翻过来、压在出口前 | 摘放帽动作，播 `hat_off` 片段 |
| 产程 | 阵痛、蓄力、两次用力、喘息（现有节拍与时长不变） | 编排的演出节拍 |
| 出生 | 母油转向出口，孩子被推出，飞进帽里、窝里或地上 | 转身动作加抛射动作；冲量按现有分布抽定并存档 |
| 落定 | 落帽就坐进帽腔；落地就摔伤哭泣；落水就进入落水事件 | 首次接触后按实际位置落定，不预约座位 |
| 初醒与迎接 | 挤扁、睁眼、问候；兄姐小跳 | 演出加小动作，小跳受能力门槛约束 |
| 清空接生帽 | 会跳的自己跳下；不会跳的被父亲逐只叼到地上 | 叼、搬、放三个动作；放下就是放下，不会再回帽 |
| 收帽 | 帽里空了，父亲把帽子戴回头上 | 收帽动作，播 `hat_on` 片段 |

- **保留的独有内容**：产程时钟与片段锁相、孕腹形变与出口锚点、帽子翻过来当容器的姿态、冲量分布、阵痛、问候、产后与摔伤的节拍和声音粒子。
- **帽船分娩**：接收者是自己的帽船，省去会合、放帽、清空、收帽四步。用力过猛的 12% 由冲量自然越过帽檐落水，属于剧情内容。产后把孩子送到父船，是意图“把孩子送到父船”，手段依次为：等两船靠近、请父油划近、叼着越船。

## 8　水生 DLC 设计

### 8.1 帽子：一个物品，四种形态

| 形态 | 物理身份 | 怎么转换 |
|---|---|---|
| 戴着 | 身体的一部分 | 用辫子摘下 → 托着，或直接放到水面、地面 |
| 托着／叼着 | 嘴或辫梢上的物品 | 放到水面就展开 |
| 展开（帽船） | 可站立宿主，也是容器 | 扶起戴上 |
| 翻覆 | 浮动物体，可推、可扶 | 推加力矩扶正 → 展开 |

- **统一尺寸**（Q3）：四种形态只改姿态，不改大小。尺寸在戴着不怪、又能当船之间取值，建议从约 1.4 倍起试，先出预览由用户确认。
- **找回帽子**：帽子不在认可形态时，主人一直有“找回帽子”的欲望，直到戴回、确认放弃或帽子沉没。

### 8.2 帽船：会漂的小陆地

| 方面 | 设计 |
|---|---|
| 上下船 | 没有专门流程。岸上走到边上跳上去；水里游到帽檐扒上去；下船跳下或滑落 |
| 帽内 | 高低不同的地面，可走动；挤不下就被挤到帽檐，甚至落水（Q6） |
| 晃动与倾斜 | 坡度超过抓握就滑；重载更易翻 |
| 浮力 | 任何形态下都生效：翻覆后空帽浮起，进水下沉 |
| 被推 | 可以被推动（Q5），也能被推上岸 |
| 翻覆 | 只由真实外因引起（摇晃、撞击、超载加水流、进水）；乘员是被甩出去的 |
| 储粮 | 粮袋是帽腔里的真实物体，占空间、算重量 |

### 8.3 水上生活

由意图驱动，取代船长阶段机：

| 意图 | 何时产生 | 手段 |
|---|---|---|
| 出航 | 水生种的常驻偏好；下雨、夜晚、缺粮时降低 | 备木棍和粮 → 到岸边 → 放帽 → 孩子上船或被叼上 → 自己上船 |
| 上岸 | 缺粮、要繁殖、要找木棍、天气恶劣 | 划向岸 → 孩子上岸或被叼下 → 自己上岸 → 收帽 |
| 夜泊 | 夜晚或雨雪 | 划进背风岸凹卡住 → 孩子进帽腔 → 船长俯身盖住 |
| 补给、照料 | 饥饿、储粮不足、孩子需要照顾 | 捞漂浮食物或上岸采集；在帽内走到孩子身边 |
| 落水自救与他救 | 身体实际入水 | 游、扒、扶正、划近、托起、请别人帮忙；每个救助者对每次落水只决定一次救不救 |

- **谁在划船谁就是船长**。“先载幼体、船长最后上船”由护幼欲望产生，不写死（Q4）。
- **出航和上岸是短承诺段**，只有危险能打断，从根上消除来回切换。

### 8.4 重建范围

- **首轮重建**以待办中的 P0-1…P0-12 观察点为准（自然生成在船上、单体航程、带赤油出航与靠岸、储粮、落水救助、自救、翻船扶正、船上分娩、夜泊、帽船即家的演出、不卡死）。
- **P1／P2**（初航、天气细节、帽内事故、非亲救助、船体损伤等）在 P0 试玩认可后再排，不在首轮重建里预留接口。
- **旧实现只作参考**：重建时可以从 Git 历史查旧算法（漂移、水面寻路、浮力），但不复制其状态机、席位、租约和票据。

## 9　演出

- **表情优先级只有一处**：操作姿态 > 反应 > 伤病或哭泣 > 情绪 > 兜底。
- **动作姿态来自动作层**：每个动作给出片段和相位；编排的演出节拍可以覆盖片段；客户端只播放同步来的数据。
- **帽上姿态**：按身体在帽内的实际位置、帽面倾斜和地名选取，不再查座位表。
- **可读性**：
  - 动作开始前先看向目标；
  - 够不着、打滑、放弃都有短反应；
  - 等待时有等待姿态，不出现僵直不动。

## 10　调参、调试与验证

### 10.1 调参
- **数据包参数**：能力系数、欲望权重、手段顺序、看门狗阈值都在数据包 JSON 里，`/reload` 即时生效。
- **参数指纹**：日志带参数文件的短指纹，试玩反馈能对上是哪一版参数。

### 10.2 调试
- **日志链路**：每个行为在日志里形成完整链路：`[intent]`（为什么选它）→ `[method]`（用哪个手段、为什么换）→ `[action]`（能力值、差额、实际峰高）→ `[body]`（挂上、卸下、落水）。
- **读数页**：`/yukkuri status <目标> raw` 增加 `body` 页，显示能力值、依附、当前动作、最近结果、意图、手段与剩余预算。

### 10.3 三级验证

| 级别 | 什么 | 谁执行 |
|---|---|---|
| 1 | 身体层纯函数单元测试：弧线求解、容器判定、高度场、能力公式 | 远端 CI（`./gradlew build`） |
| 2 | 受影响的现有试玩场景，必要时补单项展台按钮 | 用户试玩 |
| 3 | 待办 E8–E11 全量复测 | 用户试玩 |

单元测试和 CI 不代表验收，只有用户试玩认可才算完成。

## 12　评审红线

命中任何一条即退回：

1. 在 `motor/` 之外写位置、速度、朝向或骑乘。
2. 新增预约、租约、席位、票据或 `pending` 桥接状态。尝试预算（`Attempts`）和等待动作的期限除外。
3. 失败后原样重试；改记失败分类；同一次失败计入两个预算。
4. 为某个场景加条件分支；底座中出现 `isAquatic`、`boatHome()!=null` 一类分支（应通过接收者或宿主的多态表达）。
5. 行为或编排里出现跳高、时长、曲线、冲量数值（冲量分布数据除外）。
6. 新的拒绝原因没有对应的手段。
7. 失败时倒放、回座、瞬移，或直接改成功状态。
8. 被动时钟改动身体或其他实体的状态。
9. 为同一事实新增第二份存储。
