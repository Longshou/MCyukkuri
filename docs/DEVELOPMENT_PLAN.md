# 完善计划

2026-10-08 制定，2026-10-16 更新。设定依据来自 [Wiki](../wiki/README.md) 整理的漫画、小说和游戏资料，现状依据当前代码、运行资源与 `docs/` 记录。完成一步就在本页标为“已完成”并写上日期；部分实现或尚缺游戏确认的步骤单独注明，不按整步完成计算。

## 怎么用

2026-10-17 设定来源扩充见 [23 个生活领域覆盖表](../wiki/life-settings-coverage.md)与[宠物生活及襁褓](../wiki/pet-life.md)。它们登记新作品证据与待核读问题，不改变本页玩法步骤的完成状态；襁褓款式、长期照护、留守及旅行等新方向在实现前继续区分作品事实和项目参数。

- **每一步包含**：目标、设定依据、主要改动位置、完成标准。玩法步骤以“进游戏能看到什么”为完成标准；整理与工具步骤按各自标准判断。
- **执行方式**：本机只修改代码或建模，按需运行非编译资源检查；`./gradlew build` 由远端 CI 执行。玩法效果由用户在可运行环境中确认，本机不执行构建、测试编译或启动游戏时的自动编译。CI、素材检查通过不代替游戏效果确认。
- **规模**：S 指一次会话能做完；M 需要几次会话；L 需要先拆成几个 S/M 再做。
- **顺序**：阶段 0 最先做。阶段 1、2 是核心体验，优先做。阶段 3–5 是内容扩充，可以按兴趣交替推进。阶段 6 中的 6.2（代码结构整理）应在阶段 4 新增种族之前完成。
- **标注**：
  - **【原创】**：作品中没有的数值或规则，由本项目自定，可以随时调整。
  - **【待定】**：作品之间有冲突。附录 A 已给出采用的版本，实现时按附录执行；以后想改，直接改附录。
- **证据级别**：Wiki 中 A 为作者作品，W 为社区整理，I 为推测，P 为原创。作品之间没有统一正史，以 Wiki 采纳的“本设定”为准。

## 阶段 1：核心体验做扎实

### 1.1 失饰的社会后果（M）——2026-10-16 代码接入，游戏确认待完成

- **目标**：落实“饰品即身份”这一油库里最有辨识度的规则。
- **设定依据**：
  - 失饰个体会被亲友认不出，受排斥，被叫“嗯嗯奴隶”，变得自卑；找回饰品后恢复识别，血缘不变。见 `wiki/hakkei-reference/world/rules.md`、`world/personality-social.md`、传统母题 TM02（L17），以及 L01。这几处写法一致。
  - 只有持金章的观察者能认出失饰个体，这是本项目规则。
- **已接入**：`SettlementSociety` 由同群、可见、实际认不出目标且性格苛刻的观察者触发拒斥；温和成员不会自动处罚。两次拒斥后冷落，五次后按性格驱离或分配清扫【原创】。复用 `canRecognize` 的观察者金章与自用帽船例外；亲缘和群体登记不变。
- **改动**：
  - 在 `settlement/SettlementData` 增加成员职位：自由、成员、首领、被排斥者、嗯嗯奴隶。
  - 失饰的成员一段时间后降为被排斥者，可被驱离；在群里继续待着则可能变成嗯嗯奴隶，被分配去清理厕所。
  - 失饰个体表情偏自卑。`dialogue/catalog.json` 中已有 `lost_accessory`、`returned_accessory` 两类台词，在此基础上补充被冷落、被驱赶时的台词。
  - 找回饰物后，熟人重新认出它；职位按原关系恢复，或保留一段时间的芥蒂【原创】。
- **本轮结果**：成员职位和观察记录持久化；低优先级职责搬运真实排泄物，饥饿、恐慌、照护和操作可中断；原饰物归还恢复此前职位，既有好感不重置。新增 50 条原创中日字幕并同步三份语言文件，尚未配音。已核读 N05 原文及 M03、EH25 指定画格，行为阈值与劳动规则为原创，见 [群落实现](SETTLEMENTS.md)。
- **检查边界**：失饰识别、职位恢复和真实清扫物品转移已在服务端受控场景核对；对白导出与三语键保持同步。实际驱离与连续清扫表现、跨维度重载和多人同步仍待游戏确认。
- **完成标准**：摘掉聚落中一只油库里的饰物，能看到同伴不认它、它被冷落或驱赶；还回饰物后，家人重新认出它。

### 1.2 水：淋湿、洗澡与浸泡分开（S–M）

- **设定依据**：
  - 少量洒淋和短时清洗可以，八景还写到洗澡会高兴；长时间浸泡不行，也不能自己渡水。见 `rules.md`、`wiki/hakkei-reference/lore/ecology.md`。
  - 螺壳魔理沙较耐水，但长时间浸水仍会受损（`lore/species/marisa/tsumuri.md`）。
  - 【待定】“にっき”写法是会游泳（附录 A1）。
- **现状**：2026-10-16 按用户要求，全部油库里身体入水后每 20 tick 扣 1 点生命，不等待湿度阈值，关闭 AI 也不免疫。`wetness` 继续处理湿透与淋雨，螺壳的吸水率较低但入水同样掉血。水生魔理沙靠干燥帽船隔水，翻覆后受同样伤害，亚种与大帽尺寸不因落水改变；遗体也保存亚种供显示。软化与溶化表现仍待完成。
- **2026-10-17 补充**：落水改由 `WaterDistress` 驱动入水冲击、有限体力的间歇扑腾、衰弱与获救喘息，替换持续跳起逃水；新增动作源与离线演出。帽船按体型和实物占位计算容量，赤油可在受支撑帽檐撑稳，危机返帽有近身争位、挤落和亲友护救。按用户要求未跑检查、回归或本机编译；自然触发、平衡和游戏内观感仍待用户实测，不计本步骤整体完成。
- **同日修正**：取消虚构起点及追逐船位的远跳，改为真实靠缘、对齐短跳或水中抓檐爬入。水生魔理沙可尝试翻正自己的真实帽子并攀回，连续水伤与疲劳打滑仍可能致死；亲油实际划近落水孩子，单辫按帽缘最低净空低位接回。当前离线分镜在 `.local/previews/hat-motion/`，未运行检查、回归、本机编译或游戏实测。
- **同日续补**：幼体浮力与主动扑腾分离，亲油使用单辫真实接触、抓托、抬回与放下；摇船后记录实际危险来源，接回家人再撤离。新增亲油实际发声召回、子油听见回应赶回、成功登帽与拥挤挤落的连续事件；沿用已录制的对应年龄台词，按阶段编排表情和语音。仍按用户要求不做编译、检查或回归。
- **改动**：
  - 用湿布或少量表面洒淋清洁、身体未浸水时，可触发高兴反应。身体入水仍遵守每 20 tick 扣 1 点生命的既定规则，不因短时清洗获得免伤。
  - 湿度高时身体呈现“泡软”：外观发暗、动作变慢，伤口更容易扩大。用 `WoundRenderer` 已有的伤口绘制做软化贴花【原创】。
  - 浸没时间过长会导致死亡，遗体使用“溶化”外观。
- **完成标准**：用湿布清洁时它会开心；身体浸入河水后，按既定损伤规则表现挣扎、泡软和最终溶化。

### 1.3 温度：寒冷与炎热（M）——2026-10-16 代码接入，游戏确认待完成

- **设定依据**：寒冷可以致死，但没有摄氏阈值；炎热时会疲惫停步。见 `rules.md`、`wiki/hakkei-reference/world/events.md`。依据冲突时，耐温阈值不补造作品数字，一律按【原创】处理。
- **已接入**：`life/TemperatureLife` 在服务器按已加载时间采样群系、昼夜、遮蔽、湿度、实际保温窝和无遮挡热源；持续受冻会损失体力并累积冻伤，未成年积累更快。炎热会增加口干，并寻找附近可达的阴凉处短暂休息。水中伤害规则保持不变。
- **改动**：
  - 增加体感温度：由群系温度、昼夜、降雪、所处住所是否保温、是否靠近热源（火把、营火）决定【原创】。
  - **寒冷**：持续降低体力，夜里没有保温巢时会受冻伤，赤体和子体更脆弱。
  - **炎热**：白天高温时找阴凉处停下休息，口干加快。
- **本轮结果**：保温要求实际可用住所与干铺垫；火把和点燃营火不隔墙、不叠加供暖。行动让位于避险、进食、急迫排泄和家庭照护等需求，沿途避开火、水与危险方块；观察笔记增加三语温度页。已核读 N07 寒波和夏日穴居段，以及 EH23、EH15 指定画格；阈值、暴露时长和搜索范围均为原创，见 [温度实现](TEMPERATURE_LIFE.md)。
- **检查边界**：体感阈值、遮蔽与热源、冻伤、真实避寒导航和完整睡眠结算已在服务端受控场景核对。自然地形中的移动与保温效果、家油窝路径、临产与喝水优先级和多实体开销仍待游戏确认。
- **完成标准**：在雪地群系过夜，没有巢的幼体会冻伤甚至死亡；放进保温窝的能熬过去。沙漠的白天，它们会躲到阴影里。

- **剩余**：成员脱离聚落、伴侣解除目前没有接口，瓦解只解除约束并降低好感；在游戏中确认。
- **完成标准**：在家族附近建房后，会遇到一次认屋事件，且不同处理方式会有不同结局。

- **剩余**：强盗团没有离开或消散逻辑；在游戏中确认。

## 阶段 6：技术与体验

### 6.1 运行资源瘦身（M）

- **现状**：
  - 2026-10-15 核对 `yukkuri/` 下 19 个运行模型 JSON（不含 `badge_mounts.json`），合计 188,459,982 字节，约 188.5 MB；仍以未压缩 JSON 存储。

- **后续决定**：
  - 先比较同一版本完整 Jar 的发布体积与 Java 实际加载／重载耗时，再决定保持 JSON、调整归档压缩或采用新格式。Jar 已是 ZIP，展开文本大小不等于可节省的发布体积。

  - 若确认值得压缩，保留解压后原始数字字面量及模型指纹，统一维护导出链、资源包覆盖与加载兼容，不改动美术标准。
- **完成标准**：选定方案有完整 Jar 与 Java 测量支持；模型外观、资源包覆盖及既有几何身份保持兼容。未达到收益目标时保留现格式，不为压缩而改。
