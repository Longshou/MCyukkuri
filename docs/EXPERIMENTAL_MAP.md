# 油库里试玩场

试玩场是唯一的试玩地图，也是唯一的测试入口：仓库里没有 GameTest 或别的测试地图，玩法效果都在这里亲自试。根目录 `启动动作博物馆.cmd`（文件名沿用，免得打断习惯）用远端 CI 的现成运行产物启动游戏，不执行本机编译。

试玩场是**开放场地**：真实的草地、土丘洞穴、池塘、屋子、街道、群系里，个体按普通规则自然运行，只在起点设置真实状态，想看就看、想快进就快进、想重来就清场。没有玻璃罩，没有被固定的演员（唯一例外是“动作片段”区的九位只播动作的演员）。

试玩场的设施（大厅、观察台、按钮、清场与时间天气倍速）是项目原创的试玩设施，不出自原作；它展示的行为各有依据，见对应系统文档与 `wiki/`。

```text
启动动作博物馆.cmd            世界缺失或生成器改动后，先现场生成全新世界，再启动游戏
启动动作博物馆.cmd -Fresh     无论如何都生成全新世界（旧存档丢弃）
启动动作博物馆.cmd -Resume    保留已有世界，即使生成器已改
启动动作博物馆.cmd -Menu      进入 Minecraft 主菜单而不是直接进世界
```

第一批亲缘与威胁复测：`myon_brave` 同时读妖梦和捕食种，比较双方血量、`behavior.myon_combat` 的伤害／冷却／距离／接触范围／视线及 `behavior.predator` 反击；`sacrifice`／`sacrifice_reluctant` 读亲油 `behavior.protection` 的 `danger`、`decision` 与 `chance`，对照捕食目标和孩子血量，`diverted` 表示已引开，走近挡护动作待补；`hatless_kin` 比较智力 40／80 的实际认亲与鄙视记录；`hatless_monster`／`hatless_boundary` 对照两处明显伤口与单伤低血量；`family_search` 读双方的 `home.family_state`。这些读数只观察真实行为，不驱动结果。

迁徙与住所复测：`colony_migrate` 保留原迁徙复测，`colony_migrate_babies` 使用真实家庭与储粮、从会爬的赤油初态出发，观察爬行跟亲、亲油寻回喂养与共同认屋。两者的全体成员读数显示 `identity.settlement_detail`、真实 `home.pos` 与住所种类；`dig` 看 `home.dig_progress` 和挖穴阶段；`forage` 看 `home.forage_state` 的半径、最远距离、携粮与送回次数。这些读数无需开启存档调试视图。

帽船托管复测：`hat_custody` 同时读帽主、赤油与实船 NBT（`OwnerYukkuri`、`AccessoryToken`、`State`、`Cargo`）。无安全落点时没收不能改变凭据和库存；成功后只得到一顶原帽，孩子安全落岸。`hat_custody_burn` 施加一次真实火焰伤害，观察失帽、落水与一次性散落；原船被删除后，查询剩余实船无目标是预期结果。

容量与实物桨复测：`cargo_full` 看 11 粮＋1 桨占满 12 份；`cargo_load` 看赤油占 2 份后余量；`cargo_rescue` 看弃粮后接回且桨仍在；`cargo_stow` 看内外粮数之和不变。`shore*`、`voyage` 读双向归队与初航状态。使用 `water.cargo` 对照实船 `Cargo`，不以动画次数当作物品数。

返帽与救援复测：`water.self_rescue` 读原帽、接近／抓握／翻正／攀入阶段，`parent` 部分读同次翻船决定、目标、重试等待与失败原因；`water.distress` 读幼体实际落水与引导。`capsize_siblings` 中成功接回一只后仍需寻找另一只，失败重试不能重抽救子决定；同一孩子两次托举失败或 960 tick 总窗到期后应交回自救，`attempts/window` 显示实际尝试与剩余时间；超出实际托举能力时也允许转自救。

自主出航与船上接生复测：先用 `sail` 读单体取桨、备粮与登船，再用 `afloat` 读亲油、岸上赤油与实际阻塞；`couple_boats`、`family_skiffs`、`birth_boat_*` 同时读双方。`water.launch` 区分放船、候选水面重试与返岸访问；`water.birth` 读产程阻塞、双船余量和实际托举阶段。子油跨船后应只有一个乘坐归属，两船容量与预约随之变化；未满足距离、物理落点或余量时不能凭空转移。

## 展示规划

### 导航原则

- **大厅只管“去哪儿”**：站点墙按主题分组，每个按钮传送到一个区的观察台，旁边的牌子列出这个区的场景。大厅**没有**时间、天气、生成、清场、倍速、读状态。只有“领取导览书”这个信息按钮。
- **细节都在区里**：生成场景、清场、时间、天气、倍速与推进，只在各区的观察台上。试玩不设读数按钮；排查以服务端日志为主，必要时手工调用诊断命令。
- **随处可回**：每个观察台有“回大厅”；每个区南边（区外）有一对“回观察台／回大厅”按钮；生成场景把你带到场景旁，聊天栏里的 `[回观察台]` `[回大厅]` 可点击；`/function mcylab:home` 也行。
- 世界是平坦世界：草地顶面 y=63，站立高度 y=64。进图后是创造模式，出生在大厅，观察标签默认开。
- 普通场景从北侧观察，个体初始面朝北；需要对视、水岸动作或定向受击的场景保留各自朝向，商店与工厂从入口一侧观察。个体随后由普通 AI 自由转向。

### 丧偶再配对（`widow_repair`）

日常草地生成“待再配对者”“原伴侣”“新候选”，双方已有好感、住所和对候选的繁殖许可，由普通 AI 自然求偶；不使用 `scenario mate` 改写关系，也不预设胎次。

1. 原伴侣活着时，待再配对者与候选不能受孕。用收纳篮带走原伴侣，再存档退出并以 `-Resume` 重载，仍应维持配对限制；单纯离开区块也不算死亡。
2. 将原伴侣放回，在场地附近执行 `/kill @e[tag=scn_old_partner,limit=1]`。只有家族账本登记为 `DEAD` 后，待再配对者与候选才可自然求偶、受孕。等待期间可喂苹果，避免饥饿挡住繁殖。
3. 受孕前执行 `/data get entity @e[tag=scn_widow,limit=1] YukkuriFamily.Partner`，仍应读到原伴侣 UUID；正常受孕后才写入新伴侣。死亡后的旧遗体仍保留原有伴侣副本。保存重载后继续观察，不应恢复旧的繁殖限制。
4. `REMOVED` 单独对照：清场重开，先执行 `/tp @e[tag=scn_old_partner,limit=1] ~20 ~ ~`，再执行 `/execute at @e[tag=scn_old_partner,limit=1] run yukkuri clear ~ ~ ~ ~ ~ ~`，只移除隔开的原伴侣。此路径不登记死亡，待再配对者仍不能与候选受孕。

普通配对回归使用 `adult_pairing`：保留原场景的双方回应、近距互见、喷雾中断和受孕完成表现。

### NPC 主人死亡（`custody_death`）

街道区生成一名 NPC 主人、带章宠物、库存、工厂输入、可先装篮的走失个体、已归玩家的个体和无已知主人身份的旧档对照。每次生成使用新的 NPC UUID，清场不会抹掉已经确认的死亡记录。

1. 主人活着时先用运输篮装起“可先装篮”（`scn_custody_lost`）。它的 Use 是 lost，装篮不会改归玩家；胸背带和铜章保存在同一权威快照中。先保存退出并 `-Resume`，验证单纯重载不释放归属。
2. 在场地执行 `/kill @e[tag=scn_custody_owner,limit=1]`，再用诊断命令核对四组归属。宠物、库存和工厂输入应无 Owner／Use／活动标记；工厂 `FactoryCycles:3` 历史仍在。玩家个体仍归玩家；UNKNOWN 对照仍保留原 UUID 与 `future_use`。宠物只信任死 NPC 的那份历史仍在，但不再提供饲主保护。可用普通捕获规则与喷雾检查无主者装篮。
3. 先尝试向狭窄位置或液体内放出篮中个体，应失败且保留 token，不产生胸背带掉落；再向空地放出，应只出现原个体并归还一次胸背带，铜章等级不变。普通篮子放出保持无主，随后可按原规则收养；反复存档重载不重复归还装备。冰柜可在主人死前存入这只篮子，再于死后取出放出，检查租约与 token 未被死亡处理绕过。
4. 卸载对照：重新生成后将主人与个体分开，只让主人所在区块卸载，不能释放名下个体。死亡延后加载对照则让个体区块先卸载，再杀主人，返回个体区块后应解除归属。另可把个体带到其他维度保持加载，再在原维度杀主人，观察跨维处理。
5. 原有 `exam` 场景继续用于中断、退出重进后的完整考试回滚；`factory_bag` 用于托盘乘客在工人死亡后卸下，帽船乘客不应被该清理踢下船。三者均沿现有试玩场入口，不另建地图。

### 观察台的按钮分类

观察台抬高四格，从南侧落点进入时面向按钮；按钮横纵间距均为三格，每排最多九个。各区常用按钮位置一致，场景数量不会挤走它们。从入口往北依次为：

1. **青色常用排**：回大厅、到主角身边、恢复正常速度（1x）、观察标签开／关、旁观／创造；最右侧是红色“清空本场地”，中间空一列，避免挨着模式切换。清场仍无条件执行。
2. **绿色倍速排**：3x／5x／10x／20x；推进 1／5／20 分钟，快进后恢复原速。
3. **黄色环境排**：清晨、正午、黄昏、夜晚；放晴、下雨、雷暴。
4. **橙色场景排**（一到数排）：每次先清场再生成；家油屋的“模拟人类活动”“睡一晚”和动作片段的额外操作跟在场景后面。

所有场景专用读数、“读状态”和“按钮自检”的实体按钮均已移除。此调整为**已接入待试玩**；完成标准是在各区能顺手找到并点击常用操作，场景按钮全部可用，标签不互相遮挡。池塘观察台随按钮减少而缩短四格。

服务端业务日志继续默认记录，用户提供场景和大概时间即可由 AI 排查，不需要先按读数。需要瞬时状态时仍可手工执行 `/yukkuri status` 或 `/function mcylab:read/<场景id>_<序号>`；主角入口为 `/function mcylab:read/<场地id>/lead`，场景序号按 `museum_scenarios.py` 中 `reads` 从 0 起。原诊断函数保留位置锚点及 `yukkuri readout <命令>` 报告通道，执行玩家收到完整只读报告，报告日志只在实际调用时生成；不会自动轮询或补造历史快照。本文下方提到的“读数”均指排查时的命令查询，不再要求玩家点按钮。

旧世界的命令方块不会随源码自动改写；用原启动入口正常重建世界才会出现新排布，`-Resume` 会保留旧布局。不在运行中修改世界。

### 场景操作提示

- **捕食与逃避**：先看“看见捕食种”和街道的“鬼威惨”，确认未受击就退避；再看“被捕食种追猎”“捕食种远处觅食”，观察接近、咬击、吞咽及继续觅食。“捕食种宠物”的两只捕食者都处于饥饿状态，可比较银章受训者的克制和未学等待者的反应。
- **挡捕食种**：高、低意愿场景使用相同站位，差别在亲油的性格。重复生成比较护子选择；没有强制成功，护子后仍可能逃跑或受伤。
- **亲子距离**：先看同为 4 格间距的普通／大胆孩子，再看 14 格走散后的寻回；可用读数确认当前行为。独立场景继续检查已离巢子代不会被拉回。
- **失饰欺负**：用“读欺凌伤口”比较受害者血量与伤口；同一案多人只成功咬伤一次。重伤怪物对照应尽快停止欺凌，不再持续追推。
- **首餐后首便**：先不丢食物，观察未进食的新生儿只求食、不开始首便；再把苹果丢到亲油身边，看嚼糜、递喂、吞咽和首便的顺序。“读首餐与首便”可查看记录；存档重进后，已吃首餐或已完成首便的状态应保留。
- **请吃了我**（`offering`）：默认保留饥荒下的概率献身；重开后，向亲油写 `home.offering_state=offer` 可跳过抽签，或在子油仍饥饿时写 `health.core=damage`，验证同一机制的临终献体。读亲油与子油状态，核对受赠遗体和孩子后续进食。
- **腾空与小跳**：生成后等两秒，高抛与小跳同时开始；看高抛时的感叹和落地后的恢复。重复生成可重看。
- **家油血量**：空手攻击各阶段家油，需要核对数值时再用诊断命令比较。受击仍扣血、死亡仍留遗体；家油不显示伤口。
- **徽章与旁人**：生成后拿到的是该宠物的银章，右键给它佩戴，再看旁人的反应。
- **相亲**：等 2 秒完成窝位登记，持场景给出的绿宝石右键北侧店方饲养员。玩家宠物与店方种油均已登记银章，生产窝旁留有两格空窝。
- **魔理沙好斗、失饰的孩子**：前者直接发起普通相扑挑战，观察各对的不同回应；后者使用不饿的子油，避免赤油照护打断认亲。
- **吃草**：左侧有苹果和草，右侧仅有草；观察取食先后与咽下草时的嫌苦表现。草被啃后仍退回上一阶段并可再生。
- **橙汁治伤与烤足**（`treatment_severe`）：六只分别提供四类 3 级伤、旧包扎与真实烤足对照。直接用橙汁后伤口清除、生命补满、`health.foot_burned=false`；无需面粉糊前置。旧包扎者在治疗前照常漏血、`Bandage` 保存为 0；口服小麦粉只补营养。
- **去疤与治伤分工**（`treatment_scars`）：分别先用面粉糊和先用橙汁，比较伤口、血量与疤数：面粉糊只去疤，橙汁只治伤回血并保留旧疤。另看自然闭合生成的疤能被面粉糊去除，以及健康无疤者的无效用药不扣料；检查玩家扣料时切到生存模式，创造模式不消耗物品。
- **NPC 治疗用料**（`treatment_care`）：伤者初始有 3 级裂口、感染 4、疤痕 1。读伤者和医疗余量，近身连续照料时橙汁先清伤补血、草药再把感染降到 0、面粉糊最后去疤，`Medicine` 预期 8→7→6→5。若走散或照料间隔较久、感染先自然消退，草药无效不扣料，最终可为 6；按实际成功剂数核对，恢复后再等两轮也不继续扣料。
- **脏污与伤痕**（`marks`）：后两只有 1／2 级撕裂，等待自然闭合后比较伤口与 `marks.scars`，再用面粉糊去疤。自然留疤按伤型与历史最高伤级抽取，可能不留疤，可重开比较；自然愈合与舔舐不会去旧疤。

已删除的内容：领棉絮／领食屑按钮和 `nest_lint`、`food_scrap` 物品（家油改为由人类活动的痕迹驱动）、族长派工（采集／侦察／传话）与制造威胁按钮、“亲船上岸”场景、预置的独立施工工程与第二处洞口。

- **天气与捕食种**：一片空地，西侧一块 5×5 石顶（离地两格，四根墙柱），东侧很远处是没有顶的空地，视线开阔。
- **池塘与河湾**：椭圆池塘，西岸缓坡入水；岸格比水面格高一格，岸格与水格相邻，水深 1–4。
- **家油人类屋**：石砖地基、木地板、窗、屋顶、南门；有床、炉灶与烟熏炉、工作台、釜、餐桌、围栏里的一只羊（可剪毛），以及两处隐蔽墙角（两侧是墙，第三侧是书架或箱子桶，南面是入口）。屋子内部落在同一个 16×16×8 的活动格内（中心坐标对 16 取余为 8）。
- **商店／工厂**：空地和一条街；整座建筑由 `yukkuri human build` 放下（会自动清场、填平，商店在店主柜台后放一只银章爱丽丝）。商店占 41×33，工厂占 41×35。

## 家油的“模拟人类活动”需要开启生物生成

家油搬入的条件之一是游戏规则 `doMobSpawning` 为真，而试玩场平时关着它（免得凭空冒出野怪）。所以“模拟人类活动”和“睡一晚”按钮只在那一次调用里打开它，调用结束立刻关回去。

## 为什么速度按钮不用 `/tick`

原版 `/tick` 需要权限等级 3，而数据包函数和命令方块只有等级 2，所以按钮用 `yukkuri speed rate <20–400>` 和 `yukkuri speed sprint <ticks>`（等级 2）。旧版的 `util/speed_*` 函数因此根本没有加载。

## 清场永不拒绝，清完回到同一初始状态

“清空本场地”之后再按场景按钮，实体、世界账本和地形都回到同一初始状态（[AGENTS.md](../AGENTS.md#修复与试玩场) 的可重复要求）。场景按钮自己就是“先清场再生成”。

1. 取消本区未执行的延迟初始化（`scn/<id>_late`）、重试链、返岸呼叫和动作片段。
2. `yukkuri clear <方框> fld_<区>`：强制移除方框内**本模组的全部实体**（油库里、遗骸、帽船、材料掉落、人类）和**所有掉落物**，再加上带本区标记 `fld_<区>`、已走出方框的已加载实体。标记由 `util/tag_fields` 每 2 秒发给站在各区方框里的实体，所以独立离巢、逃跑、被追出场地的个体也会被清掉。移除不是死亡：胎次照普通移除取消，聚落群落和站点按中心落在框里移除。随后各账本忘掉本区留下的记录：
   - 家族账本：被移除个体、最后登记位置在框里的个体（包括上一轮死掉的），以及她们的胎次和胎儿；
   - 认知账本、好感关系、待处理的饰品没收，野生事件和住所宣言（结束并删除，去掉成员冷却和框内区域冷却）；
   - 框内的再生草排程、待掉落的空茎、家油活动格与喷雾、店铺登记、工厂与店铺的配送记录（连同在途的托管令牌）。
3. 清掉带 `scn_prop` 标签的原版小道具（家油屋的羊），重建地形，最后再清一次拆除旧方块时产生的掉落。

没有“真实过程进行中所以拒绝”这回事，也没有任何前置条件。方框有一部分没加载时，`yukkuri clear` 跳过那部分，不整条失败；地形 `fill` 需要区块已加载，所以要在观察台或场地附近按清场。群系聚落区的清场是整区清（一次一个聚落，免得撞上人口上限）。

不带标记的 `yukkuri clear <从> <到>` 只移除实体和聚落登记，账本照常记 `REMOVED`；丧偶再配对的 `REMOVED` 对照用的就是它。

**故意不复位的**：收纳篮或冰柜里的个体（托管令牌还在，固定 UUID 的场景个体装篮后不放回，重开时这只会被拒绝生成）；已确认死亡的 NPC 主人（`custody_death` 每次用新 UUID，不受影响）；玩家自己的记录（弃养记录、徽章特权、每个店主的货架与每日交易）；倍速；场地矩形外的方块。

**本身就随机的**：`yukkuri settlement spawn` 与 `site vacant` 每次用新随机种子规划布局和成员，群系聚落和族规场景每次的村落不同；概率行为（护子、献身、翻船选择）每次重抽。用固定 UUID 的场景（`museum_dsl.uid`）亲缘、胎数种子都一样；没写 UUID 的个体每次是新 UUID。

`/function mcylab:scn/<id>` 只生成不清场，可在任意平地试用，但不保证初始状态；要重复同一初始状态请按观察台按钮。`yukkuri settlement spawn`／`site vacant` 在同一广场列上遇到旧站点记录时，空记录换成新建的规划，有群落住着则拒绝。

## 场景命令（`command/ScenarioCommands.java`）

数据包的 `scn/<id>` 函数在场景的锚点处用 `summon` 生成个体，再用下面这些命令设置**无法写进 NBT 的真实状态**。需要个体站稳才能成立的（认窝、受孕、放帽船）放在生成两秒后执行（`scn/<id>_late`）：同一刻刚召唤出来的个体还没落地，走得到不到的判断会失败。

| 命令 | 作用 |
| --- | --- |
| `yukkuri scenario wound <对象>` | 一处真实磕伤（走普通伤口路径） |
| `yukkuri scenario bond <甲> <乙>` | 双向好感，让它们互相认识、愿意亲近 |
| `yukkuri scenario mate <甲> <乙>` | 让两只成体结为真实伴侣 |
| `yukkuri scenario aftermath <受影响者> <来源>` | 设置兼容成体在镜头外受袭后的真实茎生与营养负担；不把来源设为伴侣或照护父，不由附近接近自动触发 |
| `yukkuri scenario kin <亲> <子> <新生?>` | 建立真实亲子；`true` 时幼体按新生儿保留首便与学动照护 |
| `yukkuri scenario home <对象> <方块>` | 认下窝；若给的是符合条件的朝南洞口，先把它登记为家 |
| `yukkuri scenario birth <母> <父> <natural\|caught\|missed>` | 真实受孕并推进到临产 |
| `yukkuri scenario boat <模式> <亲> <其他> <岸> <水>` | 亲油的帽船放在水面；水格在干岸外 2–8 格且低一格；模式 sail／shore／high／voyage／braid／self／birth／drop／shake／afloat 等 |
| `yukkuri scenario shore <亲>` | 请亲油返岸收帽 |
| `yukkuri scenario independence <亲> <亚成> <洞口>` | 亲子放进同一个洞并让亚成准备独立（场景里改用 NBT 的 `YukkuriIndependence:{Force:1b}`，让一家自己认洞） |
| `yukkuri scenario eggs <母油> <父油>` | 在双亲认下的干净家油窝建立真实卵生胎次与卵位，保留健康、食物与繁殖条件 |
| `yukkuri clear <从> <到> [场地标记]` | 强制清场；带 `fld_<区>` 时连同走出方框的标记实体和账本记录一起清（见上） |
| `yukkuri observe on\|off` | 观察标签（生成场景时自动开启） |
| `yukkuri speed rate <20–400>`、`speed sprint <ticks>` | 倍速与推进 |
| `yukkuri relay <命令>` | 运行命令，回显发给附近玩家 |

亲子、父母、伴侣写进 NBT 时用固定的 UUID（`museum_dsl.uid`），所以家庭洞、外出觅食等场景在生成那一刻就是真实的一家。同一 UUID 每轮重用：清场让家族、认知、好感等账本忘掉这些记录，上一轮死掉或走散的个体不会挡住下一轮生成。

## 校验与工具

本机不编译、不启动游戏窗口，校验都是纯 Python 加无界面服务器：

- `python scripts/check_museum_pack.py`：生成数据包，核对每条 `yukkuri ...` 命令（包括 `relay` 包着的）能在 Java 注册的命令树里走通，每个 `function` 引用都存在；每个场景有开始函数、本场地观察台上的按钮；**每个观察台和每个区的出口都有回大厅**；**大厅只有传送按钮和导览书，没有时间、天气、倍速、生成、清场**；每个观察台有清场、时间、天气、倍速、推进、观察、模式按钮，没有读数或按钮自检按钮；场景函数里没有 NoAI／无敌；没有已删除的物品和命令；每个洞穴的门洞格空着、有两格顶、缺口两侧有土；家油屋内部在一个活动格内；场地、观察台和出口互不重叠；池塘的岸与水对得上；每个按钮不被后来的方块覆盖；每块牌子放得下（按中日韩宽度算）。
- `python scripts/render_museum_map.py`：从生成器数据画俯视布局图（默认写到 `.local/previews/museum/map.png`）。
- `python scripts/build_museum_full.py --pack-only --output .local/experimental-map/<新目录>`：只生成数据包。无界面自查工具（`.local/harness/`）可以用 `--datapack` 装载这个数据包（里面的 `saves/MCyukkuri-Museum/datapacks/mcylab`），数据包的 `load` 函数会自己建图；要用 `generator-settings` 属性换成与试玩场一致的平坦层（基岩 1、石头 124、泥土 2、草方块 1，草顶 y=63），池塘才不会漏水。

维护时可手工执行 `/function mcylab:selfcheck`，核对已加载区块里的按钮数。`MCYMUSEUM_BUILD_COMPLETE` 日志只表示建图结束，不代表玩法验收。

## 备注

- **运行模组过旧会大声报错**：进图时数据包先“探针”检查所需的命令（`scenario`、`clear`、`observe`、`speed`、`relay`、`settlement` 子命令）、方块、物品和实体。缺任何一个，屏幕出大标题“运行模组过旧”，聊天栏列出缺的是哪一类，并且**不再布置地图**。
- 世界由 `scripts/build_museum_full.py --install` 从数据包生成到 `.local/experimental-map/museum`，整体替换，不在旧存档上修补。`map-manifest.json` 记录生成器输入的哈希，启动器据此判断世界是否过期。
- 世界元数据（`level.dat`）取自 `.local/experimental-map/museum-seed/level.dat`，第一次从任一旧存档复制即可；脚本不复制区块、实体或玩家。
- 在实际游玩的机器用 `scripts/update_museum_runtime.py --run <run-id>` 更新同一提交的成功 CI 运行包；旧包保留，哈希核对和清单读回成功后仍从原 `.cmd` 启动，见[开发指南](DEVELOPMENT.md#试玩与检查)。
- 运行配置是 `.local/experimental-map/museum-runtime.json`：`runtime`（CI 运行产物）、`java`，可选 `python`（装有 nbtlib 的解释器）。
- 制作脚本：`build_museum_full.py`（装配、函数、数据包、世界）、`museum_fields.py`（区与地形）、`museum_scenarios.py`（场景）、`museum_dsl.py`（生成真实个体的词汇）、`museum_sites.py`（按钮、牌子、观察台）与 `museum_actions.py`（动作目录）；动作覆盖见 [动作目录](MOTION_MUSEUM_ACTIONS.md)。动态接触、长时间导航、多人干扰、重启恢复与帧耗时需要在可运行环境里实测。
