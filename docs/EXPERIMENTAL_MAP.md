# 油库里试玩场

试玩场是唯一的试玩地图，也是唯一的测试入口：仓库里没有 GameTest 或别的测试地图，玩法效果都在这里亲自试。根目录 `启动动作博物馆.cmd`（文件名沿用，免得打断习惯）用远端 CI 的现成运行产物启动游戏，不执行本机编译。

试玩场是**开放场地**：真实的草地、土丘洞穴、池塘、屋子、街道、群系里，个体按普通规则自然运行，只在起点设置真实状态，想看就看、想快进就快进、想重来就清场。没有玻璃罩，没有被固定的演员（唯一例外是“动作片段”区的九位只播动作的演员）。

试玩场的设施（大厅、观察台、按钮、清场与时间天气倍速）是项目原创的试玩设施，不出自原作；它展示的行为各有依据，见对应系统文档与 `wiki/`。

```text
启动动作博物馆.cmd            世界缺失或生成器改动后，先现场生成全新世界，再启动游戏
启动动作博物馆.cmd -Fresh     无论如何都生成全新世界（旧存档丢弃）
启动动作博物馆.cmd -Resume    保留已有世界，即使生成器已改
启动动作博物馆.cmd -Menu      进入 Minecraft 主菜单而不是直接进世界
```

## 展示规划

### 导航原则

- **大厅只管“去哪儿”**：站点墙按主题分组，每个按钮传送到一个区的观察台，旁边的牌子列出这个区的场景。大厅**没有**时间、天气、生成、清场、倍速、读状态。只有“领取导览书”这个信息按钮。
- **细节都在区里**：生成场景、清场、读数、时间、天气、倍速与推进，只在各区的观察台上。
- **随处可回**：每个观察台有“回大厅”；每个区南边（区外）有一对“回观察台／回大厅”按钮；生成场景把你带到场景旁，聊天栏里的 `[回观察台]` `[回大厅]` 可点击；`/function mcylab:home` 也行。
- 世界是平坦世界：草地顶面 y=63，站立高度 y=64。进图后是创造模式，出生在大厅，观察标签默认开。
- 普通场景从北侧观察，个体初始面朝北；需要对视、水岸动作或定向受击的场景保留各自朝向，商店与工厂从入口一侧观察。个体随后由普通 AI 自由转向。

### 丧偶再配对（`widow_repair`）

日常草地生成“待再配对者”“原伴侣”“新候选”，双方已有好感、住所和对候选的繁殖许可，由普通 AI 自然求偶；不使用 `scenario mate` 改写关系，也不预设胎次。

1. 原伴侣活着时，待再配对者与候选不能受孕。用收纳篮带走原伴侣，再存档退出并以 `-Resume` 重载，仍应维持配对限制；单纯离开区块也不算死亡。
2. 将原伴侣放回，在场地附近执行 `/kill @e[tag=scn_old_partner,limit=1]`。只有家族账本登记为 `DEAD` 后，待再配对者与候选才可自然求偶、受孕。等待期间可喂苹果，避免饥饿挡住繁殖。
3. 受孕前执行 `/data get entity @e[tag=scn_widow,limit=1] YukkuriFamily.Partner`，仍应读到原伴侣 UUID；正常受孕后才写入新伴侣。死亡后的旧遗体仍保留原有伴侣副本。保存重载后继续观察，不应恢复旧的繁殖限制。
4. `REMOVED` 单独对照：清场重开，先执行 `/tp @e[tag=scn_old_partner,limit=1] ~20 ~ ~`，再执行 `/execute at @e[tag=scn_old_partner,limit=1] run yukkuri clear ~ ~ ~ ~ ~ ~`，只移除隔开的原伴侣。此路径不登记死亡，待再配对者仍不能与候选受孕。

普通配对回归使用 `adult_pairing`：保留原场景的双方回应、近距互见、喷雾中断和受孕完成表现。

### NPC 主人死亡（`custody_death`）

街道区生成一名 NPC 主人、带章宠物、库存、工厂输入、可先装篮的走失个体、已归玩家的个体和无已知主人身份的旧档对照。每次生成使用新的 NPC UUID，清场不会抹掉已经确认的死亡记录。

1. 主人活着时先用运输篮装起“可先装篮”（`scn_custody_lost`）。它的 Use 是 lost，装篮不会改归玩家；胸背带和铜章保存在同一权威快照中。先保存退出并 `-Resume`，验证单纯重载不释放归属。
2. 在场地执行 `/kill @e[tag=scn_custody_owner,limit=1]`，再读四个归属按钮。宠物、库存和工厂输入应无 Owner／Use／活动标记；工厂 `FactoryCycles:3` 历史仍在。玩家个体仍归玩家；UNKNOWN 对照仍保留原 UUID 与 `future_use`。宠物只信任死 NPC 的那份历史仍在，但不再提供饲主保护。可用普通捕获规则与喷雾检查无主者装篮。
3. 先尝试向狭窄位置或液体内放出篮中个体，应失败且保留 token，不产生胸背带掉落；再向空地放出，应只出现原个体并归还一次胸背带，铜章等级不变。普通篮子放出保持无主，随后可按原规则收养；反复存档重载不重复归还装备。冰柜可在主人死前存入这只篮子，再于死后取出放出，检查租约与 token 未被死亡处理绕过。
4. 卸载对照：重新生成后将主人与个体分开，只让主人所在区块卸载，不能释放名下个体。死亡延后加载对照则让个体区块先卸载，再杀主人，返回个体区块后应解除归属。另可把个体带到其他维度保持加载，再在原维度杀主人，观察跨维处理。
5. 原有 `exam` 场景继续用于中断、退出重进后的完整考试回滚；`factory_bag` 用于托盘乘客在工人死亡后卸下，帽船乘客不应被该清理踢下船。三者均沿现有试玩场入口，不另建地图。

### 观察台的按钮分类

观察台抬高四格、面向场地，从北到南每两格一排：

1. **场景**（一到数排）：生成本区的各个场景。每次先清场再生成，所以任何时候都可以按；有的区带额外按钮（家油屋的“模拟人类活动”“睡一晚”，动作片段的各类片段）。
2. **读数**（有则一排）：各场景自带的读数按钮，打开只读翻页报告，保留对应命令的完整输出，例如“读觅食数据”（`YukkuriForageView`）、“读搬家说明”（`YukkuriHabitatView`）、“读反应”（完整 `status raw`，含 `behavior.reaction`）、“店铺登记”（`human shop list`）、“读家油现状”（`household status`）。长字段和列表会换行跨页，不倾倒进聊天栏。
3. **控制**：回大厅、清空本场地（永不拒绝）、读状态（主角完整的 `yukkuri status ... raw` 快照报告）、到主角身边、观察标签开／关、旁观／创造、按钮自检。
4. **时间与天气**：清晨、正午、黄昏、夜晚；放晴、下雨、雷暴。
5. **倍速与推进**：倍速 1x／3x／5x／10x／20x（`yukkuri speed rate`）；推进 1 分钟／5 分钟／20 分钟（`yukkuri speed sprint`，快进后自动恢复原速）。

读数用 `yukkuri readout <命令>` 收集本次命令结果，只为执行玩家打开原版读书界面的报告，不广播给附近所有人、不改手持物品或背包，也不记录观察笔记的发现/成就。按钮沿其他玩家操作按钮的惯例，取8格内最近玩家执行（红石按钮不能准确辨认按压者）；命令仍定位原场景或场地中心，选择器范围不变。报告包含观察者、位置、游戏tick与原命令，是按按钮时的快照，再按可刷新。被包的本模组命令要写全，如 `yukkuri readout yukkuri status ... raw`。手工诊断的 `status`/`raw` 和其他短消息的 `relay` 保持原行为。传输分片有明确大小上限；超限会明确提示缩小目标范围，不显示缺字段的半份报告。

旧试玩世界的命令方块不会随Java更新自动改写，需按原启动入口的正常重建流程更新生成的数据包和按钮，并使用包含读数报告通道的CI运行包；沿用旧世界/旧数据包时仍是旧聊天输出。本改动不在运行中修补世界。

### 场景操作提示

- **捕食与逃避**：先看“看见捕食种”和街道的“鬼威惨”，确认未受击就退避；再看“被捕食种追猎”“捕食种远处觅食”，观察接近、咬击、吞咽及继续觅食。“捕食种宠物”的两只捕食者都处于饥饿状态，可比较银章受训者的克制和未学等待者的反应。
- **挡捕食种**：高、低意愿场景使用相同站位，差别在亲油的性格。重复生成比较护子选择；没有强制成功，护子后仍可能逃跑或受伤。
- **亲子距离**：先看同为 4 格间距的普通／大胆孩子，再看 14 格走散后的寻回；可用读数确认当前行为。独立场景继续检查已离巢子代不会被拉回。
- **失饰欺负**：用“读欺凌伤口”比较受害者血量与伤口；同一案多人只成功咬伤一次。重伤怪物对照应尽快停止欺凌，不再持续追推。
- **首餐后首便**：先不丢食物，观察未进食的新生儿只求食、不开始首便；再把苹果丢到亲油身边，看嚼糜、递喂、吞咽和首便的顺序。“读首餐与首便”可查看记录；存档重进后，已吃首餐或已完成首便的状态应保留。
- **腾空与小跳**：生成后等两秒，高抛与小跳同时开始；看高抛时的感叹和落地后的恢复。重复生成可重看。
- **家油血量**：先用四个读数按钮比较，再空手攻击各阶段家油。受击仍扣血、死亡仍留遗体；家油不显示伤口。
- **徽章与旁人**：生成后拿到的是该宠物的银章，右键给它佩戴，再看旁人的反应。
- **相亲**：等 2 秒完成窝位登记，持场景给出的绿宝石右键北侧店方饲养员。玩家宠物与店方种油均已登记银章，生产窝旁留有两格空窝。
- **魔理沙好斗、失饰的孩子**：前者直接发起普通相扑挑战，观察各对的不同回应；后者使用不饿的子油，避免赤油照护打断认亲。
- **吃草**：左侧有苹果和草，右侧仅有草；观察取食先后与咽下草时的嫌苦表现。草被啃后仍退回上一阶段并可再生。
- **脏污与伤痕**：后两只分别带轻、重撕裂并已包扎；等伤口关闭后看疤痕。重撕裂必留三级疤，轻撕裂有概率不留疤，可重新生成比较。

已删除的内容：领棉絮／领食屑按钮和 `nest_lint`、`food_scrap` 物品（家油改为由人类活动的痕迹驱动）、族长派工（采集／侦察／传话）与制造威胁按钮、“亲船上岸”场景、预置的独立施工工程与第二处洞口。

## 地形

各区只做场景需要的真实地形，`field/<区>/terrain` 能把整个区恢复成初始状态：

- **野外住所**：四座朝南的土丘（门洞是土丘南缘的单格露天缺口，缺口后是两格高、头顶两格土的洞腔）：家庭洞、独立用洞、石头围的小洞（洞腔是一条 5 格长的走廊，四壁是石头，挖不动）、空的大土洞（5×5 洞腔）；大洞在小洞东边 14 格。
- **流浪与觅食**：193×193 的草地，一座 9×9×4 的实心土丘（挖穴用）和一座 5×5 洞腔的土丘。家旁大部分植物已被采空，外围保留草场；吃草对照点另留一小片近处草。
- **群系聚落**：8 块 44×44 的地块（4×2），各自 `fillbiome` 并换地面（森林草地、平原草地、雪原雪块、针叶林草地、沼泽草地、热带草原草地、沙漠沙、恶地红沙），树木避开地块中心。
- **天气与捕食种**：一片空地，西侧一块 5×5 石顶（离地两格，四根墙柱），东侧很远处是没有顶的空地，视线开阔。
- **池塘与河湾**：椭圆池塘，西岸缓坡入水；岸格比水面格高一格，岸格与水格相邻，水深 1–4。
- **家油人类屋**：石砖地基、木地板、窗、屋顶、南门；有床、炉灶与烟熏炉、工作台、釜、餐桌、围栏里的一只羊（可剪毛），以及两处隐蔽墙角（两侧是墙，第三侧是书架或箱子桶，南面是入口）。屋子内部落在同一个 16×16×8 的活动格内（中心坐标对 16 取余为 8）。
- **商店／工厂**：空地和一条街；整座建筑由 `yukkuri human build` 放下（会自动清场、填平，商店在店主柜台后放一只银章爱丽丝）。商店占 41×33，工厂占 41×35。

## 家油的“模拟人类活动”需要开启生物生成

家油搬入的条件之一是游戏规则 `doMobSpawning` 为真，而试玩场平时关着它（免得凭空冒出野怪）。所以“模拟人类活动”和“睡一晚”按钮只在那一次调用里打开它，调用结束立刻关回去。

## 为什么速度按钮不用 `/tick`

原版 `/tick` 需要权限等级 3，而数据包函数和命令方块只有等级 2，所以按钮用 `yukkuri speed rate <20–400>` 和 `yukkuri speed sprint <ticks>`（等级 2）。旧版的 `util/speed_*` 函数因此根本没有加载。

## 清场永不拒绝

- “清空本场地”先取消本区未执行的延迟初始化、重试和动作片段，再执行 `yukkuri clear <方框>`、清掉带 `scn_prop` 标签的原版小道具（家油屋的羊）、重建地形，最后再清一次拆除旧方块时产生的掉落。`yukkuri clear` 强制移除方框内**本模组的全部实体**（油库里、遗骸、帽船、材料掉落、人类）和**所有掉落物**，并先取消被清走母油的胎次、移除落在框里的聚落群落与站点登记；后者把整块地面、方块（巢、坟、供给堆、聚落站点、水、洞穴）全部恢复为初始状态。
- 没有“真实过程进行中所以拒绝”这回事，也没有任何前置条件；场景按钮自己也是先清场再生成。
- 群系聚落区的清场是整区清（一次一个聚落，免得撞上人口上限）。

## 场景命令（`command/ScenarioCommands.java`）

数据包的 `scn/<id>` 函数在场景的锚点处用 `summon` 生成个体，再用下面这些命令设置**无法写进 NBT 的真实状态**。需要个体站稳才能成立的（认窝、受孕、放帽船）放在生成两秒后执行（`scn/<id>_late`）：同一刻刚召唤出来的个体还没落地，走得到不到的判断会失败。

| 命令 | 作用 |
| --- | --- |
| `yukkuri scenario wound <对象>` | 一处真实磕伤（走普通伤口路径） |
| `yukkuri scenario bond <甲> <乙>` | 双向好感，让它们互相认识、愿意亲近 |
| `yukkuri scenario mate <甲> <乙>` | 让两只成体结为真实伴侣 |
| `yukkuri scenario aftermath <受影响者> <来源>` | 设置兼容成体在镜头外受袭后的真实茎生与营养负担；不把来源设为伴侣或照护父，不由附近接近自动触发 |
| `yukkuri scenario kin <亲> <子> <新生?>` | 建立真实亲子；`true` 时幼体按新生儿保留首便与学动照护 |
| `yukkuri scenario home <对象> <方块>` | 认下窝；若给的是符合条件的朝南洞口，先把它登记为家 |
| `yukkuri scenario birth <母> <父> <natural\|caught\|missed>` | 真实受孕并推进到临产 |
| `yukkuri scenario boat <模式> <亲> <其他> <岸> <水>` | 亲油的帽船放在水面；模式 sail／shore／low／high／voyage／braid／self／birth／drop／shake／afloat |
| `yukkuri scenario shore <亲>` | 请亲油返岸收帽 |
| `yukkuri scenario independence <亲> <亚成> <洞口>` | 亲子放进同一个洞并让亚成准备独立（场景里改用 NBT 的 `YukkuriIndependence:{Force:1b}`，让一家自己认洞） |
| `yukkuri scenario eggs <母油> <父油>` | 在双亲认下的干净家油窝建立真实卵生胎次与卵位，保留健康、食物与繁殖条件 |
| `yukkuri clear <从> <到>` | 强制清场（见上） |
| `yukkuri observe on\|off` | 观察标签（生成场景时自动开启） |
| `yukkuri speed rate <20–400>`、`speed sprint <ticks>` | 倍速与推进 |
| `yukkuri relay <命令>` | 运行命令，回显发给附近玩家 |

亲子、父母、伴侣写进 NBT 时用固定的 UUID（`museum_dsl.uid`），所以家庭洞、外出觅食等场景在生成那一刻就是真实的一家。

## 校验与工具

本机不编译、不启动游戏窗口，校验都是纯 Python 加无界面服务器：

- `python scripts/check_museum_pack.py`：生成数据包，核对每条 `yukkuri ...` 命令（包括 `relay` 包着的）能在 Java 注册的命令树里走通，每个 `function` 引用都存在；每个场景有开始函数、本场地观察台上的按钮；**每个观察台和每个区的出口都有回大厅**；**大厅只有传送按钮和导览书，没有时间、天气、倍速、生成、清场**；每个观察台有清场、读状态、时间、天气、倍速、推进、观察、模式按钮；场景函数里没有 NoAI／无敌；没有已删除的物品和命令；每个洞穴的门洞格空着、有两格顶、缺口两侧有土；家油屋内部在一个活动格内；场地、观察台和出口互不重叠；池塘的岸与水对得上；每个按钮不被后来的方块覆盖；每块牌子放得下（按中日韩宽度算）。
- `python scripts/render_museum_map.py`：从生成器数据画俯视布局图（默认写到 `.local/previews/museum/map.png`）。
- `python scripts/build_museum_full.py --pack-only --output .local/experimental-map/<新目录>`：只生成数据包。无界面自查工具（`.local/harness/`）可以用 `--datapack` 装载这个数据包（里面的 `saves/MCyukkuri-Museum/datapacks/mcylab`），数据包的 `load` 函数会自己建图；要用 `generator-settings` 属性换成与试玩场一致的平坦层（基岩 1、石头 124、泥土 2、草方块 1，草顶 y=63），池塘才不会漏水。

游戏里随时可以按观察台的“按钮自检”，核对已加载区块里的按钮数。`MCYMUSEUM_BUILD_COMPLETE` 日志只表示建图结束，不代表玩法验收。

## 备注

- **运行模组过旧会大声报错**：进图时数据包先“探针”检查所需的命令（`scenario`、`clear`、`observe`、`speed`、`relay`、`settlement` 子命令）、方块、物品和实体。缺任何一个，屏幕出大标题“运行模组过旧”，聊天栏列出缺的是哪一类，并且**不再布置地图**。
- 世界由 `scripts/build_museum_full.py --install` 从数据包生成到 `.local/experimental-map/museum`，整体替换，不在旧存档上修补。`map-manifest.json` 记录生成器输入的哈希，启动器据此判断世界是否过期。
- 世界元数据（`level.dat`）取自 `.local/experimental-map/museum-seed/level.dat`，第一次从任一旧存档复制即可；脚本不复制区块、实体或玩家。
- 运行配置是 `.local/experimental-map/museum-runtime.json`：`runtime`（CI 运行产物）、`java`，可选 `python`（装有 nbtlib 的解释器）。
- 制作脚本：`build_museum_full.py`（装配、函数、数据包、世界）、`museum_fields.py`（区与地形）、`museum_scenarios.py`（场景）、`museum_dsl.py`（生成真实个体的词汇）、`museum_sites.py`（按钮、牌子、观察台）与 `museum_actions.py`（动作目录）；动作覆盖见 [动作目录](MOTION_MUSEUM_ACTIONS.md)。动态接触、长时间导航、多人干扰、重启恢复与帧耗时需要在可运行环境里实测。
