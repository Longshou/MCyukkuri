# 油库里试玩场

试玩场是唯一的试玩地图，也是唯一的测试入口：仓库里没有 GameTest 或别的测试地图，玩法效果都在这里亲自试。根目录 `启动动作博物馆.cmd`（文件名沿用，免得打断习惯）用远端 CI 的现成运行产物启动游戏，不执行本机编译。

旧的“展馆”是玻璃展台加脚本演出：演员被固定、不会动、重置还会因“真实过程进行中”被拒绝，大量失败都是这种形式带来的。现在改成**开放场地**：真实的草地、池塘、房屋、洞穴、雪原里，个体按普通规则自然运行，只在起点设置真实状态，想看就看、想快进就快进、想重来就清场。

试玩场的设施（大厅、观察台、按钮、清场与时间天气倍速）是项目原创的试玩设施，不出自原作；它展示的行为各有依据，见对应系统文档与 `wiki/`。

```text
启动动作博物馆.cmd            世界缺失或生成器改动后，先现场生成全新世界，再启动游戏
启动动作博物馆.cmd -Fresh     无论如何都生成全新世界（旧存档丢弃）
启动动作博物馆.cmd -Resume    保留已有世界，即使生成器已改
启动动作博物馆.cmd -Menu      进入 Minecraft 主菜单而不是直接进世界
```

## 一张图、一个入口、一份世界

- 世界由 `scripts/build_museum_full.py --install` 从数据包生成到 `.local/experimental-map/museum`，整体替换，不在旧存档上修补。`map-manifest.json` 记录生成器输入的哈希，启动器据此判断世界是否过期。
- 世界元数据（`level.dat`）取自 `.local/experimental-map/museum-seed/level.dat`，第一次从任一旧存档复制即可；脚本不复制区块、实体或玩家。
- 运行配置是 `.local/experimental-map/museum-runtime.json`：`runtime`（CI 运行产物）、`java`，可选 `python`（装有 nbtlib 的解释器）。`command/Scenario*.java`、`command/PlaygroundTools.java` 改动后，需要用含这些命令的 CI 构建更新运行产物。
- **运行模组过旧会大声报错**：进图时数据包先“探针”检查所需的命令（`scenario`、`clear`、`observe`、`settlement` 子命令）、方块、物品和实体。缺任何一个，屏幕出大标题“运行模组过旧”，聊天栏列出缺的是哪一类，并且**不再布置地图**，而不是让某个场地静默缺失。
- 世界是平坦世界：草地顶面 y=63，站立高度 y=64。进图后是创造模式，出生在大厅。

## 场地与场景

十块场地，各自远离，北侧都有一座抬高的观察台。每个场景生成真实个体（普通 AI，没有 NoAI、没有无敌、没有 `pm_actor`），**只设置真实的起始状态**；之后一切由普通玩法运行。

| 场地 | 内容 | 场景（观察台第一排按钮） |
| --- | --- | --- |
| 草地 | 平地、几棵树 | 回窝睡觉、相遇与蹭蹭、受伤与照料、厕所排便、饿了取食、嚼糜喂食、首便与舔舐、学起跳、陆地接生（接住／漏接） |
| 人类社会 | 十字土路与灯 | 野良应对、徽章与旁人、商店与人类、考场、相亲、捕食种、运输与动手 |
| 池塘与河湾 | 椭圆池塘，西岸缓坡入水（水深 1–4） | 备粮划桨、返岸收帽、带幼体返岸、两幼体、四幼体、第一次出航、落水·亲油救援、落水·自救、船上接生（接住／漏接） |
| 人类房屋 | 一座真实的小屋：石砖地基、木地板、窗、屋顶、南门 | 家油入住（无巢）、家油的巢与卵；另有领棉絮、领食屑按钮 |
| 山坡洞穴 | 一座土丘，两个朝南洞口相距八格 | 长大后独立、一路长大（赤油／子油／亚成／亲油） |
| 林地 | 森林群系，外圈有树 | 秋：采集储粮 |
| 雪原 | 雪原群系，雪块地面，云杉 | 冬：居巢（下雪加黄昏） |
| 聚落草地 | 森林群系，80×72 的大草地 | 小聚落、聚落与族长、流浪小队；另有派工（采集／侦察／传话）、制造威胁、尝试迁居按钮 |
| 季节 | 一块对齐 4×4 群系网格的地面 | 春／夏／秋／冬四个按钮：改群系并按 `#mcyukkuri:season_*` 报告判定 |
| 动作片段 | 九位固定演员（NoAI，只播动作） | 五类纯动作片段（身体与移动、日常生活、交流与情绪、宠物店与表情、运输与篮子）、全体合唱、全体体操 |

每个场景的看点、预计时间、没反应时怎么办，会在生成时发到聊天栏。要点：

- **接生**：四个场景都直接生成一对**临产**的双亲（陆地：有顶的小棚里放窝；船上：母油坐在自己的帽船里、岸上有戴帽的父油）。经 `FamilyData.conceive` 真实受孕、把胎次推进到临产；接住＝有戴帽的父油有时间摘帽，漏接＝强制无垫。陆地漏接等同摔伤，水上漏接等同落水（会溺水，除非亲油用辫子救起）。
- **嚼糜首便、学起跳**：赤油与亲油用 `scenario kin` 建立真实亲子；起跳场景把子油的儿童状态预设到“已爬行、尚未学会跳”。
- **长大与独立**：独立场景在两处洞口里放一个真实窝，把亲油和亚成油编进同一家庭群落，写好独立计划，之后亚成自己采叶、搬运、挖新巢（可能要十分钟以上，请用倍速）。
- **家油**：不预造巢、不预造卵。“家油入住”只放一对家油，把棉絮、食屑丢在附近看它们好奇、拾取、筑巢；“家油的巢与卵”预放空巢和少量库存。观察台有“领棉絮”“领食屑”按钮，按 Q 丢给它们。
- **帽船日常**：备粮划桨、返岸收帽、幼体载荷只设置“帽船已在水面、有桨、有两份口粮、幼体已上船”，之后航行、返岸、收帽由普通行为接管。
- **聚落、秋冬**：直接用现有的 `/yukkuri settlement spawn band|village|demo`，由聚落系统自己建站点并安置成员。

## 导航

| 位置 | 内容 |
| --- | --- |
| 大厅（出生点，面向北） | 站点墙：每行一个场地，最左的按钮去观察台，右边每个按钮对应一个场景（同样传送到该场地观察台）；南侧一排是全局按钮：全部清场、时间、天气、倍速、观察标签、旁观／创造、领取导览书、自检 |
| 每个场地北侧的观察台 | 抬高四格、面向场地，三排按钮，见下 |

观察台上的三排按钮：

1. 第一排：生成本场地的各个场景（会先清场再生成，所以任何时候都可以按）；某些场地另有额外按钮（派工、领物品、改群系、片段）。
2. 第二排：**清空本场地**、回大厅、到主角身边（传送到本场景的主角个体身边）、观察标签开／关、旁观模式、创造模式。
3. 第三排：时间（清晨／正午／黄昏／夜晚）、天气（放晴／下雨，寒冷群系下雨即下雪）、**倍速** 1x／3x／5x／10x（`/tick rate 20／60／100／200`）。

## 清场永不拒绝

- “清空本场地”＝ `yukkuri clear <方框>` ＋ 重建该场地地形。前者强制移除方框内**本模组的全部实体**（油库里、遗骸 `RemainsEntity`、帽船、材料掉落、人类）和**所有掉落物**（棉絮、食屑、污物、帽子……），并先取消被清走母油的胎次、移除落在框里的聚落群落与站点登记，免得家庭账本与人口预算还认为它们活着；后者把整块地面、方块（巢、坟、供给堆、聚落站点、水、洞穴）全部恢复为初始状态。
- 没有“真实过程进行中所以拒绝”这回事，也没有任何前置条件；场景按钮自己也是先清场再生成。
- “全部清场”（大厅）会先加载各场地再逐个清空。

## 观察辅助

- **观察标签**（`/yukkuri observe on|off`）：附近每只油库里头顶显示 `行为/动画 饥 困 年龄 孕 伤`（饥＝营养，困＝100−体力，便意高时多一项，幼体显示成长百分比，怀孕、伤、感染、乘船）。关闭时恢复原来的名字。
- **到主角身边**：每个场景把主要观察对象标记为 `scn_lead`，按钮把你传到它身边。
- **旁观／创造**：旁观可穿过实体和方块；点按钮前先切回创造。
- 每个场景的个体都带 `scn` 与 `scn_<名字>` 标签，便于用命令选择。

## 场景命令（`command/ScenarioCommands.java`）

数据包的 `scn/<id>` 函数在锚点处（默认是场地中心；池塘是岸边格，山坡是洞口格）用 `summon` 生成个体，再用下面这些命令设置**无法写进 NBT 的真实状态**：

| 命令 | 作用 |
| --- | --- |
| `yukkuri scenario wound <对象>` | 一处真实磕伤（走普通伤口路径） |
| `yukkuri scenario bond <甲> <乙>` | 双向好感，让它们互相认识、愿意亲近 |
| `yukkuri scenario kin <亲> <子> <新生?>` | 建立真实亲子；`true` 时幼体按新生儿保留首便与学动照护 |
| `yukkuri scenario home <对象> <方块>` | 认下窝（普通窝、野生住所或家油巢） |
| `yukkuri scenario birth <母> <父> <natural\|caught\|missed>` | 真实受孕并推进到临产 |
| `yukkuri scenario boat <模式> <亲> <其他> <岸> <水>` | 亲油的帽船放在水面，带桨、两份口粮，幼体上船或落水；模式 sail／shore／low／high／voyage／braid／self／birth |
| `yukkuri scenario shore <亲>` | 请亲油返岸收帽 |
| `yukkuri scenario independence <亲> <亚成> <洞口>` | 在洞口放真实窝、编入同一群落、写好独立计划 |
| `yukkuri clear <从> <到>` | 强制清场（见上） |
| `yukkuri observe on\|off` | 观察标签 |

这些命令都只设定起点，不控制之后的行为；失败时原因同时发给附近玩家（命令方块的输出没人看得见）。

## 校验与工具

本机不编译、不启动游戏，校验都是纯 Python：

- `python scripts/check_museum_pack.py`：生成数据包到临时目录，核对每条 `yukkuri ...` 命令都能在 Java 注册的命令树里走通，每个 `function` 引用都存在；每个场景都有开始函数、本场地观察台上的按钮和大厅按钮；每个观察台都有无条件的清场、回大厅、时间、天气、倍速、观察、模式按钮；场景函数里没有 NoAI／无敌／`pm_actor`；场地与观察台不重叠，池塘的岸与水对得上，山坡两个洞口空着且有顶；每个按钮不被后来的方块覆盖；每块牌子都放得下（按中日韩宽度算）。
- `python scripts/render_museum_map.py`：从生成器数据画俯视布局图（默认写到 `.local/previews/museum/map.png`）。
- `python scripts/build_museum_full.py --pack-only --output .local/experimental-map/<新目录>`：只生成数据包。

游戏里随时可以按大厅的“试玩场自检”，核对已加载区块里的按钮数。`MCYMUSEUM_BUILD_COMPLETE` 日志只表示建图结束，不代表玩法验收。

制作脚本：`build_museum_full.py`（装配、函数、数据包、世界）、`museum_fields.py`（场地与地形）、`museum_scenarios.py`（场景）、`museum_dsl.py`（生成真实个体的词汇）、`museum_sites.py`（按钮、牌子、观察台）与 `museum_actions.py`（动作目录）；动作覆盖见 [动作目录](MOTION_MUSEUM_ACTIONS.md)。动态接触、长时间导航、多人干扰、重启恢复与帧耗时需要在可运行环境里实测。
