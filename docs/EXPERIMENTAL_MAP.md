# 油库里试玩场

试玩场是唯一的试玩地图，也是唯一的测试入口：仓库里没有 GameTest 或别的测试地图，玩法效果都在这里亲自试。根目录 `启动动作博物馆.cmd`（文件名沿用，免得打断习惯）用远端 CI 的现成运行产物启动游戏，不执行本机编译。

试玩场是**开放场地**：真实的草地、土丘洞穴、池塘、屋子、街道、群系里，个体按普通规则自然运行，只在起点设置真实状态，想看就看、想快进就快进、想重来就清场。没有玻璃罩，没有被固定的演员（唯一例外是“动作片段”区的九位只播动作的演员）。

试玩场的设施（大厅、观察台、按钮、清场与时间天气倍速）是项目原创的试玩设施，不出自原作；它展示的行为各有依据，见对应系统文档与 `wiki/`。

```text
启动动作博物馆.cmd            世界缺失或生成器改动后，先现场生成全新世界，再启动游戏
启动动作博物馆.cmd -Fresh     无论如何都生成全新世界（旧存档丢弃）
启动动作博物馆.cmd -Resume    保留已有世界，即使生成器已改
启动动作博物馆.cmd -Menu      进入 Minecraft 主菜单而不是直接进世界
```

本页只说明通用操作、分区、清场和诊断入口。当前要复测什么、看哪些变化，统一见[待试玩清单](TODO.md#待试玩清单)；规则与专用操作见[系统专题](README.md#游戏系统)。

## 展示规划

### 导航原则

- **大厅只管“去哪儿”**：站点墙按主题分组，每个按钮传送到一个区的观察台，旁边的牌子列出这个区的场景。大厅**没有**时间、天气、生成、清场、倍速、读状态。只有“领取导览书”这个信息按钮。
- **细节都在区里**：生成场景、清场、时间、天气、倍速与推进，只在各区的观察台上。试玩不设读数按钮；排查以服务端日志为主，必要时手工调用诊断命令。
- **随处可回**：每个观察台有“回大厅”；每个区南边（区外）有一对“回观察台／回大厅”按钮；生成场景把你带到场景旁，聊天栏里的 `[回观察台]` `[回大厅]` 可点击；`/function mcylab:home` 也行。
- 世界是平坦世界：草地顶面 y=63，站立高度 y=64。进图后是创造模式，出生在大厅，观察标签默认开。
- 普通场景从北侧观察，个体初始面朝北；需要对视、水岸动作或定向受击的场景保留各自朝向，商店与工厂从入口一侧观察。个体随后由普通 AI 自由转向。

场景 ID、按钮标题、初态和可用读数以 `scripts/museum_scenarios.py` 与游戏内导览为准，不再手工维护场景总数、完整列表或另一份试玩状态。

| 主题 | 分区 |

| 野生与住所 | 野外住所、流浪与觅食 |
| 群系聚落 | 群系聚落 |
| 家庭与成长 | 日常草地、出生与成长 |
| 天气、伤病与头饰 | 天气与捕食种、伤病与遗体、头饰与认知 |
| 水生魔理沙 | 池塘与河湾 |

专用操作：[丧偶再配对](ADULT_AGITATION.md#丧偶再配对widow_repair)、[NPC 主人死亡](HUMAN_WORLD.md#npc-主人死亡custody_death)、[治疗与遗体](INJURIES_AND_REMAINS.md#治疗流程与试玩陆-49)、[水生帽船](AQUATIC_MARISA_IMPLEMENTATION.md#试玩场景)。

### 观察台的按钮分类

观察台抬高四格，从南侧落点进入时面向按钮；按钮横纵间距均为三格，每排最多九个。各区常用按钮位置一致，场景数量不会挤走它们。从入口往北依次为：

1. **青色常用排**：回大厅、到主角身边、恢复正常速度（1x）、观察标签开／关、旁观／创造；最右侧是红色“清空本场地”，中间空一列，避免挨着模式切换。清场仍无条件执行。
2. **绿色倍速排**：3x／5x／10x／20x；推进 1／5／20 分钟，快进后恢复原速。
3. **黄色环境排**：清晨、正午、黄昏、夜晚；放晴、下雨、雷暴。
4. **橙色场景排**（一到数排）：每次先清场再生成；家油屋的“模拟人类活动”“睡一晚”和动作片段的额外操作跟在场景后面。

所有场景专用读数、“读状态”和“按钮自检”的实体按钮均已移除。通用操作的试玩结论见[待办](TODO.md#待试玩清单)。池塘观察台随按钮减少而缩短四格。

服务端业务日志继续默认记录，用户提供场景和大概时间即可由 AI 排查，不需要先按读数。需要瞬时状态时仍可手工执行 `/yukkuri status` 或 `/function mcylab:read/<场景id>_<序号>`；主角入口为 `/function mcylab:read/<场地id>/lead`，场景序号按 `museum_scenarios.py` 中 `reads` 从 0 起。原诊断函数保留位置锚点及 `yukkuri readout <命令>` 报告通道，执行玩家收到完整只读报告，报告日志只在实际调用时生成；不会自动轮询或补造历史快照。专题和待办里的“读数”均指排查时的命令查询，不要求玩家点按钮。

旧世界的命令方块不会随源码自动改写；用原启动入口正常重建世界才会出现新排布，`-Resume` 会保留旧布局。不在运行中修改世界。

场景完成标准与当前失败项见[待试玩清单](TODO.md#待试玩清单)；具体行为和读数含义见各专题文档。

## 地形

各区只做场景需要的真实地形，`field/<区>/terrain` 能把整个区恢复成初始状态：草皮下两层泥土（y=61–62，聚落会在这里挖水塘和黏土坑）、地面、地上直到 y=82 的空气和地物；场景会改群系的区（群系聚落、暖桌地块）在清场时把群系也改回来。场地矩形之外、清场方框边缘的 4 格不重建方块。

- **野外住所**：四座朝南的土丘（门洞是土丘南缘的单格露天缺口，缺口后是两格高、头顶两格土的洞腔）：家庭洞、独立用洞、石头围的小洞（洞腔是一条 5 格长的走廊，四壁是石头，挖不动）、空的大土洞（5×5 洞腔）；大洞在小洞东边 14 格。
- **流浪与觅食**：193×145 的草地（南北不再加深：站在观察台按“清空本场地”时，渲染距离 10 要能加载到场地最南边），一座 9×9×4 的实心土丘（挖穴用）和一座 5×5 洞腔的土丘。家旁大部分植物已被采空，外围保留草场；吃草对照点另留一小片近处草。
- **群系聚落**：8 块 44×44 的地块（4×2），各自 `fillbiome` 并换地面（森林草地、平原草地、雪原雪块、针叶林草地、沼泽草地、热带草原草地、沙漠沙、恶地红沙），树木避开地块中心；清场恢复地面、树和群系。村落（含草场环）半径 29 格，会伸出 44 格地块：平原聚落和四个族规场景先把平原村落整片（±30 格）铺成平原草地并设为平原群系，迁徙场景对东侧 64 格外的空聚落做同样处理（否则新址压在雪原雪块、沙漠沙和恶地红沙上）。下次清场再把各地块改回来。
- **天气与捕食种**：一片空地，西侧一块 5×5 石顶（离地两格，四根墙柱），东侧很远处是没有顶的空地，视线开阔。
- **池塘与河湾**：椭圆池塘，西岸缓坡入水；岸格比水面格高一格，岸格与水格相邻，水深 1–4。
- **家油人类屋**：石砖地基、木地板、窗、屋顶、南门；有床、炉灶与烟熏炉、工作台、釜、餐桌、围栏里的一只羊（可剪毛），以及两处隐蔽墙角（两侧是墙，第三侧是书架或箱子桶，南面是入口）。屋子内部落在同一个 16×16×8 的活动格内（中心坐标对 16 取余为 8）。
- **商店／工厂**：空地和一条街；整座建筑由 `yukkuri human build` 放下（会自动清场、填平，商店在店主柜台后放一只银章爱丽丝）。商店占 41×33，工厂占 41×35。

## 家油的“模拟人类活动”需要开启生物生成

家油搬入的条件之一是游戏规则 `doMobSpawning` 为真，而试玩场平时关着它（免得凭空冒出野怪）。所以“模拟人类活动”和“睡一晚”按钮只在那一次调用里打开它，调用结束立刻关回去。

## 为什么速度按钮不用 `/tick`

原版 `/tick` 需要权限等级 3，而数据包函数和命令方块只有等级 2，所以按钮用 `yukkuri speed rate <20–400>` 和 `yukkuri speed sprint <ticks>`（等级 2）。旧版的 `util/speed_*` 函数因此根本没有加载。

## 清场永不拒绝，清完回到同一初始状态

“清空本场地”之后再按场景按钮，实体、世界账本和地形都回到同一初始状态（[AGENTS.md](../AGENTS.md#修复与试玩场) 的可重复要求）。场景按钮自己就是“先清场再生成”。

1. 取消本区未执行的延迟初始化（`scn/<id>_late`）、重试链、返岸呼叫和动作片段。
2. `yukkuri clear <方框> fld_<区>`：强制移除方框内**本模组的全部实体**（油库里、遗骸、帽船、材料掉落、人类）和**所有掉落物**，再加上带本区标记 `fld_<区>`、已走出方框的已加载实体。标记由 `util/tag_fields` 每 2 秒发给站在各区方框里的实体，所以独立离巢、逃跑、被追出场地的个体也会被清掉。移除不是死亡：胎次照普通移除取消，聚落群落和站点按中心落在框里移除。随后各账本忘掉本区留下的记录：
   - 家族账本：被移除个体、最后登记位置在框里的个体（包括上一轮死掉的），以及她们的胎次和胎儿；
   - 认知账本、好感关系、待处理的饰品没收，野生事件和住所宣言（结束并删除，去掉成员冷却和框内区域冷却）；
   - 框内的再生草排程、待掉落的空茎、家油活动格与喷雾、店铺登记、工厂与店铺的配送记录（连同在途的托管令牌）。
3. 清掉带 `scn_prop` 标签的原版小道具（家油屋的羊），重建地形，最后再清一次拆除旧方块时产生的掉落。

没有“真实过程进行中所以拒绝”这回事，也没有任何前置条件。方框有一部分没加载时，`yukkuri clear` 跳过那部分，不整条失败；地形 `fill` 需要区块已加载，所以要在观察台或场地附近按清场。群系聚落区的清场是整区清（一次一个聚落，免得撞上人口上限）。

不带标记的 `yukkuri clear <从> <到>` 只移除实体和聚落登记，账本照常记 `REMOVED`；丧偶再配对的 `REMOVED` 对照用的就是它。

**故意不复位的**：收纳篮或冰柜里的个体（托管令牌还在，固定 UUID 的场景个体装篮后不放回，重开时这只会被拒绝生成）；已确认死亡的 NPC 主人（`custody_death` 每次用新 UUID，不受影响）；玩家自己的记录（弃养记录、徽章特权、每个店主的货架与每日交易）；倍速；场地矩形外的方块。

**本身就随机的**：`yukkuri settlement spawn` 与 `site vacant` 每次用新随机种子规划布局和成员，群系聚落和族规场景每次的村落不同；概率行为（护子、献身、翻船选择）每次重抽。用固定 UUID 的场景（`museum_dsl.uid`）亲缘、胎数种子都一样；没写 UUID 的个体每次是新 UUID。

`/function mcylab:scn/<id>` 只生成不清场，可在任意平地试用，但不保证初始状态；要重复同一初始状态请按观察台按钮。`yukkuri settlement spawn`／`site vacant` 在同一广场列上遇到旧站点记录时，空记录换成新建的规划，有群落住着则拒绝。

## 场景命令（`command/ScenarioCommands.java`）

数据包的 `scn/<id>` 函数在场景的锚点处用 `summon` 生成个体，再用下面这些命令设置**无法写进 NBT 的真实状态**。需要个体站稳才能成立的（认窝、受孕、放帽船）放在生成两秒后执行（`scn/<id>_late`）：同一刻刚召唤出来的个体还没落地，走得到不到的判断会失败。

| 命令 | 作用 |
| --- | --- |
| `yukkuri scenario wound <对象>` | 一处真实磕伤（走普通伤口路径） |
| `yukkuri scenario bond <甲> <乙>` | 双向好感，让它们互相认识、愿意亲近 |
| `yukkuri scenario mate <甲> <乙>` | 让两只成体结为真实伴侣 |
| `yukkuri scenario aftermath <受影响者> <来源>` | 设置兼容成体在镜头外受袭后的真实茎生与营养负担；不把来源设为伴侣或照护父，不由附近接近自动触发 |
| `yukkuri scenario kin <亲> <子> <新生?>` | 建立真实亲子；`true` 时幼体按新生儿保留首便与学动照护 |
| `yukkuri scenario home <对象> <方块>` | 认下窝；若给的是符合条件的朝南洞口，先把它登记为家 |
| `yukkuri scenario birth <母> <父> <natural\|caught\|missed>` | 真实受孕并推进到临产 |
| `yukkuri scenario boat <模式> <亲> <其他> <岸> <水>` | 亲油的帽船放在水面；水格在干岸外 2–8 格且低一格；模式 sail／shore／high／voyage／braid／self／birth／drop／shake／afloat 等 |
| `yukkuri scenario shore <亲>` | 请亲油返岸收帽 |
| `yukkuri scenario independence <亲> <亚成> <洞口>` | 亲子放进同一个洞并让亚成准备独立（场景里改用 NBT 的 `YukkuriIndependence:{Force:1b}`，让一家自己认洞） |
| `yukkuri scenario eggs <母油> <父油>` | 在双亲认下的干净家油窝建立真实卵生胎次与卵位，保留健康、食物与繁殖条件 |
| `yukkuri clear <从> <到> [场地标记]` | 强制清场；带 `fld_<区>` 时连同走出方框的标记实体和账本记录一起清（见上） |
| `yukkuri observe on\|off` | 观察标签（生成场景时自动开启） |
| `yukkuri speed rate <20–400>`、`speed sprint <ticks>` | 倍速与推进 |
| `yukkuri relay <命令>` | 运行命令，回显发给附近玩家 |

亲子、父母、伴侣写进 NBT 时用固定的 UUID（`museum_dsl.uid`），所以家庭洞、外出觅食等场景在生成那一刻就是真实的一家。同一 UUID 每轮重用：清场让家族、认知、好感等账本忘掉这些记录，上一轮死掉或走散的个体不会挡住下一轮生成。

## 静态检查与制作工具

以下工具只检查或生成数据包与布局，不证明玩法通过；玩法仍由用户在本试玩场确认。

- `python scripts/check_museum_pack.py`：按源码核对命令树、函数引用、场景与按钮覆盖、观察台布局、地形与洞穴条件、文字容量，以及已删除的物品／命令和 NoAI／无敌限制。
- `python scripts/render_museum_map.py`：从生成器数据画俯视布局图，默认写到 `.local/previews/museum/map.png`。
- `python scripts/build_museum_full.py --pack-only --output .local/experimental-map/<新目录>`：只生成数据包，不编译、不启动游戏。

维护时可手工执行 `/function mcylab:selfcheck`，核对已加载区块里的按钮数。`MCYMUSEUM_BUILD_COMPLETE` 只表示建图结束；动态接触、连续导航、重启恢复、多人干扰与帧耗时仍需实际试玩。日志和运行版本的定位方法见[开发指南](DEVELOPMENT.md#试玩日志与事后排查)。

## 备注

- **运行模组过旧会大声报错**：进图时数据包先“探针”检查所需的命令（`scenario`、`clear`、`observe`、`speed`、`relay`、`settlement` 子命令）、方块、物品和实体。缺任何一个，屏幕出大标题“运行模组过旧”，聊天栏列出缺的是哪一类，并且**不再布置地图**。
- 世界由 `scripts/build_museum_full.py --install` 从数据包生成到 `.local/experimental-map/museum`，整体替换，不在旧存档上修补。`map-manifest.json` 记录生成器输入的哈希，启动器据此判断世界是否过期。
- 世界元数据（`level.dat`）取自 `.local/experimental-map/museum-seed/level.dat`，第一次从任一旧存档复制即可；脚本不复制区块、实体或玩家。
- 在实际游玩的机器用 `scripts/update_museum_runtime.py --run <run-id>` 更新同一提交的成功 CI 运行包；旧包保留，哈希核对和清单读回成功后仍从原 `.cmd` 启动，见[开发指南](DEVELOPMENT.md#试玩与检查)。
- 运行配置是 `.local/experimental-map/museum-runtime.json`：`runtime`（CI 运行产物）、`java`，可选 `python`（装有 nbtlib 的解释器）。
- 制作脚本：`build_museum_full.py`（装配、函数、数据包、世界）、`museum_fields.py`（区与地形）、`museum_scenarios.py`（场景）、`museum_dsl.py`（生成真实个体的词汇）、`museum_sites.py`（按钮、牌子、观察台）与 `museum_actions.py`（动作目录）；动作覆盖见 [动作目录](MOTION_MUSEUM_ACTIONS.md)。动态接触、长时间导航、多人干扰、重启恢复与帧耗时需要在可运行环境里实测。
