## 代码首轮结论：须修复后复审

审查入口为 `src/main/java/io/github/longshou/mcyukkuri/` 下的 `family/HatCarry.java`、`entity/YukkuriEntity.java`、`interaction/OperationLife.java`、`item/AccessoryItem.java`、`client/YukkuriModel.java` 与 `client/YukkuriRenderer.java`。首轮源码已冻结到 `.local/marisa-hat-review/code-round1/`，完整 SHA-256 登记为同目录 `hashes.json`。

`HatCarry.java` 的首轮哈希为 `de075842c5d5a962fc06261a44e46169f22136de36d9c0a1966d4b6b634f017e`，`YukkuriEntity.java` 为 `bcdabb8759ce4823c858fbe1ba70930b8b39e9b003bf4fc2124bd8781ed103df`。下述结论只适用首轮源码。

### 必须修复

1. **P1：帽侧乘客座位不检查世界碰撞。** `canSeat` 只判断两模型的静态尺寸，`pickUp` 随后直接 `startRiding`；`positionRider` 用 `move.accept` 放到座位。当前普通帽座位距身体中心约 0.523 格，可在身体尚未碰墙时进入邻接方块。应在拾取前检查子油目标世界包围盒，并在移动中处理新出现的阻挡。测试不能仅检查乘客中心等于 `seatWorld`。
2. **P1：危险时找不到放下位置会继续悬空。** `tick` 在帽子丢失、火烧、水中等状态下调用 `putDown`，但其返回失败时仍保留乘客关系。`landing` 找不到周边有坚实顶面的格子便返回空，因此无落脚点时幼油继续留在没有帽子的旧座位。需定义保持帽子或停止携带的可靠兜底，不得丢弃或复制幼油。测试应覆盖无安全放下点。
3. **P2：旧剪刀入口绕过新增取帽流程。** `YukkuriEntity.mobInteract` 的 Shift+剪刀仍直接调用 `life.takeAccessory`，既不先放下幼油，也不触发 `HAT_REMOVE`。菜单入口已做两项处理。应统一两个入口，避免用户从旧入口摘帽时丢失动画、留下不受帽支撑的乘客。
4. **P2：只变换座位中心，不能保证幼油脚底与帽面一致。** `seatWorld` 使用父体帽骨骼矩阵，`positionRider` 只更新位置；子油渲染仍使用自己的朝向和直立姿态。父体转向或侧弯时，实际足印不会应用同一个帽矩阵，`fits` 的同朝向静态 AABB 条件因此不再等价于实际支承。父体 `dailyMotion` 的转动、平移及睡眠缩放也未进入服务端座位计算。应让乘客渲染共享帽子最终矩阵，或对携带状态限制并统一父子动作，使验证条件真实成立。

### 已确认的结构与仍需验证的范围

- 五个资源 ID 为 `marisa`、`marisa_sparse`、`marisa_face`、`marisa_bean`、`house_marisa`。每个 `hat_follow` 后代影响 21 个帽沿、帽体、帽蝴蝶结部件，未影响头发。新增 `hatMotion` 对该根骨骼单独平移，从结构上支持独立抬帽。
- `OperationLife` 的菜单取帽与剪坏帽已补齐 `SourceModel`，第一轮造型审查指出的资源字段差异在这些入口已修订。归还仍先验证 Owner/Token 并消费唯一物品，没有发现仅由这段逻辑导致的重复物品。
- 幼油使用真实 `startRiding` 关系，未创建第二个渲染替身；父子均设为持久实体。已有测试源码覆盖原生 Passenger NBT 递归读取，但本审查没有执行它，不能把静态读取称为保存/重载实际通过。
- `HatCarry.fits` 使用真实脚底边界、帽座支承范围及可见部件包围盒，适合做静态预筛选；它不自动证明旋转后、运动中、碰墙或受伤改变身体时仍有正确支承。
- 当前源登记实际选择右侧帽檐，坐标 X 约 8.373、Z 0，不是首轮讨论中的前帽檐。应按真实交付姿势说明，并查看父子合成几何预览。

建议引擎验证覆盖：五种帽摘下/归还、家油独立帽根、Shift+剪刀与菜单行为一致、靠墙拾取拒绝、移动撞墙处理、无安全落点的去帽、保存后重新载入的唯一真实乘客，以及父体转向和侧弯时幼油脚底与帽面接触。未执行项目须继续明确标注。
