# 方块帽船

当前魔理沙帽的交互几何候选。`recipe.json` 是造型配方；`build.py` 从现行制作源和运行网格生成可编辑长方体模型 `worn-hat.bbmodel`、`boat-hat.bbmodel`，以及共用接触尺寸 `geometry.json`。不写游戏运行资源。

佩戴和翻转共用同一套帽檐、帽冠与贴图。保留上段帽冠 55% 高度的折尖、白带、蝴蝶结、外沿平面轮廓及 1.5 倍水生比例，扩宽下段帽冠形成较宽的帽腔。

| 几何 | 现版 | 候选 | 用途 |
| --- | --- | --- | --- |
| 最深平底 | 5.0251 × 7.22 | 7.00 × 8.15 | 减少幼体及自戴帽的侧壁限制；完整容纳粮堆保守占位边界 |
| 前踏台纵深 | 1.66 | 2.26 | 容纳 0.20 初航子油完整身体支撑范围，其自戴帽与后方母油分开 |
| 帽檐接触面的最大高度偏差 | 0.1749 | 0 | 真实几何与统一支撑平面对齐，避免轻微悬浮／穿入 |
| 深货底距帽口 | 7.029 | 7.029 | 保留满粮堆低于母油身体的上下间隔 |

数值使用未压缩帽单位；水上竖向乘 0.75，转世界坐标再乘 `hullScale / 16`。粮堆形状、缩放和容量不变，把中心 X 从 -0.55 移到 -0.0193、Z 从 -0.10 移到 0.50；仍坐在原深货底，最大档与深底前缘的平面净距为 0.3171。深底前侧保留 0.55 宽的中间台阶，不把两级落差合并成一面直壁。较宽的平底不增加 12 份容量。

未孕成体宽约 8.53 帽单位，仍不能进入宽 7.00 的深底。几何改稿不代表母油可以自由走舱底，也不解决朝向同步、握桨角度、船岸碰撞或服务端阶段交接问题。0.20 子油检查只覆盖空前踏台和正常驾驶位母油；其他乘员、伤病姿态和动态过程仍由实际占位规则决定。

在仓库根目录使用带 NumPy、Pillow 的 Python 运行：

```sh
.local/venv/bin/python standards/yukkuri-library/drafts/block-hat-boat/build.py
```

生成时核对模型支撑面与导出尺寸、三档粮堆网格及保守包络、粮堆与母油完整碰撞体的间隔、0.20 子油支撑和自戴帽净空。此为静态资源检查，不是游戏动作验收。`.local/previews/block-hat-boat/` 保存当前模型图、同尺度对照与接触尺寸图；工作树可通过 `MCY_LOCAL` 指向主检出的 `.local`。

采用时须把配方同步到正式组件和导出链，重建帽船、接触尺寸、粮堆及陆地放帽／接生派生数据，不能只替换模型。试玩沿用 `cargo_load`、`shore_babies`、`self_rescue`、`hat_swap`，观察实际乘员、容量、托举／登离船阶段与拒绝原因；候选未接入前，这些场景仍使用现版模型。
