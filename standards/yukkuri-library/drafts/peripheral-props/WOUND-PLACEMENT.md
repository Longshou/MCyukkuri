# 全身伤口与多处挂接

2026-09-13，R3.1。用户指出伤口不应固定在脸颊，本批补齐不同部位的定位、多处独立伤情和对应漏馅。当前交付是素材编辑与动作预览，尚未接入 Minecraft 受击事件。

## 使用入口

打开[统一预览](previews/current/index.html)，在“伤情与效果”中选择“全身伤口 · 多处挂接”。原有八个伤情示例也提供“调整伤口位置／多处共存”按钮。

- 选择正面、右侧、背面、左侧、顶部或底部，再用两个位置滑块调整部位内的落点；也可点击“皮面定位”后直接点模型。点击会反查当前姿态下的真实皮面，不以屏幕坐标保存伤口。
- “新增伤口”保留已有记录，最多编辑八处。每处独立保存位置、擦伤／裂口／凹陷／焦痕类型、0–3 级程度和范围；移除当前或清除全部不会留下可见伤痕。
- 裂口各自设置 0–12 份漏馅和渗出／拉丝／飞散／落地阶段。零份保留裂口、去掉释放的馅料；伤情零级隐藏这处伤口及其漏馅。
- 默认保留头发和饰物。被头发或帽子盖住的伤口仍在皮面上；可切换“仅看皮面”核对。仰视按钮用于底部检查，不会自动抬起或改变角色。
- “检查变形与动作”可切换受压、干瘪，以及选定角色的侧弯、伸展、走动、按压动作。伤口与出馅口跟随皮面，体型同时作用于角色和漏出的馅料。

旧八个示例用于比较分级外观，保留原固定示例位置。全身编辑器才是本次位置与多处共存的制作入口；油霉的全身扩散和身体整体干瘪仍由各自示例表达，不把它们当作单个切口。

## 制作源、配方与导出

[wound-surface.js](wound-surface.js)是皮面定位、局部凹入、伤痕和漏馅的共同制作源。[wound-editor.js](wound-editor.js)提供编辑入口；[export-wound-scenes.cjs](export-wound-scenes.cjs)调用同一几何函数导出场景，浏览器没有另画一套近似图形。

[wound-source.json](wound-source.json)由主构建生成，包含选定角色的原始几何、骨骼、权重、动作及本批材质定位；来源文件指纹见 [body-effects-recipe.json](body-effects-recipe.json)。没有修改这些角色的正式源或运行快照。

皮面取当前身体方盒并集的外表面，去掉内部切片端面；伤口贴到实际外表面，边界外的片段裁掉。相邻皮面使用从原骨骼权重插值得到的共享绑定，避免去掉内面后，分层身体在动作中露出接缝。五官贴面参与同一局部凹入与皮面绑定，头发和饰物继续使用原有独立部件。

配方按伤口 ID 保存 `kind`、`side`、`u`、`v`、`severity`、`size`、`quantity`、`mode`；全局保存角色、体型、身体变形、动作与时间。部位坐标根据实际身体边界计算，可连续移动；导出还记录求得的部件名、静态位置、当前姿态位置和骨骼权重。

`wound-scenes/` 包含两角色各六个部位及一个多处组合，共 14 份配套示例。每份包含 `.bbmodel`、`.mesh.json`、`texture.png` 和 `recipe.json`，指纹登记在 [导出记录](reports/current/exports.json)的 `wound_scenes`。

详情页“下载当前组合与姿态模型”生成与当前画面相同的自由网格；“下载当前伤口配方”保存可再次导入的编辑参数。Blockbench 模型保存当前静态姿态，并在元数据中携带配方，没有提供原生 Blockbench 动画时间轴。需要修改后复现时，以配方和上述制作源为准。

## 检查与接入边界

在项目根目录运行 `python standards/yukkuri-library/drafts/peripheral-props/verify-wound-exports.py` 可核对当前源、选定角色、全部配套导出、浏览器证据和文档链接。

[几何检查](reports/current/wound-static.json)核对两角色六方向的正反定位、共享顶点动作接缝、独立伤口编辑、零份清除、体型缩放及飞散落地。

[浏览器检查](reports/current/wound-browser.json)从实际 HTML 入口操作，生成各部位带遮挡／皮面截图、三处组合、四种动作起中末帧及受压／干瘪截图，并检查点击定位、增删、配方恢复、下载模型与当前画面的顶点和 UV 一致、动作播放结束及移动布局。实际目视结果与指纹见[视觉记录](reports/current/wound-visual-review.md)；当前图位于 [wound-placement/](previews/current/wound-placement/)。

本批没有把游戏中的命中点写入存档，也没有增加游戏伤情字段或替换正在使用的伤口渲染。后续适配应将实际命中位置转换为实体局部皮面记录，持久化各处伤口身份和伤情，并驱动同一位置的漏馅。其他动作、任意动画混合、碰撞形状及游戏中的治疗恢复仍需接入验收。飞散是在所选姿态下演示该处的释放轨迹，不是完整的游戏粒子历史模拟。

本轮未执行 Minecraft 运行或 Blockbench 应用导入验收；技术检查不代表用户已经确认这些造型。
