# 伤口生成与中枢外露

制作源见 [README](README.md)，伤病规则见[受伤与遗体](../../../../docs/INJURIES_AND_REMAINS.md)，接入与试玩状态只在[待办](../../../../docs/TODO.md)登记。

伤缘使用无肤色底的透明贴图，面皮断面只放在真实缺损以内；凹陷共同细分皮面、头发和五官并保留 UV，避免稀疏眼睛网格下沉后被皮面误盖。伤口外器官不被肤色边框覆盖。

## 通用分层表现

伤口位于头发覆盖区时显示在对应发面上。以下形状、分层与投影方式均为项目设计，复用同一权威伤口及既有制作源，不另造一套伤害系统；运行素材选择与接口见[发面制作源](hair-wounds/README.md#文件和接口)。

头发按伤型响应，不能受伤就统一消失。砸击时头发与体表一起凹陷并保留；裂伤只在实际开口内截断毛束，断掉部分直接消失，不制作散落头发。[发面制作源](hair-wounds/README.md)保存相应纹样、共同凹陷顶点及断发创腔样例，游戏验收仍见待办。

家油按用户最新限定仅适配足部与全身烧伤，受烧直接选择三级外观，实际扣血与存活独立结算，不提供其他伤口或露核美术；其余现有品种与形态均按各自模型登记适配。全身烧伤同时使蝴蝶结、发带和布帽逐级褐变、熏黑、焦枯；螺壳和彩晶采用烟熏，独立附件保留自身尺寸，足部烧伤不影响头饰。

伤口必须先有确定伤因，再确定外形。机械伤的形态、三级材质、足部／全身烧伤范围、横向干瘦及露核条件统一见[制作源伤因与伤型](hair-wounds/README.md#来源与伤因)。`WoundShape` 记录同一处已发生损伤的机理，`WoundKind` 继续承担治疗与漏馅业务类别；两者不复制伤势。制作源不新增破损中枢或取出空腔的美术，运行仍保留真实损坏／取出状态。精细贯穿的未实现边界见下文。

一处伤只有一个身体锚点、一份严重度和一个稳定 ID。显示分为覆盖层（头发）、面皮、普通馅、唯一中央中枢；伤口在哪一侧，所有层就对应那一侧。大小表示表面影响范围，深度表示损伤到哪一层，两者不能互相代替：大擦伤不露核，细长裂口不自动变成大洞。

| 伤型 | 裸露皮面 | 头发覆盖部位 | 内部表现 |
| --- | --- | --- | --- |
| 擦伤 | 顺受力方向的断续浅痕、薄破皮 | 同一位置的浅色擦痕与局部毛束磨损，保留发色 | 不见馅，不挖创腔 |
| 闭合凹伤 | 局部压陷、低对比暗沉 | 发面随受伤区域压陷，毛束局部压扁，轮廓和轻微明暗共同辨认 | 不凭凹陷画出馅料 |
| 普通开放伤 | 细长或不规则开口、浅色面皮翻边 | 相交毛束局部裂开，外缘保留发色和断发轮廓，下面接破皮 | 哑光普通馅，凹入皮面，不画核心 |
| 足部烧伤 | 足底及足缘连续褐变／焦化 | 上部头发保留 | 热损本身不挖创腔 |
| 全身烧伤 | 全身连续热损，无孤立焦斑 | 整体受热变色，与全身范围一致 | 不由焦黑或等级自动露核 |
| 露核重伤 | 大缺损、面皮厚度和明显向内的腔壁 | 外缘断发，覆盖开口的头发、面皮和相交五官共同让出通道 | 普通馅腔壁通向体内唯一中枢，核心保留真实深度 |
| 闭合旧疤 | 原位浅米色细痕、极浅凹边 | 对应发面用窄淡痕和毛束分缝表达，不能仍画开放裂口 | 不漏馅、不留活动创腔 |

形状随类型区分：擦伤断续、裂伤细长且两端收尖、撕裂边缘不规则、压伤圆钝、焦痕边缘碎裂。保留既有低饱和面皮和豆沙材质，不增加鲜红血液、通用针脚或发光描边。深浅发色通过局部明暗与边缘形状保持可辨，不将整个受伤区域涂成白块。普通馅颜色沿用物种已有定义；中枢与周围馅共用色系及颗粒，只以中央位置、致密程度和受损裂隙区分，不画异色器官、光滑外壳或硬描边。依据见发面制作源的来源表。

## 头发覆盖与挂接

1. **锚点不动。** 仍以身体 `Triangle/U/V` 为业务位置，在模型静止姿态建立伤口局部切平面。只将轮廓向该伤位外侧的覆盖发面映射；限制在同侧、相邻覆盖区域与模型登记的投影距离内，排除背面及无关垂辫。缺少适配时记录模型缺口，不能投到最近的任意毛束或挪到脸上。
2. **浅伤贴合外层。** 以同一轮廓和稳定种子生成皮面及发面片段；按覆盖关系裁分，发际线两侧连续，不重叠成两处伤。贴片沿真实发面三角形和自身骨骼蒙皮，只用避免闪烁的微小法线偏移；不关深度测试、不贴屏幕、不把皮面贴片整体向外推。
3. **开放伤局部开口。** 用伤口通道与覆盖发片求交，裁去通道内的片段，保留交界以外的发型。头发外口与下方皮面口属于同一个通道，补齐断发边、面皮翻边和凹入的馅壁；厚发处不能留下悬浮皮边或一层完整头发横挡洞口。裂口只开裂口宽度，不因一级裂痕剃掉整片后发。露核通道的皮面与发面共用同一实际开口，核心与周边馅料之间不能再露出一条原发束；`core_tunnel_parts` 登记的内层发片也参与该通道，外层后发不扩大删除范围。普通开放伤仍按伤型保留附着毛束和外侧遮挡，命中遮挡与绘制共用这些边界。
4. **遮挡有边界。** 帽子、发带、蝴蝶结和外置部件不作为发面接收伤纹，不因伤口自动开洞或消失；它们可以正常挡住伤口，摘下后应见原位伤。头发识别由模型组件语义登记，不只依赖骨骼名含 `hair`；无发、稀发、厚发和不同体型共用这套规则。
5. **动作保持对应。** 发面片段随发骨，皮面边缘随皮面，深部向身体骨骼过渡；局部缺口沿同一身体通道约束，毛束摆动不能把伤口拖到别处或重新封住活动创腔。发型、缺发状态和模型变化后重新适配同一个身体锚点，不生成新伤。

裁切表示活动伤的局部外观，不自动新增永久脱发状态。闭伤后按真实伤疤及既有缺发状态重建：没有真实缺发记录的头发恢复未受伤覆盖形态并显示对应疤痕；已有缺发仍缺发，橙汁和面粉糊不借重建外观补回。永久局部断发或再生若需玩法支持，须另有权威状态，不能由客户端裁切缓存决定。

## 中枢位置与创腔

[Wiki「身体与馅料」](../../../../wiki/hakkei-reference/lore/entities-sources.md)把中枢馅放在身体中央较深处；L36 出处见该页与[来源表](../../../../wiki/hakkei-reference/sources-lore.md)。用户采用的造型要求是：从外部能看见中枢的创口必须是大创口，缺失沿途面皮和普通馅，形成通向身体中央的空间。核心只有一个固定位置，不随伤口移动，不在每处伤口里复制一颗。

`cavity.cjs` 保存当前低面数开口轮廓、薄面皮断面、近似垂直的内馅腔壁、较平深色底部和中央核心。`export_cavity.cjs` 导出共享开口描述、放样层级及完好／破裂核心网格，游戏按模型尺寸和真实伤位适配。当前灵梦稿开口约体宽 48%、体高 44%，属于项目美术设计，不是 Wiki 数值。中枢与腔底使用同一品种色系的深浅两档，品种与 RGB 配方见[发面制作源的内馅色板](hair-wounds/README.md#品种内馅配色)；取出后保留下方深色空腔，不引入异色器官。

通用露核外观从外向内依次为断发边缘（有发时）、浅色面皮断面、凹入的普通馅腔壁、中央中枢。中枢位置由身体结构决定，既不朝伤口搬动，也不朝镜头偏移。斜看时允许只见腔壁或部分核心；完整皮面、低血小裂口和单纯焦痕都不能显示表面“核心贴纸”。核心受损只改变同一个核心的破裂状态；核心已取出则通道深处为空腔。

当前保持只选一处真实深伤建立露核通道，其他伤口仍显示普通馅。未来若支持多个缺损通道，应从各自开口看见同一个内部核心，并对相交空腔取并集，不能每个洞各放一颗。视距简化可以减少腔壁细节，但不能封住实际可命中的开口或移出核心；外露命中仍复用 `BodyCavity` 的通道与核心几何，不根据发面贴图颜色判断。

## 当前接入

- **落点与记录**：复用 `WoundPlacement` 的实际命中、`BodyWound` 的 UUID／三角面／重心坐标及 `WoundSurface` 的模型适配；同一伤口的 `Shape` 保存真实机理，旧锚点、伤级和 NBT 路径保留。
- **表面纹样**：轻伤、脏污、油霉、旧疤由原材质函数离线烘焙；局部贴图裁到相邻真实皮面，足缘焦化使用连续环周投影。油霉四阶段保留稳定挂点并随实际病程改变，不每帧抽签或计算像素。
- **露核条件**：只在满足制作源条件的真实大缺损中选择一处共享 `BodyCavity` 通道，其他开放伤显示普通馅。低生命、毒、油霉、烧伤或中枢损坏标志本身不会在完整皮面上生成洞。
- **可见几何**：缓存生成时按独立轮廓裁切皮面、覆盖发面及相交五官，补断发边、面皮断面和凹入普通馅；露核通道才绘制唯一中央核心。饰品与腔壁保留正常深度遮挡，伤口外原发面及附着毛束保留。
- **动作与缓存**：边缘随实际皮面蒙皮，深处向身体骨骼过渡；伤口、模型、表情或核心存在状态改变才重建相关缓存，每帧只蒙皮和绘制。
- **命中一致性**：客户端开口和服务端受击共用 `BodyCavity` 描述。实际攻击射线需穿过开口、避开腔壁并命中中央核心，不能借同一身体侧面上远处的另一处伤口判定露核命中。遵守当前已接入的准确命中立即致死；穿刺贯穿和疾病临终仍走各自规则。
- **治疗与遗体**：治疗改变真实伤势后重新生成外观，不凭画面复活。疤痕保留原锚点与机理；遗体沿用保存伤口、印记及缺发。`CoreTaken` 为真时保留真实通道并隐藏核心，搬运物品与放置实体共用此状态；食用余额不充当生命比例。家油只选用三级热损美术。

## 接入约束

优先扩展既有 `WoundSurface` 模型适配和 `WoundRenderer`／`CavityRenderer`，由制作源导出可受伤的皮面、覆盖发面及局部骨骼绑定。模型适配数据与运行快照按现有素材流程登记；发面补画只需派生显示数据，不新增一份伤口 NBT 或改已有伤级数值。客户端通过 `YukkuriView` 读取真实状态，遗体使用保存快照，不能从渲染调用伤害、治疗或中枢取出逻辑。

裁切、邻接关系和稳定轮廓在伤口、模型、发型／缺发、表情、疤痕或核心状态改变时更新有界缓存；逐帧只进行必要的蒙皮与通道对齐，不每帧烘焙材质或重新随机伤形。视角变化不改变伤口数据。服务端仍由身体领域记录真实伤势、闭合留疤和中枢变化，发面映射不额外扣血、不重复漏馅、不产生业务成功日志。

待试玩须覆盖发际线连续性、厚后发和侧发的原位伤、动作中贴合、遮饰与摘饰、无发／缺发模型、不同成长体型，以及普通开放伤与露核通道的区别；治疗、重载、遗体搬放后不得换位或复制核心。场景入口与最短完成标准只记在待办，具体初态和读数由场景源码维护。

## 尚未接入的精细伤型

真实伤因已能选择窄刺、刀割、咬缺和爆裂外形，但独立长宽、沿皮面的方向、穿入长度、面皮／局部馅缺损量及连续愈合进度仍未写入伤口记录；不能将当前按机理和等级显示的创腔称为完整的物理贯穿系统。

后续若实施精细伤型，应保留真实命中及稳定 UUID，按工具形状与受击强度产生长宽和深度；邻近相交伤口才合并，不能仅按同一部位合并远处伤。狭窄深刺可伤及中央核心却不一定外露；受击应按方向和穿入长度与内部核心体积相交，外露应取决于真实缺损通道。旧伤不能因数据格式变化被随意改造成新大洞。

这些细化不在本次素材接入范围，不能写成已实现。当前待试玩边界见[待办](../../../../docs/TODO.md)。现阶段用 `core_exposed` 的深伤、小裂口与完整皮面对照核对显示并手动瞄准核心，用 `core_filling` 核对取出核心后的空腔，用橙汁观察伤口闭合。
