# 发面伤口制作源

本包为项目原创美术。2026-10-22 用户明确授权本次由 Codex 制作；制作配方、生成器、导出网格和透明贴图保存在这里。当前是待视觉确认的制作源，未替换游戏运行资源，也不表示游戏已有发面裁切。

## 来源与伤因

每个导出样例必须填写 `spec.cause`，由 [sources.json](sources.json) 校验伤因与类型；没有对应依据就拒绝生成。原作文字、项目代码、本次用户规则分开登记，代码存在某个枚举不等于已有该外形的原作证据。

| 美术样例 | 确定的发生来源 | 依据与采用范围 |
| --- | --- | --- |
| 擦伤 | 滚动／拖行中的摩擦 | `InjuryModel.kind` 的 `ROLL/SLIDE → SCRATCH`；浅擦纹是项目美术，不推导深洞 |
| 裂伤 | 刀刃切割 | `kind` 的剑／`cutting_knife → TEAR`；仅制作刀刃造成的方向性裂口，不冒充弹孔、牙印或爆炸缺损 |
| 凹伤 | 钝击／落物压击 | `kind` 默认 `DENT`、`crush` 的落物来源，加上用户明确的共同凹陷要求 |
| 足部烧伤 | 热地板与足底接触 | `underfoot(HOT_FLOOR)`、`analyse → soleSite`，以及本次用户限定的足部范围；使用连续足底覆盖 |
| 全身烧伤 | 全身着火 | `IS_FIRE → SCORCH` 证明热伤入口；全身范围直接来自本次用户规则，代码尚未按该范围显示 |
| 中枢外露 | 已有刀割或压裂缺损通向中央 | 实际开放／深伤等级与用户要求；不是独立发生的一种伤口，不由烧伤自动挖洞 |

伤级来自项目 `BodyWound` 的 1–3 级；长宽、纹样和颜色是制作参数，没有伪称成原作数值。现有代码还把针刺、投射物、啃咬、爆炸、重摔归为 `TEAR`；这只证明归类入口，不能证明它们都应该长成刀口，独立外形和按伤因选图仍见待办。

身体资料定位见 [Wiki 身体与馅料](../../../../../wiki/hakkei-reference/lore/entities-sources.md)。本轮重新核读 E01 [《ゆっくり解体新書》「餡」](https://w.atwiki.jp/yukkuri_gyakutai/pages/3102.html)：该作者把中枢写作较致密的馅料；这是具名作品的个人设定，不证明统一尺寸或异色外壳。L36 原页本轮访问超时，仅使用仓库已整理的身体、足部与中央馅料摘录，不声称重新核验了原页。

## 伤型表现

机械伤对应 `SCRATCH`、`TEAR`、`DENT` 的 1–3 级。二级裂伤开放，三级裂伤／凹伤为深伤；三级擦伤不挖深腔。烧伤按用户最新规则单独使用足部／全身范围，不能把代码中的深伤判定直接做成局部烧洞。

| 类型 | 1 级 | 2 级 | 3 级 |
| --- | --- | --- | --- |
| 擦伤 | 少量短浅擦痕，头发保留 | 增加擦痕、毛束磨损 | 密集擦损、碎屑状浅破皮；不露核 |
| 裂伤 | 细窄闭合切痕，不露馅 | 裂口张开，参差断端，露普通馅 | 扩大的不规则深撕裂，断端及附着毛束继续遮住部分破口 |
| 凹伤 | 轻度共同凹陷 | 加深压陷和压折纹，头发保留 | 在压陷内形成压碎裂口；折发仍连接外围，非整片凹区缺失 |
| 足部烧伤 | 足底连续轻度褐变 | 同一足底范围加深、干裂 | 足底及足缘焦化，上部皮面／头发保留 |
| 全身烧伤 | 全身皮面／头发整体褐变 | 全身焦化加深 | 全身严重焦化，保留原几何；不凭颜色挖洞 |

中枢外露是深伤的派生状态，不能独立做成统一圆洞。三级裂伤、凹伤分别保留切割、压碎外形，各导出中枢完好、受损、取出后空腔三种状态。中枢始终位于身体中央；腔壁和残余头发可以遮住它，不能为了完整展示核心而删除周围头发。

发面破口位于组织缺损轮廓以内，外侧原头发全部保留，部分原发面悬在皮面开口上方。裂伤断端按上下毛束方向参差排列；凹伤保留压折毛束。附着毛束与外侧头发相连，只有真正断离的部分直接消失，不制作散落头发，也不剃空环形区域。

`DIRT`、`MOLD`、`CHAR`、`SCAR`、`PASTE`、`CORE` 属于印记或派生显示，不增设虚构的三档活动伤：脏污三档、油霉四档、整周足缘焦化继续复用上级导出；旧疤用细窄闭合淡痕；普通馅只在开放创腔内；核心使用上述两种伤因的深腔。对应关系记录在素材 manifest 的 `derived_marks`。

灵梦黑发和魔理沙金发使用同一形状与挂接规则，断发边缘按发色适配。头发接收部件在 `recipe.json` 明确列出，帽子、蝴蝶结、发束袖口及独立垂辫不参与局部裁切或压陷；全身烧伤另将登记的垂辫纳入连续受热材质，饰物仍独立。形状、配色和凹陷深度均为项目设计，没有新增玩法伤害数值。

## 文件和接口

| 文件 | 用途 |
| --- | --- |
| `recipe.json` | 三类机械伤的三级参数、两种烧伤范围、露核伤因、发面组件、颜色及保留／断发规则 |
| `author.cjs` | 在同侧真实皮面／发面采样，生成断发边、面皮边、馅壁和中央核心；生成压伤顶点及法线修改 |
| `materials.py`、`build.py` | 生成九档机械伤贴图、三档连续热损材质和一张旧疤，调用网格导出、生成覆盖清单／指纹和离线预览 |
| `export.cjs` | 导出及只读核对当前模型上的制作样例 |
| `assembled/*.png` | 九张 `类型-等级.png`、三张 `thermal-等级.png`，另有 `scar.png`，均为 512×512；UV 映射见配方 |
| `assembled/*.json.gz` | 黑发、金发、裸露皮面各九档机械伤及六种露核状态，共 45 份拟合样例 |
| `sources.json` | 各伤因的证据、定位、支持范围及当前代码冲突 |
| `thermal.cjs`、`assembled/thermal.json` | 热损连续覆盖配方与两种发色各六个足部／全身等级样例；无局部圆形裁切 |
| `assembled/manifest.json` | 制作源／角色输入指纹、输出指纹及未选入运行资源的状态 |

网格沿用现有 `xyz/u/v/normal` 顶点布局，负 `u` 对应逐三角颜色与材料索引。`profile` 给出局部 U/V/N 基、伤因／等级、皮面 `outline` 与发面 `hairOutline` 两个轮廓、实际裁切半径 `cutRadius` 及固定核心位置。不能把皮面轮廓直接套到头发上。`surfaceEdits` 的每行为 `[vertexIndex,x,y,z,nx,ny,nz]`，用于皮面与头发共同压陷，不包含烧伤删发或开洞；不减少原模型顶点数。导出样例基于各自角色 `idle:0` 的实际拟合，不能作为无骨骼的固定贴片直接盖到未裁切模型上。

中枢位置与基础几何复用上级 `cavity.cjs`；中枢和邻近腔壁采用同一低饱和豆沙色系、相同空间颗粒，不画紫红外壳、高光球或描边。致密处仅微调色值，受损以同一材质内的裂隙表达。`surface.cjs` 的可选发面分支读取导出的网格／压陷数据和贴图作离线光栅化；开口按片元裁切，正常头饰仍写入深度。正式接入须按 `profile` 裁切皮面和对应发面、补骨骼绑定，并从真实伤势选择压陷或断发，不能对所有受伤统一删发。压伤顶点样例不能直接复用于不同拓扑、表情或成长体型。

## 生成与预览

在仓库根目录运行：

```text
python standards/yukkuri-library/drafts/body-marks/hair-wounds/build.py --node node
python standards/yukkuri-library/drafts/body-marks/hair-wounds/build.py --node node --check
python standards/yukkuri-library/drafts/body-marks/hair-wounds/build.py --node node --preview
python scripts/build_preview_hub.py --node node
```

依赖 numpy、Pillow、Node.js 和中文字体；不使用浏览器、桌面自动化或 Java 编译。`--preview-root <仓库目录>` 可将独立工作树的预览输出到主仓库 `.local/previews/hair-wounds/`。该主题包含三种表面的三类机械伤三级矩阵、两伤因×三中枢状态矩阵、足部／全身烧伤各三级及侧视；中间缓冲在 `.local/hair-wounds-work/`。生成器仅按自身 manifest 清理被替代的导出，不删除制作输入或参考图。

预览不代表游戏接入或试玩通过。运行时三角裁切、动作蒙皮、按伤因选图、烧伤范围与伤口状态同步、治疗和遗体变化仍按[通用设计](../WOUND_GENERATION.md)与[待办](../../../../../docs/TODO.md#美术opus)处理。
