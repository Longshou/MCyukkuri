# 发面伤口制作源

本包为项目原创美术制作源，保存配方、生成器、导出网格和透明贴图。现有轮廓、材质和表情图集经 `select_runtime.py` 选入游戏，选用快照与指纹在 `art/source/hair-wounds/`，来源映射在 `art/runtime-sources.json`。美术认可状态与游戏试玩状态仍分别遵循制作源登记和待办；选入资源不表示用户已确认视觉效果。

## 来源与伤因

每个导出样例必须填写 `spec.cause`，由 [sources.json](sources.json) 校验伤因与类型；没有对应依据就拒绝生成。分类以项目当前 Minecraft 1.21.1 的实际伤害方式为主：[MC 伤害来源映射](mc-damage-map.json)核对了 47 个原版伤害类型及具体调用点，保存来源文件指纹；没有复制游戏源码或资源。原作资料只支持身体材质，不代替 MC 的伤因判断。原作文字、MC 来源、项目代码和用户规则分开登记。

| 美术样例 | 确定的发生来源 | 依据与采用范围 |
| --- | --- | --- |
| 擦伤 | 滚动／拖行中的摩擦 | 模组 `OperationLife.tick` 按真实移动与粗糙度累积后 `strike` 扣血，`InjuryModel.kind` 映射为擦伤；原版普通滚动不凭空生伤 |
| 裂伤 | 刀刃切割 | `kind` 的剑／`cutting_knife → TEAR`；仅制作刀刃造成的方向性裂口，不冒充弹孔、牙印或爆炸缺损 |
| 凹伤 | 钝击／落物压击 | `kind` 默认 `DENT`、`crush` 的落物来源，加上用户明确的共同凹陷要求 |
| 足部烧伤 | 热地板与足底接触 | `underfoot(HOT_FLOOR)`、`analyse → soleSite`，以及本次用户限定的足部范围；使用连续足底覆盖 |
| 全身烧伤 | 全身着火 | `IS_FIRE → SCORCH` 证明热伤入口；足部／全身范围由真实来源区分，采用范围来自用户规则 |
| 刺伤 | 箭矢刺入 | `AbstractArrow.onHitEntity → damageSources.arrow`，以窄入口表达，不沿用横向刀口；不为露核扩洞 |
| 细刺接触 | 仙人掌 | `CactusBlock.entityInside` 的接触伤害；离散细刺纹为项目设计 |
| 尖锥穿压 | 石笋／落下的滴水石锥 | `PointedDripstoneBlock.fallOn`／`getFallDamageSource`；按真实上下方向表现宽锥穿压 |
| 咬伤 | 狼等明确的咬击者 | `Wolf` 近战入口与 `Mob.doHurtTarget`，结合项目咬击判别；上下咬合边缘 |
| 爆裂伤 | TNT／苦力怕等真实爆炸 | `Explosion.explode` 的真实伤害来源；冲击撕裂，不默认烧焦 |
| 中枢外露 | 已有刀割、压裂、咬缺或爆裂的大缺损通向中央 | 实际开放／深伤等级与用户要求；不是独立发生的一种伤口，不由烧伤自动挖洞 |

伤级读取项目 `InjuryModel.severity` 的真实结算：新伤实际扣血 `0 < loss ≤ 2` 为一级、`2 < loss ≤ 4` 为二级、`loss > 4` 为三级，零扣血不生成伤口；不是按武器面板值，也不随机抽等级。`BodyLife.onHurt` 对同部位同类型旧伤采用 `min(3, max(旧等级, 本次等级) + (loss ≥ 2 ? 1 : 0))`；满八处时现有代码加重最近旧伤一级。热锥仍有最低二级特例，但本包不导出它的旧局部烧伤。长宽、纹样和颜色是制作参数，没有伪称成原作数值。近战必须继续区分武器与攻击者，投射物必须继续看实体：鸡蛋及对非烈焰人的雪球命中伤害为零，不给油库里新增伤口；潜影弹、羊驼唾沫和风弹不是箭孔。摔落、落物与挤压按实际受力面判断；爆炸本身不等于烧伤；雷击／凋灵之首的直接伤害、后续着火和状态伤害分别处理。窒息、溺水、饥饿、冻伤、魔法、凋零、龙息和音波不能凭扣血虚构刀口，泛用来源缺少上下文时不猜外形。具体伤因维护在 MC 映射，三级素材对应由 `coverage.py` 生成到 [source-coverage.json](assembled/source-coverage.json)：47 种来源、141 个等级条目，每个条件分支直接指向已有素材或明确不增加外部伤口；不为凑数量给内部损耗制造破口。

窄刺口、尖锥穿压、咬合缺口和爆裂仍沿用 `TEAR` 业务类别，细刺接触属于浅表损伤，不扩展 `WoundKind` 的治疗、漏馅或伤级分类。`WoundShape` 只保存同一处真实伤口已发生的机理，用于按伤因选择现有美术；不是第二套伤势。MC 三叉戟是单次实体命中，未提供逐齿接触数据；植物也未提供逐刺落点，不伪造三次命中或精确刺位。真实接触位置与穿透方向仍由运行事件提供。荆棘附魔经 `DamageEntity.apply` 反伤，并非实体尖刺，不画成针孔。

身体资料定位见 [Wiki 身体与馅料](../../../../../wiki/hakkei-reference/lore/entities-sources.md)。E01 [《ゆっくり解体新書》「餡」](https://w.atwiki.jp/yukkuri_gyakutai/pages/3102.html)将中枢写作较致密的馅料；这是具名作品的个人设定，不证明统一尺寸或异色外壳。L36 仅采用仓库已整理的身体、足部与中央馅料摘录，原页未重新核验。

## 伤型表现

机械伤基于 `SCRATCH`、`TEAR`、`DENT` 拆为摩擦、刀割、钝击、窄刺、细刺接触、尖锥穿压、啃咬、爆裂八种美术形态，各 1–3 级。贴图在 64×64 硬边像素网格上绘制并最近邻导出为 512×512，不使用平滑渐变或肤色底块；开放伤由低面数创缘、近似垂直的内壁和真实底部表现深度。二级裂伤开放，三级裂伤／凹伤为深伤；三级擦伤不挖深腔。烧伤按用户最新规则单独使用足部／全身范围，不能把代码中的深伤判定直接做成局部烧洞。

| 类型 | 1 级 | 2 级 | 3 级 |
| --- | --- | --- | --- |
| 擦伤 | 少量短浅擦痕，头发保留 | 增加擦痕、毛束磨损 | 密集擦损、碎屑状浅破皮；不露核 |
| 裂伤 | 清晰的闭合切痕与短交叉折线，不露馅 | 裂口张开，参差断端，露普通馅 | 扩大的不规则深撕裂，断端及附着毛束继续遮住部分破口 |
| 凹伤 | 轻度共同凹陷 | 加深压陷和压折纹，头发保留 | 在压陷内形成压碎裂口；折发仍连接外围，非整片凹区缺失 |
| 刺伤 | 小入口与短裂纹 | 深入的窄入口 | 偏转的深窄孔道与单侧缺口，不扩成露核洞 |
| 细刺接触 | 少量离散细刺痕 | 接触区细痕增多 | 密集细痕；不扩成大洞 |
| 尖锥穿压 | 纵向初入刺痕 | 宽锥楔口 | 加深的非对称穿压口与侧向压裂；保留外侧头发 |
| 咬伤 | 两排分离齿痕，犬齿较深；齿间不连线 | 上下颌齿缺张开、犬齿切入延伸 | 加深咬缺及保留毛束 |
| 爆裂伤 | 压纹和放射短裂 | 不规则压力撕裂 | 大缺损，不额外涂焦黑 |
| 足部烧伤 | 足底连续轻度褐变 | 同一足底范围烟熏、干枯 | 足底及足缘焦化，上部皮面／头发保留 |
| 全身烧伤 | 全身皮面／头发整体褐变 | 全身焦化加深 | 全身严重焦化，保留原几何；不凭颜色挖洞 |

### 品种内馅配色

开放伤的普通馅、腔壁和中央核心按模型的 `filling_palette` 使用对应品种色系；开口、放样深度、伤级与命中几何不随色板改变。灵梦／魔理沙及其现有亚种沿用豆沙色，爱丽丝使用卡仕达黄，橙及长尾／圆尾橙使用巧克力棕，妖梦／红眼妖梦使用白巧克力象牙色，蕾米莉亚与芙兰使用肉包馅的熟食暖灰棕。家油仍只显示热损，不因继承色板而产生机械创腔。

| 色板 | 适用模型 | 依据与边界 |
| --- | --- | --- |
| `red_bean` | 灵梦／魔理沙及其现有亚种、家油形态 | [基本设定馅料称呼](../../../../../wiki/hakkei-reference/world/rules.md#繁殖与食物) |
| `custard` | 爱丽丝 | 用户明确指定卡仕达；[种族资料](../../../../../wiki/hakkei-reference/lore/species/alice/README.md)亦收录该称呼 |
| `chocolate` | 橙、长尾橙、圆尾橙 | [橙的品种资料](../../../../../wiki/hakkei-reference/lore/species/chen/README.md)，限于所引版本 |
| `white_chocolate` | 妖梦、红眼妖梦 | 既有[稀有形态登记](../../../subspecies/rare-forms/recipe.json)采用白巧克力；不按共享模型误判为卡仕达 |
| `meat_bun` | 蕾米莉亚、芙兰 | 用户明确指定捕食种为肉包；熟食肉馅配色为项目美术，不改变捕食行为 |
| `generic` | 其他未明确品种 | Wiki 只泛称“馅”；沿用默认美术色，不据此断言为豆沙或其他口味 |

具体 RGB、暗壁和浅色核心均为项目美术选择，不是 Wiki 给定颜色。每套色板分别提供 `base`、`bottom`、`core_color`、`wall`、`shadow`、`mid`、`deep`，面皮断边保持原色；核心与周边只使用同一品种色系的明暗和颗粒，不画异色器官。

中枢外露是深伤的派生状态，不能独立做成统一圆洞。三级刀割、压裂、咬缺、爆裂分别保留实际机械形态；只导出完好中枢外露，不提供中枢受损或取出后空腔的分支。普通露核还须剩余生命不高于 30%，且真实伤位能拟合通向中央的创腔；不满足就显示普通馅。以最大生命 10 的刀割命中为例，扣 5 点是三级伤但仍有 5/10 生命，不露核；扣 7 点后剩 3/10，三级深伤通道成立才露核。中枢始终位于身体中央；腔壁和残余头发可以遮住它，不能为了完整展示核心而删除周围头发。

发面破口位于组织缺损轮廓以内，外侧原头发全部保留，部分原发面悬在皮面开口上方。裂伤断端按上下毛束方向参差排列；凹伤保留压折毛束。附着毛束与外侧头发相连，只有真正断离的部分直接消失，不制作散落头发，也不剃空环形区域。普通开放伤沿用此保留范围；露核通道则让皮面和发面共用同一边界，裁去通道内原发束，避免发色从核心与周边馅料的接缝中露出，外缘断发仍保留。`core_tunnel_parts` 另行登记 `underlayer` 等位于普通同侧过滤之外的内层发片，露核时也须裁切；外层后发不因该登记扩大删除范围，普通开放伤不启用这条内层通道。

`DIRT`、`MOLD`、`CHAR`、`SCAR`、`PASTE`、`CORE` 属于印记或派生显示，不增设虚构的三档活动伤：脏污三档、油霉四档、整周足缘焦化继续复用上级导出；旧疤用细窄闭合淡痕；普通馅只在开放创腔内；核心使用上述四种大缺损的深腔。对应关系记录在素材 manifest 的 `derived_marks`。

头发接收部件由 `species.py` 按当前角色／亚种登记生成到 `species.json`，普通灵梦和魔理沙保留 `recipe.json` 的原接收范围。伤口边缘按实际发色适配，独立饰物不参与机械伤裁切或压陷。全身烧伤也影响饰物：蝴蝶结、发带、布帽及袖口逐级褐变、熏黑、焦枯，螺壳、彩晶与耳环采用烟熏覆盖；它们保持自身尺寸，以完整组件跟随挂点，不能把每片壳或帽面单独挪动。足部烧伤不影响头饰。该材质响应属于项目设计，没有新增玩法伤害数值。

## 品种与形态适配

当前制作源覆盖 `living.json` 的 10 个基础模型与 `subspecies.json` 的 14 个形态，共 24 套。按用户最新限定，**家灵梦、家魔理沙仅提供足部／全身烧伤，受烧直接使用三级外观，不提供机械伤或中枢外露**；其他 22 套各有覆发区和面部皮面两处、八种机械伤各三级，以及四种满足条件的完好中枢外露，共 1,232 份机械网格。24 套共 136 份热损配置，所有现有表情按适用等级派生干枯图集，共 1,603 张（家油仅三级，其余各三级），分辨率保持各自 128／256／512 的 UV 布局。不是给未实现品种猜一套通用外观。

实际模型体表包围尺寸决定坐标映射，五官 UV 仅采集正面三角形，排除眼盒侧面的占位 UV；干枯脸保留各自虹膜、尖牙和表情身份。豆形的短头部长躯干单独拟合头部伤口纵向范围，不把伤口挪到腹部。原先天稀发、缺发及面部不足结构不补回。妖梦／红眼妖梦按实际 14 点最大生命展示露核条件，满血扣 10 点后剩 4/14，其余非家油当前 10 点生命样例扣 7 点后剩 3/10；仍须真实三级大缺损及通道成立。

成长沿用实际身体的同一次变换，不能使用固定世界尺寸贴片。普通形态示例为 0.14／0.5／1／1.2，家油以自身成体为基准展示 0.32／0.65／1，灵胖仅有成年 1.5 倍；同世界视距下赤体伤纹会随身体一起变小。水生魔理沙共用魔理沙身体，另按真实 `hat_vessel.json` 挂点与 1.5 倍帽饰展示，不另造身体模型。家油实际赤／子／成体最大生命为 1／2／4，来自 `BodyConstants` 与 `BodyLife.syncStageHealth`。家油受烧直接选择三级外观，足部与全身范围仍区别；这是明确的品种外观例外，不把实际扣血改写成超过 4 点，存活由真实血量独立决定。成长页展示这一外观随体型的变化；静止样例不替代运行时动作蒙皮的用户试玩。

## 文件和接口

| 文件 | 用途 |
| --- | --- |
| `recipe.json` | 八种机械伤形态的三级参数、两种烧伤范围、露核伤因、发面组件、颜色及保留／断发规则 |
| `author.cjs` | 在同侧真实皮面／发面采样，生成断发边、面皮边、馅壁和中央核心；生成压伤顶点及法线修改 |
| `materials.py`、`build.py` | 生成二十四档机械伤贴图、三档连续热损材质和一张旧疤，调用网格导出、生成覆盖清单／指纹和离线预览 |
| `export.cjs` | 导出及只读核对当前模型上的制作样例 |
| `assembled/*.png` | 二十四张机械伤、三张热损、一张旧疤为 512×512；另有两角色各 22 种表情 × 3 级的干枯图集，保持原 256×256 UV |
| `assembled/*.json.gz` | 黑发、金发、裸露皮面各二十四档机械伤及四种完好中枢外露，共 84 份拟合样例 |
| `mc-damage-map.json` | Minecraft 1.21.1 的 47 个真实伤害类型、具体调用点与项目美术分类 |
| `coverage.py`、`assembled/source-coverage.json` | 47 种来源 × 3 级的明确素材选择；内部／系统伤害不伪造外部破口 |
| `sources.json` | 各伤因的证据、定位、支持范围及当前代码冲突 |
| `dry_face.py`、`assembled/dry-face.json` | 参考灵胖的部位 UV 绘制法，派生疲惫眼睑、短干纹和暗淡唇色；不画下巴轮廓线，不改变原图集 |
| `grading.py`、`assembled/damage-examples.json` | 从真实 Java 伤级常量生成确定的扣血、旧伤加深与露核例子，源判定变化时拒绝沿用旧例子 |
| `thermal.cjs`、`assembled/thermal.json` | 按高度分布的横向干瘦形变与热损连续覆盖配方与两种发色各六个足部／全身等级样例；无局部圆形裁切 |

| `species.py`、`species.cjs`、`species.json` | 真实模型清单、接收部件、体表坐标映射、独立饰物组、热损材质及露核内层发片登记；未分类的新模型／部件拒绝生成 |
| `adapt.py`、`assembled/species/` | 全品种拟合网格、各自表情的干枯图集、成长／热损配置及输入输出指纹；家油仅烧伤 |
| `select_runtime.py` | 只选取既有轮廓、材质、表情图集和真实模型发面绑定；生成快照、运行资源与来源指纹，不重新创作美术 |

网格沿用现有 `xyz/u/v/normal` 顶点布局，负 `u` 对应逐三角颜色与材料索引。`profile` 给出局部 U/V/N 基、伤因／等级、皮面 `outline` 与发面 `hairOutline` 两个轮廓、实际裁切半径 `cutRadius` 及固定核心位置。不能把皮面轮廓直接套到头发上。`surfaceEdits` 的每行为 `[vertexIndex,x,y,z,nx,ny,nz]`，用于皮面与头发共同压陷，不包含烧伤删发或开洞；保留原始索引用于定位。`surfacePatches` 保存 `{triangle, part, vertices}`：渲染时跳过指定原三角形，使用保留 UV 的细分面，并给皮面、头发和五官施加相同凹陷场。不能仅移动稀疏的眼睛顶点，否则会被密集皮面误挡。导出样例基于各自角色 `idle:0` 的实际拟合，不能作为无骨骼的固定贴片直接盖到未裁切模型上。

烧伤材质参考 Wiki 收录的 [EH16-008](../../../../../wiki/art-references/ehentai/images/EH16/008.webp)（綾蔵／shku）：本图受热处表现焦黑细点与烟熏，表皮保持连续。采用焦褐底、疏密焦黑炭化、细点过渡和干枯哑光，随等级加深；不画 Voronoi 块面、连通裂网、周期格纹或明亮碎片边；焦黑区仍保留低对比炭粒，三向混合投影使下颌连续受热。只采用材质语言，不采用原图的局部火焰范围，也不复制原图。全身烧伤保持高度和前后深度不变，按高度分布收窄横向轮廓：颊部最大收窄幅度为 5%、10%、16%，上下缘收得更少，属于项目制作参数。皮面、五官与头发共用同一形变；头饰保持尺寸，仅跟随挂点向内移动。足部烧伤没有全身干瘦或干枯脸。脸部参考 [灵胖画法](../../../body-standard/features/deibu-mature/author.py)在既有 UV 框内派生各表情的干眼睑、离散短干纹与暗淡唇色，去掉颊部弧线和下巴横线，二级保留原虹膜及圆眼，缩短眼睛高度形成疲惫垂眼；三级中性／睁眼状态使用柔和闭合眼睑，去掉白色窄缝和竖瞳造成的瞪视感。哭泣、闭眼和进食等表情不被统一替换成中性脸。

所有机械贴图使用透明背景，无肤色打底；开放创腔的面皮断面严格放在真实缺损轮廓以内，不加外扩肤色边框。保留伤口外的眼睛、嘴和头发，真实缺损内仍允许正常遮蔽。

中枢位置与基础几何复用上级 `cavity.cjs`；中枢和邻近腔壁采用同一品种的内馅色系与颗粒，腔底较深、致密核心较浅，以实际位置和遮挡区分，不画异色外壳、高光球或描边。创腔使用薄面皮断面、近似垂直的内壁与较平底面；核心保留低面数正面，取出后显示同一通道的深色空腔。本包仍只导出完好中枢样例，裂损与取出空腔沿用上级运行创腔，不在此另增分支。`surface.cjs` 的可选发面分支读取导出的网格／压陷数据和贴图作离线光栅化；开口按片元裁切，正常头饰仍写入深度。正式接入须按 `profile` 裁切皮面和对应发面、补骨骼绑定，并从真实伤势选择压陷或断发，不能对所有受伤统一删发。压伤顶点样例不能直接复用于不同拓扑、表情或成长体型。

## 生成与预览

按用户要求，每轮绘制并导出图片后，必须由专门的 subagent 直接查看成图，独立审核伤型辨识、焦枯质感、脸部观感及指令符合度；不能只读代码或采用作者自评。审核发现偏离要求时继续修改、重新出图并复审。审核不代替用户的最终视觉认可。

在仓库根目录运行：

```text
python standards/yukkuri-library/drafts/body-marks/hair-wounds/build.py --node node
python standards/yukkuri-library/drafts/body-marks/hair-wounds/build.py --node node --check
python standards/yukkuri-library/drafts/body-marks/hair-wounds/build.py --node node --preview
python standards/yukkuri-library/drafts/body-marks/hair-wounds/adapt.py --node node --preview
python standards/yukkuri-library/drafts/body-marks/hair-wounds/adapt.py --node node --check
python scripts/build_preview_hub.py --node node
```

依赖 numpy、Pillow、Node.js 和中文字体；不使用浏览器、桌面自动化或 Java 编译。`--preview-root <仓库目录>` 可将独立工作树的预览输出到主仓库 `.local/previews/hair-wounds/`。该主题包含三种表面的八种机械伤三级矩阵、四种大缺损的完好中枢外露矩阵、足部／全身烧伤各三级、侧视、眼部叠加、透明棋盘底、一级伤辨识、干瘦脸、扣血阈值及 47 种 MC 来源的逐级选图；中间缓冲在 `.local/hair-wounds-work/`。生成器仅按自身 manifest 清理被替代的导出，不删除制作输入或参考图。

运行接口读取同一处 `BodyWound` 的 UUID、身体三角面／重心坐标、严重度和 `Shape`，按真实机理选图。`HairWoundRenderer` 将轮廓投影到登记的同侧皮面、发面和五官，重建凹陷细分面、独立发面开口及普通馅腔；深伤通过共享 `BodyCavity` 通向唯一中枢。伤口、表情、模型、缺发、遮饰或核心状态变化时才重建有界缓存，逐帧沿当前骨骼与真实成长变换蒙皮。发缘在通道附近向皮面权重过渡，保留远处发束的原动作；受伤补片继续参与孕肚面部拟合和实际接生产道裁切。

足部和全身烧伤读取各自真实状态，旧疤保留原机理但不再触发活动热损。全身收窄与服务端命中共用形变，独立饰物按完整登记组跟随挂点；足烧不改变上部体型或表情。家油仅显示三级热损。橙汁闭伤后按原锚点显示疤痕，面粉糊去疤不重造缺发；遗体沿用保存的伤口、疤痕、缺发及核心取出状态。普通露核不再由烧伤或损坏标志绕过低血量和大缺损条件；既有真实破损核心保留原损坏对比，并使用连续馅料色系，本包仍未新增破损中枢美术分支。

静止制作样例与离线预览不能证明游戏中的动作、遮挡或交互已通过。动态贴合、重载、治疗、遗体搬放与核心准确命中仍由用户在动作博物馆确认，场景和完成标准见[待办](../../../../../docs/TODO.md#美术opus)。精细贯穿仍遵循[通用设计](../WOUND_GENERATION.md)的实现边界。
